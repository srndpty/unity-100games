# 1本あたりの標準ワークフロー

## 0. Scope Freeze

対象の`games/NNN-*.md`を読み、ルール差異、使用Unity版、データ形式、勝利条件を固定。Out of scopeに該当する要求は追加しない。

## 1. Core-first

ゲーム状態と入力コマンドを先に設計。主な状態遷移を一枚の図または簡単な表にする。最小のEditModeテストを先に書き、基本・境界・不正・多重実行を検証。

## 2. Playable

単一シーンまたは最小限のSceneにCoreを接続。操作・表示・効果音は必要十分に留め、開始/終了/リスタートを実装。

## 3. Verification

各題材の必須テスト＋共通テストを実行し、データ不変条件を確認。Windowsビルドを起動し、スクリーンショットまたは短い録画を保存。

## 4. Retrospective

技術的に新しかった点、発生した不具合、次なら変える設計の3点を記録。`progress.csv`を更新して完了。

## スコープ膨張ルール

- 見た目の磨き込み・コンテンツ追加は原則として完成条件に入れない。
- Coreのテストが難しければ、抽象化を増やすより境界を見直す。
- 一作品で2日以上詰まったら、目的技術を守ったまま表現・素材・面数を小さくする。ルールの正しさは削らない。
- 継続不可能なほど大きい題材（MOBA/RTS等）は、削る機能を変更履歴に明記し、最小メカニクスの実証を優先する。

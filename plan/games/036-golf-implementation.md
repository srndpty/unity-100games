# 036 ゴルフ 実装計画

## Context

- 036 ゴルフ（難易度3・Phase 2）が未着手。仕様書 [plan/games/036-golf.md](./036-golf.md) の中心課題は「**投射軌道と地形摩擦のモデル化**」、重点は「**予測線と実際の一致を計測**」。In scope：3 ホール・パワー/方向/打点設定・風とグリーン傾斜・タイトル→説明→結果→再プレイ。Out of scope：18 ホール・複雑なクラブ性能。
- 題材固有テスト：カップイン判定が球速度条件を満たす／障害物衝突で再計算／OB 後の打数加算。完了判定：3 ホールを規定打数で完走・軌道予測と実軌道の差分記録。
- ユーザーと決めたこと：
  - **2D 真上から**（2D 雛形）。球の高さは影との離れで表す（024 と同じ）。ホールは横長の画面に合わせて左→右に置く。
  - **物理は Core の整数物理**。飛行・バウンド・転がり・風・傾斜を固定小数点で自前実装し、**予測線と実際の球は同じ関数**で進める。.NET と Mono で最終ハッシュを一致させる（013・020・033・035）。
  - **ショットは 2 回押しのメーター**：1 回目でパワー、2 回目（インパクト）のずれで左右に曲がる。方向（←→）・打点（球のどこを打つか＝スピン）は事前にキーで設定。予測線は「ずれ 0」の軌道で、実際との差を記録する。

作品名はオリジナル（仮）：**BREEZEWAY LINKS**。参考作品の名称・素材・演出は使わない。
この計画は着手時に `plan/games/036-golf-implementation.md` として保存し、各セッションの結果を追記する（025〜035 と同じ）。

## セッション1：ルール表（README に固定）と Core / App

### ルール表（要点）

| 項目 | 採用ルール |
|---|---|
| 時間 | 60 Tick/秒。Core・App は Tick 単位。入力はイベント時刻を含む Tick に反映（022 の `PrecisionFlow`。メーターの止めどころがフレームレートに依らない） |
| 単位・座標 | 整数。1 単位 = 1 µm（`Units.PerMeter = 1_000_000`、400 m でも int に収まる）。x：ホールの奥へ、y：横、z：高さ（地面は z = 0 の平面。起伏は持たず、傾斜はグリーンの転がりにだけ効く）。速度は単位/Tick、積は long。浮動小数点を使わない |
| 地面の種類 | 1 マス = 2 m の格子。ティー・フェアウェイ・ラフ・バンカー・グリーン・池・OB。種類ごとに「着地の反発（分数）」「着地の水平の減り」「転がりの減速」「その場所から打つときのパワーの係数（ライ）」を設定に持つ |
| クラブ | 4 本（ウッド・アイアン・ウェッジ・パター）。最大初速と打ち出し角だけ（複雑な性能は Out of scope）。↑↓ で替える。既定は残り距離から自動で選ぶ。グリーン上はパター固定 |
| 打点 | 球の上下左右の 5×5 段（−2〜+2）。上下：打ち出し角の増減とバック/トップスピン（着地後の転がりを減らす/増やす）。左右：横のスピン（飛行中に横へ一定の加速＝曲がる）。パターでは打点は効かない |
| メーター | Space で始める。ゲージは 0 → 100% → 0 を `MeterTicks` で往復。1 回目の押下でパワー（その Tick のゲージ値）を決め、戻りの 0 付近の **インパクト帯** で 2 回目。理想の Tick からのずれ e（Tick 数）で打ち出しの向きが e に比例して曲がる（早い＝左・遅い＝右）。帯の外・押さないまま 0 を過ぎた → ミスショット（最大のずれ＋パワーを半分）。1 回目を押さないまま戻りきったら取り消し（打数に数えない）。3 回目以降の押下は無視 |
| 飛行 | 1 Tick：風に対する相対速度に比例する空気抵抗（分数、0 方向へ切り捨て）→ 重力 → 横スピンによる加速（スピンは毎 Tick 減る）→ 位置 += 速さ |
| 風 | ホールごとに一定（突風なし）。向き 16 方位・強さ 0〜`MaxWind` をラウンドのシードからホールごとに別系列で引く（015）。HUD に矢印と強さ |
| 障害物（木） | 平面上の円柱（中心・半径・高さ）。その Tick の水平の線分が円に触れ（int-geometry の `Sweep.First` を木の中心からの相対座標で）、触れた時刻の z が高さ以下なら、触れた位置で水平の速さを法線方向に反射し係数で減らして**残りの時間で軌道を計算し直す**。ちょうど接するだけでは触れない |
| 着地・転がり | z が 0 を下回った Tick は、その中で地面に触れた割合で位置を求める（024）。鉛直の速さが `RollThreshold` 以下になったら転がりへ。転がり：地面の減速＋グリーンでは傾斜の加速（マスごとの傾き）。止まる条件：速さ ≤ `StopSpeed` かつ傾斜の加速 ≤ 転がりの減速（坂の上では止まらない）。1 打の Tick 数の上限 `MaxShotTicks`、超えたら止めたとみなす（設定の検証で通常の打球が超えないことを保証） |
| カップ | グリーン上の円（半径 54 mm）。**転がる球の中心の軌跡がカップの円に入り、そのときの水平の速さ ≤ `CupMaxSpeed` ならカップイン**。速すぎれば通り過ぎる。飛んでいる球（z > 0）はカップに入らない。着地した Tick にカップに入った場合も同じ速さの条件。軌跡の判定なので、1 Tick でカップを飛び越える速さでも条件を満たせば入る |
| OB・池 | 球が地面に触れた（着地・転がり）位置が OB・池のマス、またはホールの外 → その打球は終わり、**1 打罰を加えて前の位置から打ち直し**（池も同じ扱い。救済の位置は採用しない）。1 打球で 1 回だけ数える |
| 打数 | 打った時点で +1、OB・池で +1。ホールの上限 `par + MaxOver`（既定 +5）に達したらそのホールは上限の打数で終わる |
| 終了・結果 | 3 ホールの合計とパー差、ホールごとのスコアカード、ショットごとの予測と実際の着地の差。結果の後は入力で状態を変えない。再戦は新しいシード |
| 予測線 | 今の設定（クラブ・向き・打点・**パワーは 100% と、1 回目を押した後は決めたパワー**）とずれ 0 で、実際と同じ `BallSim` を進めた最初の着地までの軌跡（木への衝突を含む）。パターは最初の `PuttPreviewTicks` だけ（傾斜の読みを残す）。打った後、予測の着地点と実際の着地点の差を記録する |

### コースデータ（`Assets/Game/Data/Course.txt`、TextAsset）

- ホールごとに：`hole <番号> par <n>`・格子の文字地図（`#` OB・`~` 池・`.` ラフ・`,` フェアウェイ・`o` バンカー・`g` グリーン・`T` ティー）・`cup x y`・`tee x y`・`tree x y r h`・`slope x0 y0 x1 y1 dx dy`（グリーンの矩形範囲の傾き）。
- Core の `CourseBook.Parse` が検証：ちょうど 3 ホール、par 3〜5、地図が長方形で外周が OB、ティー・カップの位置が正しい種類のマス、カップがグリーン内、木がグリーン・ティーに重ならない、傾きが範囲内でグリーンの上だけ。dotnet のテストも同じファイルを読む（033・034・035 と同じ流れ）。
- 3 ホールは par 3・4・5 を目安（横 120〜230 マス × 縦 50 マス程度、画面に横長で収まる大きさ）。

### Core（`Assets/Game/Core/`）

- `Units`・`Vec3i`、`Surface`（種類と性質）
- `GolfConfig`：重力・空気抵抗・クラブ表・地面の性質・打点の効き・メーター（`MeterTicks`・インパクト帯）・風の上限・カップ（半径・`CupMaxSpeed`）・止まる条件・`MaxShotTicks`・`MaxOver`。公開フィールド＋検証（範囲・`Sweep.FirstLimit` に収まる 1 Tick の移動量・止まる保証）。検証済みの複製を返す（029・030）
- `Course`・`Hole`・`CourseBook`：コースデータと検証
- `ShotSetup`（クラブ・向き・打点・パワー・ずれ）→ `Launch.From`：初速とスピン（純粋関数）
- `BallSim`：`Step(ref BallState, Hole, Wind)` が 1 Tick を進め、出来事（着地・木・カップイン・OB/池・停止）を返す。**予測と実際の両方がこれを使う**
- `Predictor`：`BallState` を複製して `BallSim` を進め、軌跡の点の列と最初の着地点を返す（固定容量の配列、割り当て 0）
- `Meter`：Tick で進む状態機械（待ち→上り→下り→決定/取り消し/ミス）
- `GolfRound`：1 ラウンド。状態（構え／スイング／球が動いている／ホールアウト／終了）、コマンド（向き・クラブ・打点・メーターの押下）、`Step()`、打数・罰打・スコアカード・`ShotLog`（予測の着地・実際の着地・止まった位置・差）・`Hash()`（全状態＋設定とコースの指紋、`StateHash`）・`Clone()`

### App（`Assets/Game/App/`）

- `GolfFlow`：Title / Playing / Paused / HoleResult / Result。時刻付きの 1 本の入力の列（012・022）、フレーム単位の Tick 上限、フォーカス喪失で一時停止し保留入力とメーターの押下を消す・復帰は手動再開。向きの長押しは `MoveRepeater` の方式（012）
- `Autopilot`：`Clone` と `Predictor` でクラブ・向き・パワー・打点の候補を探してカップに近い（OB・池・木を避ける）ものを選び、メーターの理想の Tick で押す。乱数で少しだけずらして周期に入らないようにする。撮影・テスト・PlayMode で共有。ラウンドが変わったら判断の状態を捨てる（023）

### テスト（題材固有を優先）

- **カップイン判定が球速度条件を満たす**：速さちょうど `CupMaxSpeed` で入る・+1 で通り過ぎる、1 Tick でカップをまたぐ速さ（端点は両方カップの外）でも条件を満たせば入る、カップの縁をかすめる（距離 = 半径ちょうどは入らない）、飛んでいる球は上を通過、着地した Tick にカップ内、カップイン後の Step で状態が変わらない
- **障害物衝突で再計算**：木に当たった球が反射し残りの時間を進む（当たらない場合と着地点が変わる）、木の高さちょうど ±1 の z、最大の速さで細い木をすり抜けない（Tick を細かく刻む素朴な参照実装と接触の有無・時刻を照合）、**予測線も木の衝突を含めて計算し直し、予測と実際の着地が一致**
- **OB 後の打数加算**：OB で +2（打球と罰打）・前の位置に戻る、池も同じ、OB の上を飛んで場内に着地しても罰なし、1 打球で OB を 1 回だけ数える（重複した出来事）、上限の打数に達する打球が OB、連続 OB
- **予測と実際**：ずれ 0 なら予測の軌跡と実際の軌跡が全 Tick で一致（クラブ・打点・風・木の乱択）、ずれ e で予測からの横の差が e の符号どおりに出る、`ShotLog` の差が実際の差と一致
- **風と傾斜**：向かい風で短く・追い風で長く・横風で風下へ、傾斜で球が低い方へ曲がる、坂の上では止まらず平らなところで止まる
- **メーター**：押下の境界 Tick（帯の端ちょうど・1 Tick 外）、2 回目なし→ミス、1 回目なし→取り消し（打数不変）、3 回目は無視、30〜240fps と不規則間隔で同じ入力列のハッシュが一致（022）
- コース・設定：実データが通る、壊れたデータ 10 通り程度を拒否、範囲外の設定を拒否
- 共通：状態遷移（タイトル→3 ホール→結果→再戦）、終了後の入力無視、フォーカス喪失・復帰の順序入れ替え、Hash の「今同じでも以後が分かれる」組（022）、**操縦役で 20 シードが 3 ホールをそれぞれ par 以内で終える**（完了判定「規定打数で完走」）、シード 1 の最終ハッシュが .NET と Mono で一致

  - スイングは「振り始め・パワー・インパクト」の 3 回押し（計画の「2 回押し」は振り始めの後の 2 回）。
  - グリーンの上のパターの向きは 16 単位刻み（0.09°）。64 単位では 10 m で 6 cm ずれ、カップ（半径 54 mm）を狙えない。

## ルール表（セッション 1 で README に固定する案）

### コートと試合

| 項目 | 採用ルール |
|---|---|
| コート | 縦 32 m × 横 20 m（ゴールは左右の短い辺）。ゴールの幅 3 m・高さ 2 m。GK の範囲はゴール前の半径 5 m の半円 |
| 時間 | 試合時間 5 分（60 Tick/秒で 18,000 Tick）。前後半なし。得点・ライン外の間も時計は進む（止まる場面を作らない） |
| 開始・再開 | センターから攻める側のキックオフ。失点した側が次のキックオフ。キックオフの間、相手はセンターの円（半径 3 m）に入れない |
| 決着 | 時間切れで終了。勝ち・負け・引き分け。延長・PK はなし |
| 反則 | なし（体の接触は押し合いで止まるだけ）。オフサイドなし |

### 球（整数・固定小数点。1 m = 1000 単位、速さは 1 Tick あたり）

| 項目 | 採用ルール |
|---|---|
| 状態 | 位置（x, y）・高さ z・速度（vx, vy, vz）。高さ 0 で地面を転がる間は摩擦で減速、空中は重力。地面に触れたら反発の割合で弾み、小さい弾みは転がりに変わる |
| 地を這う球 | パス・ドリブルのこぼれ球・トラップ。速さは毎 Tick 一定の割合で減る |
| 浮き球 | ループパスとシュート（シュートは低い弾道）。着地点は予測で求める |
| ゴールポスト | 柱を円とし、球との接触は掃引（int-geometry の `Sweep`）で求めて跳ね返す。クロスバーは高さで判定 |
| 得点 | 球の全体がゴールラインを越え、ポストの間・クロスバーの下にあるとき。**ゴール通過の Tick に 1 回だけ**得点を記録し、その後は再開まで得点を判定しない（ネットの中で跳ねても、ラインを戻っても数えない） |
| ライン外 | 球の全体がタッチライン／ゴールライン（ゴールの外）を越えたら止める。最後に触れた側の相手が再開：タッチライン → スローイン、ゴールライン → 攻めた側が最後ならゴールキック（GK）、守った側が最後ならコーナーキック |

### 選手と操作

| 項目 | 採用ルール |
|---|---|
| 構成 | 各チーム GK 1（自動）＋フィールド 2。人間は青チームのフィールド 2 人のうち 1 人を操作する。もう 1 人は役割割当で自動に動く |
| 保持 | 球が足元の範囲（半径）に入り、高さが膝より低く、相対速度が一定以下なら保持する。保持中は球を体の前に置いて運ぶ（ドリブル）。保持者は少し遅くなる |
| 奪取 | 守備側は「タックル」で、保持者の球に届く範囲なら球を弾く（決まった向き・速さ）。タックルの後は一定 Tick 動けない（空振りの代償）。CPU も同じ規則 |
| パス | 方向キーの向きの円錐の中の味方から、パス候補評価で受け手を選ぶ（下の「パス候補評価」）。速さは受け手の到着時刻に合うよう、予測で決める |
| ループパス | 浮き球のパス。間の相手の上を越えられる |
| シュート | ゴールへ向けた低い浮き球。方向キーの上下でゴールの左右の隅を狙う。ぶれ（シードの乱数）は角度だけ |
| 切替 | 切替キーで、球に近い方の味方（いま操作している選手でない方）へ。パスを出したら受け手へ自動で切り替える。守備では球に近い方へ自動で切り替える（設定で切れる） |
| 切替と入力 | **切替の Tick に押していた移動・ボタンは新しい選手に引き継がない**（いったん離すまで無視）。切り替えた選手は同じ Tick から役割割当で動く |

### オフボールの役割割当（中心課題）

| 局面 | 役割 | 位置の決め方 |
|---|---|---|
| 攻撃（自チーム保持） | **支援**（パスコースを作る） | 保持者からの距離が帯の中で、相手から最も離れたパスコース（線分と相手の距離）を、候補点の格子から評価して選ぶ |
| 攻撃 | **抜け出し**（裏へ走る） | 相手の最終ラインの裏で、ゴールに近く、ループパスが届く点 |
| 守備（相手保持） | **寄せ**（プレス） | 保持者とゴールの間へ詰める |
| 守備 | **カバー** | 保持者以外の相手とゴールの間で、パスコースを切る点 |
| こぼれ球 | **回収** | 球への到着時刻（予測の軌跡に最初に届く Tick）が最も早い選手。ほかは攻守の中間の位置 |

- 役割は一定 Tick ごと（と保持者が変わった Tick）に割り当て直す。フィールド 2 人なので、全ての割当（2 通り）の費用（移動時間の和）を比べて決める。同点は選手番号の小さい順。
- 操作している選手は役割から外す（人間が動かす）。操作していない味方と CPU チームの全員が同じ割当を使う。

### ボール軌道予測とパス候補評価（重点）

- 予測：球を複製して本番と同じ `Step` を回し、Tick ごとの位置の列を作る（024 の `BallPredictor` と同じ。予測と本番は Tick 単位で一致する）。
- 到着時刻：選手が軌跡上の点に届く最短 Tick（最高速・加速の上限から）。球がそこにある Tick 以下なら「届く」。
- パス候補：受け手ごとに、足元・数歩前（走り込み）の候補点 × 地を這う／ループの軌道。各候補で「受け手が届く最初の Tick」と「相手の誰かが届く最初の Tick」を比べ、余裕（Tick の差）・前進量・ゴールへの近さで点数を付ける。相手が先に届く候補は除く。
- CPU の保持者も同じ評価でパス・ドリブル・シュートを選ぶ（シュートは「ゴールの隅への軌道に、GK とほかの相手が届かない余裕」で点数）。

### CPU と戦術差

- CPU チームの方針（設定アセット）：**前から奪う**（寄せの位置が高い）／**引いて守る**（カバーを優先し自陣に下がる）。攻撃は**つなぐ**（パスの点数の閾値が低い）／**蹴り込む**（早めにシュート・ループ）。
- 難しさ：反応の遅れ（Tick）・パスとシュートのぶれ・最高速。乱数は用途ごとの系列（試合シード × 用途）。
- 「戦術差が現れる」は、方針の組み合わせごとに複数シードの CPU 同士の試合を回し、統計（保持率・パス成功率・シュート数・ボールを奪った位置の平均）が方針どおりの向きに差が出ることをテストで確かめる。

## テスト（主なもの）

- **得点は一度だけ**：ゴールラインちょうど・1 単位越え・ポストに当たって戻る・クロスバーの上・ネットの中で跳ねる・ラインを戻る、で得点の記録が 0 か 1。得点の Tick に 2 つの条件（ライン外と得点）が重なっても得点だけ。乱択の長い通しで、得点の出来事の数とスコアが一致。
- **選手切替で入力が混線しない**：移動キーを押したまま切り替えると、新しい選手は離すまで動かず、古い選手はその Tick から自動で動く。切替と同じ Tick のパス・シュートは 1 回だけで、どちらの選手から出たかが一意。手動の切替と自動の切替（パスの受け手・守備）の順序を入れ替えたテスト。
- **支援位置へ動く**：保持者以外の味方が、一定 Tick 後に割り当てた支援位置の近くにいる（場面を作って確かめる）。支援位置のパスコースが、元の位置より相手から離れている。
- **予測**：予測の軌跡と本番の軌跡が Tick 単位で一致（地を這う・浮き球・弾む・ポストに当たる）。到着時刻の計算が、選手を実際に動かした結果と一致。
- **パス候補評価**：相手が先に届く候補を選ばない。ループは間の相手を越える場面で選ばれる。
- **ライン外と再開**：最後に触れた側で再開の種類と側が決まる。再開の間は相手が近づけない。
- **共通**：状態遷移（タイトル → 試合 → 時間切れ → 結果 → 再戦は新しいシード）、終了後の入力を無視、拒否で状態不変、設定の検証（境界・NaN）、シード固定で同じ試合（ハッシュ）、最終ハッシュを .NET と Mono で照合。
- **PlayMode**：仮想キーボードだけで 1 試合を完走して結果画面、切替の表示、一時停止・フォーカス喪失、タイトルへ戻った表示が起動直後と同じ。

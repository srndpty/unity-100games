## ルール表（セッション1・2で README に固定する要点）

| 項目 | 採用ルール |
|---|---|
| 時間・座標 | 60 Tick/秒、1 タイル = 256 単位の整数（tile-motion）。自機・敵は円、壁との解決は `BodyMotion`、動く物との接触は `Sweep`（相対軌跡） |
| 操作 | WASD 移動、マウス照準、左ボタン＝基本攻撃（押しっぱなしで攻撃間隔ごとに連続）、右ボタン＝スキル（範囲の薙ぎ払い、待ち時間あり）、Q＝回復薬、E＝近くの品を拾う（地面の名前のクリックでも拾う）、I/Tab＝持ち物（開いている間は一時停止）、Esc＝一時停止メニュー |
| 能力値 | 最大 HP・攻撃力（最小〜最大）・攻撃速度（攻撃間隔の Tick）・移動速度・防御・会心率・会心倍率・吸収（与ダメージの %）・火/冷気耐性。基礎値は自機の設定、装備の基礎値と Affix で変わる |
| **Affix の合成** | Affix は `StatMod`（能力・種類 `Flat`/`Increased`・値）の列。算出は **基礎 + Σ Flat → ×(100 + Σ Increased)/100**（整数、0 方向へ切り捨て、long で計算して上限で飽和）。**合成は可換**（装備・Affix の順序で結果が変わらない）、能力値は装備の集合からいつでも 0 から計算し直す（差分の加減はしない） |
| 装備 | 枠 5 つ（武器・鎧・兜・指輪・首飾り）。基礎品 **20 種**（武器 6・鎧 4・兜 3・指輪 4・首飾り 3）。基礎品は枠・必要階（出る階の下限）・基礎の StatMod を持つ |
| 希少度 | 普通（Affix 0）・魔法（1〜2）・希少（3〜4）。接頭 2・接尾 2 まで。値は Affix の段（階が深いほど上の段）の範囲から引く |
| **禁止の組合せ** | ①同じ Affix の**群**（例：火耐性の段違い）は 1 品に 1 つ ②データに書いた**排他の組**（例：「攻撃速度＋」と「重撃（攻撃速度−・攻撃力＋）」）③**枠に合わない Affix**（指輪に武器の攻撃力など）。生成は残った候補から重み付きで引き、候補が尽きたら Affix を減らす（禁止を破って埋めない）。データの検証で、排他の組の片方が未定義・自分自身との排他・どの枠にも付かない Affix を拒否 |
| 生成の乱数 | **敵ごとに独立した系列**：`試合シード × 階 × 敵の配置番号` から派生（015）。倒す順・倒した Tick・他の敵のドロップに依らず同じ品が出る。宝箱も同じく配置番号から |
| ドロップ | 敵の種類ごとの確率と希少度の重み、ボスは希少確定 2 品。**倒れた Tick に 1 回だけ**判定し、敵に「落とした」印を立てる（同じ Tick の複数の攻撃・飛び道具・スキルの同時命中でも 1 回）。回復薬もドロップ（所持上限 5） |
| 品の数の上限 | 敵は再出現しないので品の総数は有限（無制限生成はしない）。地面の品は階ごとに上限（例 48）、持ち物 20 マス。満杯なら拾えない（案内を出す） |
| 敵 3 種 | 近接（追って殴る）・射手（距離を取って矢、矢は飛び道具として掃引）・突進（溜めて直線に突っ込む）。各階の固定の配置。気づく距離に入るまで待機 |
| ボス | 3 階の奥の部屋。近接の薙ぎ・火の弾の扇・HP 半分で突進が加わる。撃破で勝利→結果（時間・撃破数・死亡回数・拾った品の数・最高の希少品）→タイトル |
| 被弾・死亡 | 防御：`ダメージ × 100 / (100 + 防御)`、耐性は % で減算（上限 75%）、最低 1。被弾後の無敵 30 Tick。HP 0 で**その階の入口に復活**（HP 全快、持ち物・装備・倒した敵・開けた宝箱は保持、生きている敵の HP と位置は初期へ戻す）。ボスも HP 全快に戻る |
| 階の移動 | 各階の階段で下へ。戻りはしない（必要なし）。階に入った時の状態が復活点 |
| 説明表示 | Core の `ItemText.Describe(item)` が基礎値と各 Affix の行を作る（名前・希少度の色・「攻撃力 +12」「攻撃速度 +15%」）。装備中の品との**能力値の差**（`StatSheet` を付け替えて算出した差）も Core で出す |

## セッション1：戦利品（Core）

- `LootData`（TextAsset `Loot.txt` の表：基礎品・Affix・群・排他・段・ドロップ表）を Core のパーサで読み、`LootValidator` が理由付きで検証（040 の `MoveTable`、041 の `GameDataValidator` の方式）。指紋は 040 `Fingerprint.cs` の方式
- `StatMod`・`Affix`・`ItemBase`・`Item`（不変、Affix の列と値）・`Equipment`（5 枠）・`StatSheet.Compute(base, equipment)`
- `LootGenerator.Roll(rng, floor, dropTable)` → `Item?`、`AffixRules.IsAllowed(item)`（生成とテストの両方で使う）
- `ItemText`（説明の行、比較の差）

### テスト（セッション1）

- **禁止 Affix**：多数のシード × 全階 × 全枠で生成した全品が `IsAllowed`（群の重複・排他・枠違いなし）。わざと禁止を含む候補しか残らない表で、Affix が減って禁止を出さない。`IsAllowed` 自体を素朴な全組合せの参照実装と照合
- **装備入替後の能力値**：着脱・入替（A→B→A で元に戻る）・同じ枠の付け替え・全外し＝基礎値。合成が順序に依らない（装備の並びを乱択で入れ替えて一致）。Flat と Increased の境界（切り捨て、上限の飽和、負の Increased で 0 未満にならない）。テスト側の素朴な再計算と乱択で照合
- 生成：同じシードで同じ品、配置番号が違えば別の系列、希少度・段の分布が階で変わる、全基礎品・全 Affix が出うる（019 の「範囲内の値でシードで結果が変わる」）
- データ検証の負例：重複 ID・未定義の群/排他・空の枠・重み 0 の合計・範囲の逆転・合計の int 超え（041）を 1 つずつ拒否
- 説明文：全基礎品・全 Affix に文があり、比較の差が `StatSheet` の差と一致

## セッション2：戦闘・探索・App

- Core：`FloorMap`（文字の地図＋配置、`ISolidGrid`）、`Hero`（移動・攻撃・スキル・無敵・回復薬）、`Foe`（3 種＋ボスの状態機械、気づく距離）、`Projectile`、`DelveRun`（Step・Clone・Hash、ドロップ・拾う・装備・死亡と復活・階段・勝利）、`DelveConfig`（検証付き）
- 単発の操作は「押したまま」と「その Tick の押下」を分けて渡す（040 の教訓）。ハッシュに設定・データの指紋を混ぜる（040）
- App：`DelveFlow`（Title / HowTo / Playing / Inventory / Paused / Result、時刻付き入力をフレーム単位の上限で Tick へ）、`Autopilot`（`Clone` の先読みで戦い、拾って強ければ装備、階段→ボス）と人寄りの操縦役（反応を遅らせる、038）
- 持ち物の画面の操作（装備・外す・捨てる）は Flow の意図の列を通す（012：順序のある操作は 1 本の列）

### テスト（セッション2）

- **二重ドロップなし**：同じ Tick に基本攻撃＋スキル＋吸収で倒す、2 本の飛び道具が同じ Tick に当たる、死んだ敵への追撃、死亡→復活をまたぐ、`Clone` 後の両方 → いずれもドロップ 1 回（出来事の数と地面の品）。修正前相当の実装で失敗することを確かめる
- 戦闘：被ダメージの式（防御・耐性の上限・最低 1）、無敵の境界 Tick、攻撃間隔、吸収の上限、矢・突進の掃引（かすり）
- 死亡と復活：入口・HP 全快・持ち物保持・倒した敵は戻らない・ボス HP 全快
- 状態遷移：タイトル→プレイ→結果→タイトル、結果の後の入力を無視、持ち物を開いている間 Tick が進まない、満杯で拾えない
- 操縦役で 20 シード全部が規定 Tick 内にボス撃破、人寄りの操縦役の勝率、シード 1 の最終ハッシュが .NET と Mono で一致

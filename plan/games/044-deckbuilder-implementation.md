# 044 デッキ構築ローグライト 実装計画

## Context

- 仕様書 [plan/games/044-deckbuilder.md](044-deckbuilder.md) の中心課題は「**カード効果をコマンド列/イベントで実行**」、重点は「**対象選択と解決を分離**」。
- In scope：20 カード・敵 5 種・ボス 1、短い 3 戦ルート、報酬によるデッキ改善、タイトル→操作説明→結果→再プレイ。Out of scope：長大マップ、数百カード（増やさない）。
- 題材固有テスト：**エネルギー不足カードを使えない／複数効果の順序が固定／廃棄カードが捨て札へ混入しない**。完了判定：**3 戦を遊べる／効果順のユニットテスト通過**。
- ユーザーと決めたこと：
  - **分岐あり 3 戦**：戦 1・戦 2 は 2 つの遭遇から選ぶ（片方は手強い代わりに報酬の希少度が上がる）、戦 3 はボス。戦 1 と戦 2 の間に休憩を 1 回。
  - **マウス＋キー併用**：カードをクリック→対象をクリックで確定。キーは 1〜0 でカード、←→/Tab で対象、Enter で確定、E でターン終了、右クリック/Esc で選択の取り消し。
  - **報酬はカード 3 択（スキップ可）＋任意の 1 枚除去**（強化版カードは作らない）。
- 作品名はオリジナル（仮）：**CINDER LEDGER**。参考作品の名称・カード名・敵・演出は使わない。
- 作業は `feature/game044`（main から切る。043 はマージ済み）。ルールの正は作品 README の「採用ルール」。

## ルール表（セッション1・2で README に固定する要点）

| 項目 | 採用ルール |
|---|---|
| 数値 | 全て整数。浮動小数点を使わない。倍率は百分率で 0 方向へ切り捨て |
| 自機 | 最大 HP 70（戦闘をまたいで持ち越し）、毎ターン エネルギー 3・5 枚引く、手札上限 10（超えて引いた分は捨て札へ） |
| 初期デッキ | 10 枚（基本攻撃 ×5・基本防御 ×4・固有 1 枚） |
| **領域** | 山札・手札・**解決中**・捨て札・**廃棄**の 5 つ。カードは実体 ID（デッキ内で一意）で持ち、どの時点でも**ちょうど 1 つの領域**にある（不変条件をテストで全局面検査）。山札が空で引くときは捨て札を戦闘ごとのシャッフル系列で混ぜて山札へ。**解決中・廃棄は混ぜない** |
| **カードを使う** | `PlayCard(実体 ID, 対象 ID?)` → 検証（自分の番・手札にある・**エネルギーが足りる**・対象の種類に合い生きている）→ 不可なら `Rejected(理由)` を返し、**状態・乱数・ハッシュを何も変えない**。可ならエネルギーを払い、カードを「解決中」へ移し、データの効果列を**コマンド列**に展開して解決キューへ |
| **解決キュー** | FIFO。各コマンド（`Damage`・`Block`・`ApplyStatus`・`Draw`・`GainEnergy`・`ExhaustFromHand`・`Discard` など）は実行時に状態を変え、**出来事（`BattleEvent`）を記録**し、続きのコマンドを**キューの末尾**に積むことがある（例：倒れた→死亡処理）。カードの効果列は**書いた順に**実行し、終わってからカードを捨て札（`廃棄` 持ちなら廃棄）へ移す。キューの長さに上限を置き、データの検証で超えないことを保証（超えたら例外・fail-closed） |
| **対象選択と解決の分離** | 対象の種類はデータ：`None`・`Self`・`Enemy`（単体）・`AllEnemies`・`RandomEnemy`。**選ぶ**のは App の `TargetingSession`（選んだカード・候補・カーソル・取り消し）、Core は確定した `PlayCard` だけを受ける。`AllEnemies`／`RandomEnemy` は**解決時**にその時点の生きている敵から決める（乱択は戦闘の効果系列）。単体の対象が解決の途中で倒れたら、その対象への残りのコマンドは**不発**（出来事 `Fizzled` を記録）、他のコマンドは続ける |
| ダメージ計算 | 基礎 ＋ 筋力 → 脱力なら ×75/100 → 弱体なら ×150/100 → 0 未満は 0 → ブロックで吸収 → 残りを HP。順序は固定でテスト |
| 状態異常 | 筋力（永続・戦闘中）、脱力・弱体（ターン数、持ち主のターン終わりに −1）、毒（ターン開始に量のダメージ、−1）。ブロックは持ち主のターン開始に 0 |
| ターン | 自分の番：ブロック 0 → 毒 → エネルギー 3 → 5 枚引く → 操作 → `EndTurn` で手札を全て捨て札へ（廃棄持ちでも手札にあるだけなら捨て札）→ 敵の番：敵ごと番号順に意図を実行 → 次の意図を決めて公開 |
| 敵の意図 | 敵のデータの行動パターン（巡回の列、または重み付きの抽選を敵の系列で）。**次の行動を自分の番の初めに公開**し、表示は Core の `IntentView` から |
| 勝敗 | 敵全滅で勝利（途中で全滅したら残りのキューは捨てて報酬へ）。自機 HP 0 で即敗北→結果。終了後の操作は全て `Rejected` |
| **ルート** | 戦 1（2 択：通常／手強い）→ 報酬 → 休憩（最大 HP の 30% 回復 or 最大 HP +6）→ 戦 2（2 択）→ 報酬 → 戦 3 ボス → 結果。遭遇の候補はルートの系列で決め、敵 5 種が試合をまたいで登場しうる |
| **報酬** | カード 3 択（重複なし、希少度の重みは遭遇の強さで変わる、スキップ可）＋任意で**デッキから 1 枚除去**（デッキは 5 枚未満にしない）。ボス勝利の後は報酬なしで結果 |
| 乱数の系列 | 試合シードから用途別に派生（043 の `GameRng.For` を写す）：ルート、報酬 = (シード, 節)、シャッフル・敵の考え・効果の乱択 = (シード, 戦闘) の別系列。再戦は新しいシード |
| データ | `Cards.txt`・`Enemies.txt`・`Encounters.txt`（TextAsset、Core のパーサで読み、`DeckDataValidator` が理由付きで検証、040/041 の方式）。指紋（`Fingerprint`）をハッシュに混ぜる |

## セッション1：カードと戦闘（Core）

- `CardDef`・`EffectDef`（データの効果）→ `Command`（実行単位）、`CardInstance`（実体 ID）、`Zones`（5 領域と移動の唯一の入口）、`ResolveQueue`、`BattleEvent`、`Combatant`（HP・ブロック・状態異常）、`DamageCalc`、`Battle`（`PlayCard`・`EndTurn`・`Clone`・`Hash`、`PlayResult`/`Rejected(理由)`）
- 公開は読み取り専用の窓口 `BattleView`（手札・各山の枚数・敵と意図・出来事）。可変の部品を公開しない（042・043）
- データのパーサと `DeckDataValidator`、`Fingerprint`、`GameRng`（043 から写す）

### テスト（セッション1）

- **エネルギー不足**：コスト = エネルギー＋1 で `Rejected`、ちょうどで成功。拒否の前後で状態ハッシュ・乱数の状態・領域・出来事の数が完全に同じ。他の拒否（手札にない・対象が死んでいる・対象の種類違い・相手の番・終了後）も同様
- **効果順の固定**：複数効果のカードごとに、出来事の列を期待値と完全一致で照合（例：2 連撃→ブロック→引く）。途中で山札が尽きて混ぜ直しても**解決中のカード自身は混ざらない**。単体対象が 1 撃目で倒れたら 2 撃目は不発、後続の「引く」は実行。筋力・脱力・弱体の掛かる順。全体攻撃は敵の番号順。同じ入力で 2 回解決して出来事の列が一致
- **廃棄の非混入**：廃棄カードを使った後、捨て札・山札・手札にない。捨て札を混ぜ直しても廃棄から戻らない。手札から廃棄する効果、ターン終わりの捨てでも廃棄の山が変わらない。乱択の長い対戦（多数のシード × ランダムな合法手）で**全局面の領域の不変条件**（各実体がちょうど 1 領域、廃棄は単調増加）を検査
- ダメージ計算の境界（切り捨て、0 未満、ブロックちょうど）、手札上限、キューの上限の検証、データ検証の負例（重複 ID・未定義の効果・コスト負・対象の種類と効果の矛盾・カード 20 種でない）

## セッション2：ルート・敵・App

- Core：敵 5 種＋ボスの行動データと意図、`Encounter`、`RunState`（デッキ・HP・節・選択）、`RouteMap`（2 択×2＋休憩＋ボス）、報酬の生成と除去、`Run`（`ChooseEncounter`・`PickReward`・`SkipReward`・`RemoveCard`・`Rest`、全て不正なら `Rejected`）、`RunConfig`（検証付き、`long` で積も検証 043）
- App：`DeckFlow`（Title / HowTo / Route / Battle / Reward / Rest / Result）、`TargetingSession`（選択→対象→確定／取り消し）、意図の列（012：クリックとキーを 1 本の列）、**演出の再生中は入力の受付で捨てて選択も消す**（015）、出来事の再生位置（`EventPlayback`：Tick で進み、撮影でも同じ絵）
- `Autopilot`（`Clone` で 1 ターン内の手順を列挙・評価、報酬は簡単な評価）、人寄りの操縦役（貪欲＋時々の悪手）

### テスト（セッション2）

- ルート：分岐の選択、休憩、報酬の 3 択の重複なし・スキップ・除去の下限、ボス後は報酬なし、終了後の操作拒否、再戦は新しいシード
- 敵：意図の公開と実行が一致、ボスの取り巻き呼び出し、全滅の途中でキューが止まる
- App：選択→取り消し→別カード、対象のいないカードは即確定、演出中のクリック/キーを捨てて持ち越さない、選んでいたカードがエネルギー不足になったら選択解除
- 操縦役 20 シードの勝率、人寄りの勝率を記録。シード 1 の最終ハッシュを .NET と Mono で固定値照合

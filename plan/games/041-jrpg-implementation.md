# 041 コマンドRPG 実装計画

## Context

- 041 コマンドRPG（難易度 3・Phase 3 の最初）は未着手。仕様書 [plan/games/041-jrpg.md](041-jrpg.md) の中心課題は「**ゲームデータを ScriptableObject 等からロード**」、重点は「**戦闘コマンドと演出を分離**」。
- In scope：町 1・ダンジョン 1・ボス 1、通常戦闘と魔法/アイテム、装備・経験値・セーブ、タイトル→操作説明→結果→再プレイ。Out of scope：大規模ストーリー、クラス転職、素材・面の量産。
- 題材固有テスト：**MP 不足で呪文使用不可／全滅・逃走時の状態が一貫／セーブ再ロードで装備・フラグ一致**。完了判定：**町→探索→ボス→エンディング成立、保存後に再開可能**。
- 共通ルールの「セーブがある題材は破損データ・部分データ・バージョン差の扱いを明記」が初めて効く題材（023 のセーブはメモリ内の複製だけで、ファイル保存はリポジトリで初）。
- ユーザーと決めたこと：
  - **2D 見下ろしタイル**のフィールド（町・ダンジョン）を 1 マスずつ歩く。戦闘は別画面（敵を正面から見る）。生成ドット絵。
  - **3 人パーティ**（戦士・僧侶・魔法使い）。
  - **ランダムエンカウント**（歩数とシード付き乱数、階ごとの敵グループ表）。
  - **町の教会で 1 枠セーブ**（ファイル）、タイトルの「つづきから」で再開。破損・途中・旧版は読み込みを拒否して案内する（移行はしない＝互換残しをしない方針）。
- 作品名はオリジナル（仮）：**EMBERLOCK HOLLOW**。参考作品の名称・呪文名・モンスター・演出は使わない。
- 作業は `main` から `feature/game041` を切る。この計画は session 0 で `plan/games/041-jrpg-implementation.md` に置き、ルールの正は作品 README の「採用ルール」とする。

## ルール表（セッション1・2で README に固定する要点）

| 項目 | 採用ルール |
|---|---|
| データ | 職業・敵・敵グループ・呪文・道具・装備・経験値表・遭遇表・店の品・地図は **ScriptableObject のアセット**（地図の形だけは文字の地図 `TextAsset`）。Unity 層の `GameDatabase`（SO）が Core の定義クラス（公開フィールド、028 の `EnemyDefinition` → `EnemyDef` 方式）に変換し、Core の `GameData.Validate` が全体を検証して不変の `GameData` を作る。参照は文字列の ID（重複・未解決・範囲外・有限でない値は理由付きで拒否） |
| パーティ | 3 人固定（戦士・僧侶・魔法使い）。能力：HP・MP・攻撃・守備・素早さ・レベル・経験値。装備は武器・防具の 2 枠、職業ごとに装備可否 |
| 成長 | 経験値表で到達したら上がる（1 戦で複数レベルも）。上昇値は職業のデータ（乱数なし）。戦闘で倒れていた者には経験値を入れない |
| 戦闘コマンド | たたかう（1 体）／じゅもん（呪文と対象）／どうぐ（道具と対象）／ぼうぎょ（被ダメージ半減）／にげる（パーティ全体で 1 回判定）。**3 人分のコマンドを選び終えてから 1 ターンを解決** |
| 行動順 | 素早さ＋乱数のぶれ（`0..Agi/4`）の降順、同値は「味方→敵、番号順」。ぼうぎょはターン先頭で効く |
| ダメージ | 整数：`max(0, 攻撃/2 − 守備/4) × (7..9)/8`（乱数）、0 なら 1/2 の確率で 1。会心・ミスは入れない（ルールを小さく保つ） |
| 対象の付け替え | 選んだ敵が既に倒れていれば同じグループの次の生存者へ。全滅していれば何もしない。回復の対象が倒れていれば失敗（MP は消費しない） |
| 呪文 | 単体攻撃・グループ攻撃・単体回復・全体回復・蘇生（ボス戦の救済）の 5 種程度。**MP 不足の呪文はコマンド選択の時点で拒否**（Core の `CanCast` が理由付きで返し、メニューは灰色）。選択後に MP が減っていた場合（解決時に不足）は「MP が足りない」の出来事で何もしない |
| 道具 | 回復草・MP の水・解毒は作らない（状態異常は入れない）。所持数の上限 99、使ったら減る。戦闘でも使える |
| 逃走 | 成功率はパーティと敵の素早さの比（データで上下限）。**ボスは逃走不可**（コマンドを拒否）。成功したらその場（フィールドの同じマス）へ戻り、経験値・お金は増えず、HP・MP・道具の消費は残る。遭遇の歩数はリセット |
| 全滅 | 生存者 0 で敗北。**教会の前へ戻り、全員 HP 全快・MP 全快・お金半分（切り捨て）**、装備・道具・経験値・フラグは保持。ボス戦の全滅も同じ（ボスは体力全快で待つ） |
| 勝利 | 経験値・お金を生存者で分配（経験値は生存者に全額ずつ）。ボス撃破でフラグ `BossDefeated` → エンディング → 結果（歩数・戦闘数・プレイ時間・レベル） → タイトル |
| 敵の行動 | 敵ごとの行動表（重み付き）。ボスは HP 半分で行動表が切り替わる。対象は生存する味方から乱数 |
| 乱数 | 系列を分ける（015）：遭遇（歩数と敵グループ）、戦闘ごと（試合シード＋戦闘番号から派生）。1 試合 = 1 シード、セーブにはシードと戦闘番号・遭遇の系列の状態も入れ、再ロード後の結果を再現できる |
| フィールド | 町（宿・店・教会・NPC 2〜3 人・ダンジョンへの出口）、ダンジョン 3 階＋ボスの間。1 マスずつ移動（8 Tick で 1 マス、移動中は次の入力を先行で 1 つ保持）。扉・階段で地図を移る。宝箱（開けたらフラグ）、鍵の扉（宝箱の鍵でフラグ） |
| 遭遇 | 町では無し。ダンジョンでは 1 歩ごとに階の確率で遭遇、遭遇直後の数歩は無し（データ）。ボスはボスの間の決まったマスで固定戦闘 |
| 町の施設 | 宿（お金で全快）、店（お金で買う・売る、売値は半額、装備は買ったら装備するか確認）、教会（セーブ・倒れた仲間の蘇生（有料））。NPC はフラグで台詞が変わる（例：ボスの弱点の案内） |
| セーブ | **教会でだけ保存、1 枠**。中身：版番号・データの指紋（`GameData` の内容から）・パーティ（レベル・経験値・HP/MP・装備）・道具・お金・フラグ・シード・戦闘番号・遭遇の乱数状態・歩数・プレイ時間。形式は Core の行指向テキスト（`key=value`、最後に全体の CRC32 か `StateHash`）。**拒否する場合**：行が欠けた（途中で切れた）・チェックサム不一致・版番号違い・データの指紋違い・ID 未解決・値域外。拒否は理由付き、タイトルで「セーブデータを読み込めません（理由）」と案内し、つづきからを出さない（ファイルは消さず、次の保存で上書き） |
| ファイル書き込み | Unity 層。`persistentDataPath` に一時ファイル→`File.Replace`（初回は `Move`）で原子的に置き換え（証跡の `IEvidenceFileOps` と同じ考え）。バッチ実行・撮影中はテスト用の別ディレクトリ |
| 操作 | 矢印/WASD 移動、Z/Enter/Space 決定、X/Esc 取消・メニュー、長押しで連続移動（012 の `MoveRepeater` の教訓：押したフレームの deltaTime を含めない）。フォーカス喪失で保留入力を消す |

## セッション1：データと戦闘（Core）

- 定義クラス：`ClassDef`・`EnemyDef`・`EnemyGroupDef`・`SpellDef`・`ItemDef`・`EquipDef`・`ExpTable`・`EncounterTableDef`・`ShopDef`・`MapDef`（文字の地図＋扉・宝箱・NPC の配置）
- `GameData`（検証済みの不変の束、ID → 番号の索引、指紋）・`DataError`（理由と場所）
- `PartyMember`・`Party`（装備で能力を算出、レベルアップ）・`Inventory`
- 戦闘：`BattleState`（味方・敵・ターン番号・終了理由）、`BattleCommand`（コマンドの値型）、`BattleRules.Validate(command)`（MP 不足・ボスの逃走・倒れた者のコマンド・所持 0 の道具を理由付きで拒否）、`BattleResolver.ResolveTurn(state, commands, rng) → IReadOnlyList<BattleEvent>`
  - **演出との分離**：解決は純粋関数で、状態はターンの終わりの値へ一度に進む。`BattleEvent`（行動の開始・ダメージ・回復・MP 消費・倒れた・逃走成功/失敗・勝利・全滅・レベルアップ）は演出用の記録で、**状態を変えない**。演出は出来事の列を時間をかけて見せるだけ（014 の「解決は純粋関数、フェーズは待ち時間だけを数える」）
- 敵の行動選択 `EnemyAi`（重み付き行動表、ボスの段階切り替え）

### テスト（セッション1）

- **データ検証**：既定データが通る。ID の重複・未解決参照（敵グループ→敵、店→品、遭遇表→グループ）・経験値表が単調でない・負や 0 の上限・装備できない職業だけの装備・地図の扉の行き先なし・宝箱の中身なし を 1 つずつ拒否（負例ごとに理由を確認）
- **MP 不足で呪文使用不可**：MP がちょうど・1 足りない境界、選択時の拒否、選択後に MP が減って解決時に不足（何も起きず MP も減らない）、敵の呪文も同じ
- **逃走**：成功時に戦闘の終了理由・HP/MP/道具の消費が残る・経験値/お金が増えない、失敗時は敵だけ行動、ボスで拒否
- **全滅**：最後の 1 人が倒れた出来事の後に行動が続かない、ターンの途中の残りの行動が捨てられる、終了後のコマンドを拒否
- 行動順（同値の並び）、対象の付け替え、ぼうぎょ、レベルアップ（複数段・倒れた者は対象外）、装備の付け替えで能力が変わる
- **出来事の再生**：出来事の列を前の状態に順に当てた結果がターンの終わりの状態と一致（演出が状態を作り直しても食い違わない保証）
- 同じシードとコマンド列の戦闘の最終ハッシュが .NET と Mono で一致

## セッション2：フィールド・町・セーブ・App

- `FieldMap`（地図の通行・扉・宝箱・NPC）、`Explorer`（位置・向き・移動の Tick・遭遇の歩数と乱数）、`Flags`（ビット集合＋名前の索引）、`Town`（宿・店・教会の操作、お金の不足などを理由付きで拒否）
- `World`（パーティ・道具・お金・フラグ・位置・シード・戦闘番号・プレイ時間を束ねる、`Clone`・`Hash`）
- `SaveCodec`：`World` ⇄ テキスト。`Encode` → `Decode` の往復、拒否の理由型 `SaveError`
- App：`QuestFlow`（Title / Intro / Field / Menu / Shop / Battle / Ending / Result / Paused）、`MenuCursor`（ウィンドウの階層とカーソル、取消で戻る）、`BattlePresenter`（出来事の列を時間で送る演出キュー、決定で早送り。状態は Core の値を見せるだけ）、`Autopilot`（町で買い物→階段へ経路探索→戦闘は単純な方針→レベルが足りなければ入口付近で稼ぐ→ボス）、`Intent`
- 保存は App の `ISaveStore`（読む・書く）を通し、テストはメモリ上の偽物で行う

### テスト（セッション2）

- **セーブ再ロードで装備・フラグ一致**：保存→読み込みで `World.Hash` が一致（装備・道具・フラグ・お金・レベル・乱数状態）。読み込み後に同じ入力列を流して以後の最終ハッシュも一致（未来の動きが同じ、022 の教訓）。保存した記録が以後の進行で変わらない
- **セーブの負例**：途中で切れたテキスト（全ての切り位置）・1 文字の改変・版番号違い・データの指紋違い・未知の ID・値域外・重複キー → すべて理由付きで拒否し、`World` を作らない
- **全滅の後処理**：教会の前・全快・お金半分（奇数の切り捨て）・装備・道具・経験値・フラグ保持。**逃走の後処理**：同じマス・歩数リセット・消費は残る。どちらも戦闘番号が進み、次の戦闘は別の乱数
- 町：宿・店（お金ちょうど/1 足りない、所持 99 の上限、売ると装備中なら外す）・教会（蘇生・保存の可否）、教会以外では保存できない
- フィールド：壁・扉・階段、宝箱は 1 回だけ（再ロード後も開いたまま）、鍵の扉、町で遭遇しない、遭遇直後の猶予
- 状態遷移：タイトル→はじめから/つづきから→…→エンディング→結果→タイトル、エンディング後や戦闘終了後の不正操作を無視、重複した決定入力で二重購入しない
- 操縦役で 20 シード全部が規定 Tick 内にエンディング、入力なしは進まない。シード 1 の最終ハッシュが .NET と Mono で一致。全滅を含む通しも 1 つ
- 再戦（はじめから）で新しいシード・状態の初期化

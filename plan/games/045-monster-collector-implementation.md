# 045 モンスター収集RPG 実装計画

## Context

- 仕様書 [plan/games/045-monster-collector.md](045-monster-collector.md) の中心課題は「**技・属性・状態異常をデータ駆動**」、重点は「**捕獲/交代/戦闘をフェーズで管理**」。
- In scope：6 種のモンスター、捕獲とパーティ、属性 3 種・状態異常 2 種、CPU トレーナー 3 戦、タイトル→操作説明→結果→再プレイ。Out of scope：通信交換、数百モンスター（増やさない）。

- ユーザーと決めたこと：
  - **2D 見下ろしタイル**のフィールド（041 の方式）。草むらでランダム遭遇、トレーナーは地図上に立つ。
  - **中断セーブ＋記録**：回復所で 1 枠保存（パーティ・ボックス・図鑑・進行フラグ・乱数状態）、タイトルの「つづきから」で再開。クリア記録（最短時間・捕まえた種類数）も別ファイルに残す。
  - **手持ち上限 6・超えたらボックスへ**。回復所の端末でボックスと入れ替える。
  - **GameRng をセッション0で共通パッケージへ抽出**し、041・043・044 を置き換えてから 045 で使う。
- 作品名はオリジナル（仮）：**THORNWILD KEEPERS**。参考作品の名称・モンスター・技名・演出は使わない。
- 作業は main から `feature/game045`。ルールの正は作品 README の「採用ルール」。

## ルール表（セッション1・2で README に固定する要点）

| 項目 | 採用ルール |
|---|---|
| 数値 | 全て整数。倍率は百分率で 0 方向へ切り捨て |
| データ | `Species.txt`・`Moves.txt`・`Types.txt`（相性表）・`Statuses.txt`・`Encounters.txt`・`Trainers.txt`・`Learnsets.txt` と地図の `TextAsset`。Core のパーサで読み、`MonsterDataValidator` が理由付きで検証（044 の方式）。`Fingerprint` をハッシュとセーブに混ぜる |
| 属性 3 種 | 灯・潮・苔（仮称）の三すくみ。**相性表もデータ**：効果抜群 200%、いまひとつ 50%、等倍 100%。技の属性＝自分の属性なら 150%（一致補正） |
| 種族 6 | 各属性 2 種（基本形＋進化しない別種で十分。進化は作らない）。種族値（HP・攻撃・防御・素早さ）・捕獲率・経験値の量・覚える技（レベル） |
| 技（約 12） | データ：属性・威力・命中・PP・優先度・**効果列**（`Damage`・`Inflict(状態, 確率)`・`Heal(%)`・`StatStage(能力, 段)` など）。効果は書いた順に解決（044 のコマンド列を小さく写す）。状態異常だけの技、ダメージ＋確率で状態異常の技を含める |
| ダメージ | `((2×Lv/5+2) × 威力 × 攻撃/防御)/50 + 2` → 一致補正 → 相性 → 乱数 85〜100% → 最低 1（相性 0 は作らない）。順序固定でテスト |
| **命中** | 命中 `A`（1〜100）に対し `Next(100) < A` で命中。**乱数は命中 100 でも 1 回引く**（系列の使用回数を技に依らず一定に）。外れたら効果列の残りを全て不発 |
| **状態異常 2 種** | データ駆動（`Statuses.txt`：行動不能か・毎ターン終わりのダメージ割合・持続ターン範囲・捕獲補正）。**毒**：ターン終わりに最大 HP の 1/8（最低 1）、持続 4 ターン固定。**眠り**：行動不能、持続 1〜3 ターン。**持続は付与した時点で決めて「解除予定のターン番号」として持つ**（付与時の乱数 1 回）。予定ターンの開始で解除→そのターンから行動可（眠り）／その終わりでは減らない（毒）。重ね掛けは失敗 |
| 個体 | 種族・レベル（上限 20）・経験値・現在 HP・技 4 枠と PP・状態異常・能力段（戦闘中のみ）。能力は種族値とレベルから（個体差・努力値なし）|
| **育成** | 倒した相手の経験値を**戦闘に出た生存者で等分**（端数切り捨て）。経験値表でレベルアップ（複数段も）、覚える技は空き枠へ、4 枠埋まっていれば**入れ替えるか覚えないかを選ぶ**（戦闘後にまとめて） |
| **戦闘のフェーズ** | `Battle` は明示的なフェーズ機械：`ChooseCommand` → `Resolve` → （倒れた側の）`ForcedSwitch` → （捕獲成功）`Captured` → `Ended(理由)`。各フェーズで受け付けるコマンドだけを受け、他は `Rejected(理由)` で状態・乱数・ハッシュを変えない（044 の方式）|
| コマンド | たたかう（技）／交代（手持ちの元気な別個体）／道具（傷薬・捕獲玉）／にげる（野生のみ）。行動順：交代・道具・にげる → 技（優先度 → 素早さ → 同値は戦闘の系列で 1 回の抽選）。交代で出た個体はそのターン行動しない。相手の技は交代先が受ける |
| **交代** | 自分の番の交代は 1 ターン消費。**倒れたときの強制交代はターンを消費しない**（`ForcedSwitch` フェーズ、元気な個体がいなければ敗北）。トレーナーの CPU も倒れたら次の個体を出す（番号順）|
| **捕獲** | 野生のみ（トレーナー戦は `Rejected`）。捕獲値 = 捕獲率 × (3×最大HP − 2×HP) / (3×最大HP) × 状態補正（眠り 200%・毒 150%）、`Next(256) < 捕獲値` で成功（上限 255 で確定）。失敗なら相手の行動。成功で戦闘終了 |
| **手持ちとボックス** | 手持ち **最大 6**。捕獲時に手持ちが 6 なら**ボックスへ**（容量 30）。ボックスも満杯なら捕獲玉の使用を `Rejected`（玉も減らない）。回復所の端末で手持ち⇄ボックスの入れ替え・預ける・引き出す。**手持ちを 0 匹にする操作は拒否**。手持ち・ボックスの増減の入口を 1 つにし、全局面で上限の不変条件を検査 |
| 逃走 | 野生のみ。成功率 = 素早さの比（上下限はデータ）、試行回数で加算 |
| 敗北（全滅） | 最後に寄った回復所へ戻り、全員全快。捕獲・経験値・フラグは保持、捕獲玉と傷薬はそのまま |
| CPU | 野生は技を等確率。トレーナーは「相性が良く命中期待値の高い技」を選ぶ貪欲（状態異常済みの相手に状態技を使わない）、乱数は戦闘の系列 |
| フィールド | 町（家・回復所＝回復・セーブ・ボックス端末・捕獲玉の補充）、道 1（草むら）、道 2（草むら）、最後の広場。**トレーナー 3 人は道を塞ぐ位置**に立ち、話しかけて戦う。勝つと通れる（フラグ）。3 人目に勝つとエンディング→結果 |
| 遭遇 | 草むらに入った 1 歩ごとにデータの確率、場所ごとの出現表（種族と Lv 範囲、重み）。遭遇直後の数歩は無し |
| 開始 | 3 匹（属性ごと）から 1 匹を選ぶ。捕獲玉 5・傷薬 3 |
| 乱数の系列 | 抽出した `Derive(試合シード, 番号, 用途)`：遭遇（歩数）、戦闘ごと（戦闘番号）、付与の持続も戦闘の系列。セーブに系列の状態を入れる。再戦（はじめから）は新しいシード |
| セーブ | 041 の `SaveCodec` を写す：行指向テキスト、版番号・データの指紋・末尾のチェックサム。**回復所でだけ保存・1 枠**。拒否（切れた・改変・版違い・指紋違い・未知 ID・値域外・**手持ち 0 や 7 以上・ボックス超過**）は理由付きでタイトルに案内（移行はしない）。書き込みは一時ファイル→原子的置換（041 の `FileSaveStore`）|
| 記録 | クリア時に `records.txt`（最短クリア時間・最多の捕獲種類数・クリア回数）を同じ方式で保存し、結果画面とタイトルに表示 |
| 操作 | 矢印/WASD 移動、Z/Enter/Space 決定、X/Esc 取消・メニュー（手持ち・図鑑・道具・セーブは回復所のみ）、長押しで連続移動（012 の `MoveRepeater`）。フォーカス喪失で保留入力を消す |

## セッション1：データと戦闘（Core）

- 定義：`SpeciesDef`・`MoveDef`（効果列 `EffectDef`）・`TypeChart`・`StatusDef`・`LearnsetDef`、`MonsterData`（検証済みの不変の束、ID → 番号の索引、指紋）、`MonsterDataValidator`（`DataError` 理由付き）
- 個体：`Monster`（能力の算出・HP・PP・技 4 枠・状態異常と解除予定ターン・経験値）、`ExpTable`、`Growth`（経験値の分配・レベルアップ・技を覚える候補）
- 戦闘：`Battle`（フェーズ・場の 2 体・ターン番号・終了理由、`Submit(BattleCommand) → Result/Rejected`、`Clone`・`Hash`）、`Battle.Resolve`（行動順・技の効果列・命中・ダメージ・状態異常・ターン終わり処理）、`Capture`（捕獲値）、`BattleEvent`（演出用の記録、状態を変えない）、`TrainerAi`
- 公開は読み取り専用の窓口 `BattleView`（042・043：可変の部品を公開しない）

### テスト（セッション1）

- **相性倍率**：属性 3×3 の全組で倍率表どおり、一致補正との掛け順、切り捨て、最低 1。相性表のデータを差し替えると結果が変わる（データ駆動の確認）
- **命中判定**：乱数の値を固定した系列（`FromState`）で `A−1`→命中・`A`→外れの境界、命中 100 でも乱数を 1 回消費、外れたら状態異常の付与も起きない
- **状態異常の解除が予定ターン**：眠り 1・2・3 ターンそれぞれで、解除予定ターンの開始で解除→そのターンに行動。毒 4 ターンのダメージ回数。交代しても予定ターンは保持、戦闘をまたぐ扱い（戦闘終了で解除するか持ち越すかを決めてテスト）、重ね掛けの失敗
- フェーズ：各フェーズで受け付けないコマンドの拒否と状態不変（ハッシュ・乱数・出来事数）、強制交代はターンを消費しない、元気な個体がいなければ敗北、終了後の全拒否
- 交代・行動順（優先度・素早さ・同値の抽選）、捕獲（トレーナー戦の拒否、HP・状態補正の境界、確定）、逃走、PP 0 の技の拒否、経験値の等分と複数段のレベルアップ
- データ検証の負例（重複 ID・未定義の属性/状態・命中 0 や 101・効果列の矛盾・種族 6 でない・相性表の欠け）
- 同じシードとコマンド列の戦闘ハッシュが .NET と Mono で一致

### テスト（セッション2）

- **手持ち上限を超えない**：手持ち 6 で捕獲→ボックスへ、ボックス 30 も満杯で捕獲玉が拒否され玉も減らない、預ける/引き出す/入れ替えの境界（手持ち 0 にできない・7 にできない）、乱択の長い通し（多シード × ランダムな合法操作）で**全局面の上限の不変条件**、セーブの読み込みでも上限違反を拒否
- セーブ再ロードで `World.Hash` 一致、読み込み後に同じ入力列で以後の最終ハッシュも一致（022）、全切り位置・1 文字改変・版違い・指紋違いの拒否（041）。記録ファイルの更新（より良い値だけ置き換え）

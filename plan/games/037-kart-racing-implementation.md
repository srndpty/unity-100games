# 037 カートレース 実装計画

## Context

- 037 カートレース（難易度4・Phase 2）が未着手だった。仕様書 [plan/games/037-kart-racing.md](./037-kart-racing.md) の中心課題は「**車両制御とレース進行の分離**」、重点は「**CPUはウェイポイント＋速度計画**」。In scope：1 周回・CPU 3 台・加速/旋回/ドリフト・順位と 3 周・タイトルから再プレイまで。Out of scope：多数アイテム・オンライン・追加コース。
- 題材固有テスト：逆走で周回を稼げない／チェックポイント飛ばし不可／全車の順位が確定。完了判定：3 周を走破、CPU が大きな障害で立ち往生しない。
- ユーザーと決めたこと：
  - **2D 真上から**（2D 雛形）。カメラは自機に追従し、進行方向が画面の上になる。
  - **物理は Core の整数モデル**。Unity の車両物理は使わない。.NET と Mono で最終ハッシュを一致させる。
  - **車同士はすり抜ける。** 押し合いは作らない。順位はコース上の進みだけで決まる。
  - 乱数は使わない。試合は初期配置・設定・入力列だけで再現する。再戦は同じコースを初期状態からやり直す。

作品名はオリジナル（仮）：**THISTLE CIRCUIT**。参考作品の名称・素材・演出は使わない。
ルールの詳細は作品の README「採用ルール」を正とする。この計画のルール表は着手時の固定で、実装で変えた点は各セッションの結果に書く。

## ルール表（要点）

| 項目 | 採用ルール |
|---|---|
| 時間 | 60 Tick/秒。入力はイベント時刻を含む Tick に反映する（022） |
| 座標 | 1 単位 = 1 mm。向きは `Trig`（1 周 = 65536）。浮動小数点は使わない |
| 車 | 円。位置・向き・速さ・ドリフトの溜め・ブースト残り・周回の印・回復の残り Tick |
| 加速 | 加速中は `Accel` ずつ上限へ。ブースト中の上限は `BoostSpeed`。離すと `Drag` で 0 へ。ブレーキは `-ReverseSpeed` まで |
| 旋回 | `steer * Turn(speed)`。低速で大きく高速で小さい。速さ 0 では向きも位置も変えない。後退中は符号を反転 |
| ドリフト | 加速中・\|steer\| = 1・速さ ≥ `DriftMinSpeed` で開始。旋回を足し、速さを減らし、移動方向を向きから `SlipAngle` 遅らせる。離したとき溜めが `MiniTurboTicks` 以上なら `BoostTicks` のブースト。1 Tick 不足・加速を離す・壁に当たった Tick は溜めを消してブーストを出さない |
| 壁 | 左右の折れ線。食い込んだら内側へ押し出し、法線方向の移動を捨てて接線へ滑る。1 Tick に 2 回まで。ちょうど接するだけでは触れない |
| 車同士 | 重なっても速度も位置も変えない |
| 周回 | 次のゲートを前向きに横切ったときだけ印が進む。0 番（スタート）を前向きに横切ると周回 +1。3 周目で完走し、その Tick を記録して止める。逆走・飛ばしでは増えない |
| 順位 | 完走は記録 Tick の早い順。未完走は周回数・通過ゲート・区間の進み・車の番号。常に 1〜4 の置換 |
| 終了 | 4 台完走か `MaxRaceTicks`。1 位が勝利。結果後の操作は状態を変えない |
| CPU | 中心線の先の点へ向き、曲率で目標速度を決める。曲率が大きければドリフトし、出口で離してブースト。進みが `StuckTicks` 増えなければ後退して回復する。3 台は上限速度を少しずつ遅くする |
| 操作 | ←→ または A/D 旋回、W または ↑ 加速、S または ↓ ブレーキ、Space ドリフト、Esc 一時停止。フォーカス喪失で一時停止し、ドリフトはブーストにせず消す |

## コースデータ

`Assets/Game/Data/Track.txt`。`station x y halfWidth` の閉じた列と `checkpoint <点の番号>`。直線・ヘアピン・緩いカーブ・シケイン。壁とゲートは `Track.Build` の純粋関数。描画・Prefab 照合・当たりは同じ点列。

## Core / App

- `RaceFlow`（Title / Playing / Paused / Result、時刻付き入力、フレームの Tick 上限）・`Autopilot`（プレイヤー枠を `CpuPlan` で走らせる）

## テスト

- 逆走で周回 0、順走で 1 周、接するだけの横断は進まない
- 次以外のゲートを横切っても印が進まない。壁で止まった移動は通過にしない
- 順位が完走 Tick・周回・区間・同着・時間切れのどれでも 1〜4 の置換。結果後に変わらない
- 加速・速さ 0 の旋回・後退の符号・ドリフトの境界 Tick・壁での溜め消し
- 壁に正面から止まって滑る、最大の速さで薄い壁をすり抜けない（細分した参照と照合）
- 実コースで CPU 3 台が 3 周を時間内に完走。壁に付けた状態から回復して次のゲートへ
- 操縦役は 1 位で完走、入力なしは最下位。同じ入力列の最終ハッシュが .NET と Mono で一致
- タイトル → スタート待ち → 結果 → 再戦、終了後の操作拒否、30〜240fps のハッシュ一致、フォーカス喪失でブーストにしない

## セッション1の結果（2026-11-25）

- ルール表を `games/037-kart-racing/README.md` に固定した。Core（`Vehicle`・`WallContact`・`Progress`・`Standings`・`CpuPlan`・`Race`）と App（`RaceFlow`・`Autopilot`）をテストから作った。
- コースはスタジアム型の閉じた中心線（102 点、半幅 5 m、全長約 416 m）。チェックポイントは点 0・33・52・71。壁の線分は 8 m 以内。
- 立ち往生の判定は、ゲート手前のグリッドで区間の進みが 0 のままになるため、中心線方向の符号つきの進み（`Track.AdvanceOf`）で見る。
- CPU の速度割合は、コーナー速度より上の分だけを縮める。コーナーは 4 台とも同じ速さで、直線だけプレイヤーが速い。
- ミニターボの溜めは 8 Tick。25 Tick の強制ドリフトはヘアピンでコースを外してレースが終わらなかった。最高速度は 340 mm/Tick（380 では高速の旋回が半径 14 m のヘアピンを曲がりきれない）。
- 同じ入力列 400 Tick のハッシュは `1723866012`。ブースト残り・溜め・回復・次のゲートを変えるとハッシュが変わる。
- 次（セッション2）：コース描画、Stage Prefab、追従カメラ、HUD、音、シーン生成、撮影台本。

## セッション2の結果（2026-11-25）

- `ThistleSceneBuilder` が中心線から路面・点・4 台の車を置いた Stage Prefab とシーンを作る。既存の Prefab は上書きせず、点を動かすと `Mismatch` が不一致にする。
- カメラは自機の 3 m 前方を見て、進行方向が画面の上になる。HUD は PanelRenderer。音は速さで高さが変わるエンジンと、ドリフト・ブースト・周回・結果の短い音。
- 撮影台本は操縦役を Tick で進め、タイトル、グリッド、直線、順位の変化、ドリフト、ブースト、1 周、結果を撮る。
- Windows ビルド（StandaloneWindows64）と撮影が通った。

## セッション3の結果（2026-11-25）

- PlayMode 24/24。描画の位置と向きが Core と一致する。操縦役は 3 周を 1 位で終えて再戦で Tick 0 に戻る。タイトルへ戻すと起動直後の配置になる。フォーカス喪失でドリフトはブーストにならない。点を 1 つ動かすと照合が不一致になる。
- 実コース 300 Tick の Core の Step は p95 0.058 ms、車とカメラの更新は p95 0.003 ms、割り当て 0 バイト（4096 バイトの確認は 4458 バイト）。
- 同じビルド（Build GUID `84fae615640a4c898f6ee334202ea6c4`）を 2 回撮影し、画像世代 `e14ed32e37e7da65` の 8 枚の SHA-256 が一致した。
- 状態は「検証待ち」。完了にはしない。試遊は `dev run 037`。

# 031. リズムゲーム

> Unityゲーム制作100本ノック v1.1 / Phase 2：操作・アクション・スポーツ  
> 参考作品：Taiko no Tatsujin（ゲームメカニクスの参考。素材・名称・演出の複製は不要）  
> 実装難易度：★★★☆☆  
> 状態：完了

## 1. 学習目的

**この題材の中心課題**：DSP時刻を正としたノーツ判定。

学習上の重点：入力遅延の補正。

## 2. 最小完成スコープ（In scope）

- 3曲分の譜面、2打種
- タイミング判定とコンボ
- 音ずれ補正設定
- タイトル/開始、基本操作説明、勝利・敗北または結果、再プレイまでを一巡できる。

## 3. 今回は実装しない（Out of scope）

- オンラインランキング
- 曲ライセンス機能
- アセットの大量制作、追加ステージ量産、課金・実績・外部ランキングなど学習目標と無関係な製品化要素。

## 4. 内部設計・コンポーネント境界

- DSP時刻を正としたノーツ判定
- 入力遅延の補正
- **Core**：状態、ルール、検証、乱数の受け口。可能な範囲でUnity APIに依存しないC#コードとする。
- **Presentation**：MonoBehaviour/UI ToolkitまたはuGUI/描画/効果音・演出。Coreの結果を反映する。
- **Orchestration**：入力を意図に変換しCoreへ渡す。状態遷移と再開・リセットを統括する。
- パラメータ（速度、制限時間、スコア、敵挙動など）は設定アセットまたはデータへ分離する。ただし単純な作品で過剰な抽象化をしない。

## 5. テスト仕様

### 題材固有のテスト（優先）

- [x] 判定窓境界で結果が確定的
- [x] 二重入力で同一ノーツを二度取れない
- [x] 一時停止・再開で譜面がずれない

### 共通の必須テスト

- [x] **Core**：主要な合法/非合法操作と境界値を確認する。再現可能な入力は自動テスト化する。
- [x] **状態遷移**：開始→進行→終了→再戦の順序を守り、終了後の不正操作を無視または拒否する。
- [x] **再現性**：乱数利用箇所ではシード固定。物理/ネットワーク系は許容誤差・計測条件を明記する。
- [x] **負テスト**：不正入力、値域外、途中終了、重複イベントを最低1ケースずつ確認する。
- [x] **ビルド**：エディターの再生だけでなく、選択した対象プラットフォーム向けに一度ビルドして起動確認する。

## 6. 完了判定（Acceptance criteria）

- [x] 曲末まで安定して採点。
- [x] 設定したオフセットを再現。
- [x] **Core**：主要メカニクスが動作し、設計境界が説明できる。
- [x] **Playable**：チュートリアルなしでも最低限の操作案内があり、プレイを完走できる。
- [x] **Verified**：題材固有テスト＋共通テストが通過し、未解決の問題を記録した。

## 7. 成果物・記録

- 実行可能なUnityプロジェクト（原則、1題材＝1プロジェクト）。
- README：起動手順・操作・採用ルール・設計上の選択・未実装範囲。
- `Tests/`：CoreのEditModeテスト、必要ならPlayModeテスト。
- `evidence/`：動作スクリーンショットまたは短い動画、ビルド結果、主要テスト結果。
- `retrospective.md`：新たに学んだ点／想定との差／次回の改善点を各3行以内。

- 性能目標・物理許容誤差・ネットワーク条件が必要な題材では、測定環境と成功基準を先に決める。

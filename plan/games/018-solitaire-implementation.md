# 018 ソリティア 実装計画

## Context

100本ノックの18本目。仕様書 [plan/games/018-solitaire.md](018-solitaire.md) の中心課題は「カード状態とドラッグUIの分離」と「移動規則を検証するCommand」。Klondike のメカニクスだけを採用し、名称・絵・配色・音は独自のオリジナル作品にする（001〜017と同様。仮題：作品名は Core 着手時に決めて README に書く）。

ユーザーと決めたこと：
- めくり枚数：既定1枚、設定アセットで3枚も選べる（ルールとテストは両方）
- 結果：「あきらめる」＋「自明な手詰まり」の自動判定で結果画面へ
- 操作：マウス（ドラッグ＆ドロップ、クリック→クリック、ダブルクリックで組札へ）。キーボードは Undo・一時停止・画面遷移だけ

雛形・層構成・検証手順は 015 / 017 と同じ（`dev new 018` → slnx 登録を最小コミット）。

## ルール表（README の「採用ルール」に載せる）

| 項目 | 採用ルール |
|---|---|
| 札 | 52枚（4スート×A〜K）。赤＝ハート・ダイヤ、黒＝クラブ・スペード（試遊を受けて独自の記号から変更） |
| 配札 | 試合のシードでシャッフル。場札7列に1〜7枚、各列の一番上だけ表。残り24枚が山札（全部伏せ） |
| 山札 | クリックで1枚（設定で3枚）を捨て札へ表でめくる。山札が空ならクリックで捨て札を全部伏せて戻す（回数無制限） |
| 捨て札 | 一番上の1枚だけ動かせる（3枚めくりでも同じ） |
| 組札 | 4つ。空ならAだけ、以後は同じスートで1つ上のランク。1枚ずつ置く |
| 場札 | 表の札は、色違いで1つ上のランクの上へ置ける。空列にはKだけ。表の連続部分（列の途中から上全部）をまとめて動かせる。伏せ札は動かせない |
| 組札から場札 | 一番上の1枚を戻せる（場札の規則に従う） |
| 自動で開く | 移動の後、列の一番上が伏せ札なら同じコマンドの中で表にする |
| Undo | 回数無制限。めくり・戻し・移動・自動で開いた札をまとめて1手として元に戻す。手数も戻る。結果画面では使えない |
| 手数 | 成立したコマンドで+1、Undoで-1。時間は実時間で積算（017の方式、`unscaledDeltaTime`） |
| 勝利 | 52枚がすべて組札に入ったら勝利 |
| 手詰まり | 下記の探索で「組札が増える・伏せ札が開く状態へ到達できない」と確定したら自動で結果（手詰まり） |
| あきらめる | 一時停止メニューから。結果画面（組札の枚数・手数・時間）へ |
| 自動で仕上げる | 試遊の要望で追加。山札・捨て札が空で伏せ札がなくなるとボタンを出し、残りを1枚ずつ組札へ送る（必ず勝てる状態だけ） |
| 再戦 | 試合ごとに新しいシード（010の方式：起動時の値から試合ごとに進める） |

### 手詰まりの判定（Core `DeadlockDetector`）
- まず直接の前進手（組札へ置ける札、山札・捨て札のめくり範囲から場札へ置ける札、伏せ札を開く移動）があれば即「手詰まりでない」。
- なければ、現在の状態から全ての合法コマンド（めくり・戻しを含む）で幅優先探索し、「組札の枚数が増える」か「伏せ札が開く」状態に着いたら「手詰まりでない」。状態の重複は状態キーで除く。
- 探索が上限ノード数（設定、既定 例：20,000）を超えたら「手詰まりでない」とみなす（偽陽性を出さない側に倒す）。上限内で尽きたときだけ手詰まり＝その盤はもう勝てないことが確定。
- テスト：手詰まりと判定した局面を、上限なしの全探索で勝てないことを照合（自動プレイの多数シード）。Monoで判定時間のp95を計測しREADMEに記録。

## 設計

### Core（`Assets/Game/Core/`、Unity非依存）
- `Card`（readonly struct：Suit, Rank, 色）、`SuitColor`
- `PileId`（Stock / Waste / Foundation0-3 / Tableau0-6）
- `Pile`（札と表裏の並び）、`Table`（全13山。不変条件の検査 `ValidateInvariants`：52枚が重複なく、ちょうど1つの山に属する、伏せ札は場札の下側と山札だけ）
- `Deal`（シード付きシャッフル＋配札）。`SeededRandom`（xorshift、雛形・既存作品の流用）
- Command：`ICommand` を持たず、意図の値 `Move(from, to, count)` / `Draw` / `Recycle` を `MoveRules.Check(table, cmd)` が理由付き（`MoveError`：伏せ札、色が同じ、ランク違い、空列にK以外、組札に複数枚、同じ山、山札が空 など）で検証 → `Execute` が適用して `MoveRecord`（動いた札、自動で開いたか、めくった枚数）を返す。Undo は `MoveRecord` の逆適用（スナップショットではなく差分。テストでスナップショットと一致を照合）
- `MoveRules.LegalMoves(table)`：合法手の列挙（ダブルクリック、手詰まり判定、自動プレイが共用）
- `DeadlockDetector`（上記）
- `SolitaireGame`：フェーズ（Playing / Won / Stuck / Resigned）、手数、Undo の履歴、終了後のコマンドを拒否
- `SolitaireConfig`：めくり枚数（1 or 3。それ以外は検証で例外）、手詰まり探索の上限ノード数

### App（`Assets/Game/App/`）
- `SolitaireFlow`：タイトル→プレイ→一時停止→結果→再戦の遷移、経過時間（017同様）、フォーカス喪失時の保留入力の破棄
- `CardDragInput`：ポインタの押下・移動・離しを「掴んだ山と枚数」「ドロップ先の山」の意図に変える。ドラッグとクリックの閾値、クリック→クリック、ダブルクリック（実時間の間隔）を扱う。ルールは知らず、掴める位置かどうかだけ Core に聞く。ドロップ先は「重なった山のうち掴んだ札の中心に最も近い山」。不正なドロップは元へ戻す（Core 不変）
- `Autopilot`：合法手から乱数で選ぶ（テスト・撮影で共用）
- `DemoTables`：撮影・テスト用の決まった局面（勝利直前、手詰まり、3枚めくり など）

### Unity（`Assets/Game/Unity/`）
- `XxxGame`（入力・HUD・音）、`XxxTableView`（札のSpriteRenderer配置、ドラッグ中の札の追従、戻りの演出は実時間・撮影中は無効）、`XxxSettings`（ScriptableObject：めくり枚数、ダブルクリック間隔、演出時間、音量）
- 描画は Core の `Table` を読むだけ。ドラッグ中の見た目（持ち上げた札）は View が持ち、Core は確定まで変わらない＝「カード状態とドラッグUIの分離」
- 札の絵は `Editor/XxxArtGenerator` で生成（017 と同じくフォントを使わず線と円弧でランクを描く）。Prefab / シーンは `Editor/XxxSceneBuilder` で生成
- HUD：PanelRenderer（手数・時間・Undo・一時停止・操作説明・結果画面）
- 撮影台本 `XxxCaptureScenario`（タイトル、配札直後、ドラッグ中、移動と自動で開く、Undo後、3枚めくり、手詰まり結果、勝利結果 など8〜10枚）

## テスト（主なもの）

- Core：色・ランク・表裏による移動の可否（全エラー理由）、空列にK、組札A始まり、連続部分の移動、伏せ札の自動公開とUndoでの伏せ戻し、めくり1/3枚と戻し、Undoの連続で配札直後と一致、全コマンド後に不変条件（二重所属なし）を自動プレイ多数シードで検査、勝利判定、終了後のコマンド拒否、同シードで配札一致（固定ハッシュをMono/.NET両方で照合）、手詰まり判定の偽陽性なし
- App：遷移の順序、終了後の入力無視、ドラッグ/クリック/ダブルクリックの意図化、不正ドロップで不変、フォーカス復帰直後のクリックを捨てる、Undoの連打
- PlayMode：実マウス入力（015の `Mouse` 仮想デバイス方式）でドラッグ移動・不正ドロップで戻る・ダブルクリックで組札・山札クリック・Undoボタン（ポインタイベント）・勝利/手詰まりの結果画面（`DemoTables` で状態を直接作る）

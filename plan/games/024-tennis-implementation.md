## セッション1：ルール表（README に固定）と Core / App

### ルール表（要点）

| 項目 | 採用ルール |
|---|---|
| 単位 | 長さは整数（1 単位 = 0.1 mm、`Units.PerMeter = 10000`）、60 Tick/秒、時間の設定は Tick 数。浮動小数点を使わず Mono と .NET で一致させる |
| 座標 | x：横（センターが 0）、y：縦（ネットが 0、自分は y<0 の手前）、z：高さ。シングルスのコート 23.77×8.23 m、ネットの高さ 0.914 m（一定）。コートチェンジはしない（自分は常に手前。ゲーム性に影響なし） |
| 球 | 1 Tick：重力（vz -= g）→ 位置 += 速さ。z が 0 を下回った Tick は、その中で地面に触れた割合で位置を求めてバウンド（vz 反転・反発係数と摩擦は分数で）。**空気抵抗・回転なし**（Out of scope） |
| ネット | y の符号が変わった Tick に、ネットの面を通る割合で高さを求め、ネット＋球の半径より低ければネット。ネットに触れた球はその時点で死に球（打った側の失点、サーブならフォルト）。レットは採用しない |
| ラリーの失点 | ネット → 打った側。相手コートの外に最初のバウンド → 打った側。相手コートで 2 回目のバウンド、または 1 回バウンドした後に後方・側方の壁の線を越える → 受けた側。サーブのリターンを直接打つ（ノーバウンド）→ 受けた側。ラリー中のボレーは可 |
| サーブ | 打つ人はポイント数の和が偶数ならデュースサイド、奇数ならアドサイドのベースライン後方。Z で上げ、もう一度 Z で打つ。打点の高さのウィンドウ（頂点付近）で打てば狙いどおり、外れるほど速さ・高さがずれてフォルトしやすい。上げた球を打たずに落とすとやり直し（フォルトにしない）。対角のサービスボックスの外・ネット → フォルト、2 回でダブルフォルト |
| 打点ウィンドウ | 振り（`SwingTicks`）の間に、球が自機の打点の範囲（水平距離 ≤ `Reach`、高さ `MinHitZ`〜`MaxHitZ`、自分の側へ向かう、自分の側でのバウンドが 0〜1 回）に入った最初の Tick に打つ。範囲外の球は振っても当たらない（空振りの後 `RecoverTicks` は振れない） |
| 早打ち・遅打ち | 打点が理想の位置（体の前）よりネット寄り＝早打ち、後ろ＝遅打ち。ずれ e（-1〜1）で横の角度が変わる（早いほど引っ張り＝クロス、遅いほど逆＝ストレート）。←→ を押していれば狙いを足す。ウィンドウの端ほど深さも乱れアウトしうる |
| ショット | ストローク（Z）：速い・低い弾道。ロブ（X）：遅い・高い弾道。狙った着地点と飛行 Tick 数から初速を整数で解く（離散の積分で着地点が正確に一致する式） |
| 移動 | 自分の側の範囲（ネットの手前まで）を 8 方向に速さ一定。振っている間は遅くなる |
| 得点 FSM | 通常のゲーム：0/15/30/40/デュース/アドバンテージ。セット：`TiebreakAtGames`=T のとき、T ゲームを 2 差で取るか T+1 対 T-1 で勝ち、T 対 T でタイブレーク（`TiebreakPoints` 点・2 差）。**既定 T=0**＝最初からタイブレーク＝「7 ポイント先取の 1 ゲーム」。T=6 で通常の 1 セット |
| サーブ順 | 通常ゲーム：ゲームごとに交代。タイブレーク：最初の 1 点を A、以後 2 点ごとに交代（B,B,A,A…）。サイドはそのゲーム内のポイント数の和の偶奇 |
| 乱数 | 1 試合 = 1 シードの xorshift。CPU の判断・CPU のサーブで系列を分ける（015 の知見） |
| 終了後 | 試合終了後の Tick と入力は状態を変えない |

### Core（`Assets/Game/Core/`、`com.games100.tile-motion` の `Countdown`・`StateHash` を参照）
- `Vec3i`・`Units`、`Court`（寸法・コートの内外・サービスボックス・ネット）
- `Ball`：`Step()` が 1 Tick の軌跡を進め、`BallEvent`（バウンド位置・ネット・壁の線）を返す。`Clone()`
- `BallPredictor`：`Ball.Clone()` を同じ `Step` で進め、次のバウンド地点・打点の高さに入る Tick と位置を返す（**予測と実際が同じ関数**）
- `ShotSolver`：狙いの着地点と飛行 Tick → 初速。ショットの種類（ストローク・ロブ・サーブ）
- `HitWindow`：打点の範囲判定と早打ち・遅打ちのずれ e。理想の打点
- `Athlete`：位置・振り・空振りの回復（`Countdown`）
- `Rally`：1 ポイントの FSM（Toss → InPlay(最後に打った人・バウンド数・リターン前か) → Dead(理由)）。`PointResult`（勝者と理由：Net / Out / DoubleBounce / Fault / DoubleFault / ReturnVolley）
- `MatchScore`：得点・ゲーム・タイブレーク・サーバー・サイドの FSM（ラリーと独立。結果を入れると次の状態）
- `CpuBrain`：予測から移動先を決め、反応の遅れ・速さ・狙いのぶれ（乱数）・ショットの選択（相手がネット寄りならロブ）。コマンド（移動方向・振る・種類）を返す
- `TennisMatch`：試合全体（両者・球・ラリー・スコア・乱数・ポイント間の待ち）。`Step(PlayerCommand)`・`Hash()`・`Clone()`
- `TennisConfig`：公開フィールド＋検証（有限・範囲・`TiebreakAtGames` 0〜6）。**ウィンドウ中央で打った球が入ることを実際に `Ball` を飛ばして確かめる**、1 Tick の球の移動量が打点範囲の奥行きより小さい（打点を飛び越えない）ことも検証で保証

### App（`Assets/Game/App/`）
- `TennisFlow`：Title / Playing / Paused / Result、時刻付き入力をその Tick に反映・フレーム単位の Tick 上限（022 の `PrecisionFlow` を移植。打点ウィンドウはフレームレートに依らない必要がある）
- `Intent`・`HeldControls`：↑↓←→、Z（ストローク・サーブ）、X（ロブ）。押し始めだけ振る
- `Autopilot`：`CpuBrain` を自分の側で使い Intent に変換（撮影・テスト用）。試合ごとに判断状態を捨てる（023 の知見）

### テスト（題材固有を優先）
- **ネット/アウト/ツーバウンドで正しく失点**：各理由を球の状態を直接作って再現し勝者を確認。サーブのフォルト・ダブルフォルト・リターンのノーバウンド・ネット際の境界（ネットの高さちょうど±1）、ライン上（内）・1 単位外
- **得点後サーブ権が更新**：通常ゲームの交代、タイブレークの A,B,B,A,A…、サイドの偶奇、デュース・アドの往復、`TiebreakAtGames` 0/4/6 で 6-4・7-5・7-6 の決着
- **届かない球を打てない**：距離 Reach+1・高すぎ・低すぎ・相手の側・2 バウンド後・振っていない・回復中を拒否、境界ちょうどは打てる
- **早打ちと遅打ちで球筋が変化**：同じ入球を異なる Tick で打ち、着地 x の符号が分かれる・e=0 で狙いどおり
- **着地点予測**：`BallPredictor` の予測と実際のバウンド位置・Tick が完全一致（ショット種類×乱択）
- 共通：状態遷移（開始→進行→終了→再戦・終了後の入力無視）、負テスト（未定義の操作・NaN/範囲外の設定・終了後の Step・同 Tick の二重の振り）、再現性（同シード同入力で同ハッシュ）、**完走**（Autopilot 対 CPU で 50 シードが上限 Tick 内に決着し、スコアが規則どおり。固定シードの最終ハッシュを .NET と Mono で照合）

## セッション1の結果と計画との差（2026-11-22）

- ルール表は [README](../../games/024-tennis/README.md) の「採用ルール」を正とする。
- 打点は「振りの間に球が範囲に入った最初の Tick」ではなく「押してから `ImpactTicks` Tick 目」にした。最初の Tick に当てると早く押すほど常に早打ちになり、時機の意味が薄れるため。空振りの後の回復は振りの長さ（`SwingTicks`）で兼ねる。

- CPU の時機のぶれは ±1 Tick だとラリーが平均 129 本続いて終わらなかったので ±2 Tick（平均 5 本）にした。
- `TennisMatch.StageRally`（打ち合いの場面を作る）をテスト・撮影用に足した。

## 試遊を受けた調整（2026-11-22）

- 指摘：難しすぎる。サーブがフォルトになりやすい。体の正面の球を拾えない。手本はマリオテニス。
- 早押しの待ち（`SwingHoldTicks` 20）：打点の Tick に球が向かってくる途中なら打点で待ち、理想の打点に来たら打つ。打点の Tick に届く範囲にあればその場で打つ（早打ち・遅打ちは残る）。
- 届く範囲 1.3 → 1.8 m、打てる高さ 2.2 → 2.6 m、早打ちの横のずれ 4 → 3 m。
- プレイヤーのずれ（サーブを含む）を `PlayerTimingAssistPercent` 50% に弱める。CPU は 100%。案内のしきい値も半分。
- サーブの幅 ±12 → ±20 Tick。頂点の 16 Tick 前から 12 Tick 後まで入る。
- CPU のぶれ ±2 → ±4 Tick（早すぎる押下は待つのでミスが減るため）。ラリー平均 16.5 本、1 試合約 3 分。最終ハッシュ `0x52DDAB1C`。
- 設定アセットは生成スクリプトが上書きしないので、新しい既定値をアセットにも書いた。

## 2 回目の試遊を受けた調整（2026-11-22）

- 指摘：まだ難しすぎる。体の周りにボールがあれば全部返せるように（ネット・アウトはありうる）。CPU のショットが速いのでは。サーブ時に左右に動いて場所を選べるように。
- 打ち方：押すと構える。押した Tick に球が届く範囲にあればその場で打ち（早打ち・遅打ち）、まだ向かってくる途中なら最大 90 Tick 待って理想の打点で打つ。8 Tick 後の打点（`ImpactTicks`）と打点での待ち（`SwingHoldTicks`）はやめた。構えている間はふつうに動ける。
- 球の速さ：遅打ちでネットの余裕を減らすと弾道が平らで速くなり、補助のない CPU の球が速かった（実測 CPU 25.4 m/s・プレイヤー側 23.9 m/s）。飛ぶ時間をずれ 0 の弾道で決め、ずれは着地点だけを変える（遅打ちは `ShortError` 8 m 短く、サーブは 5 m）。どちらも約 22 m/s になった。
- サーブ：トスを上げるまで ← → でベースラインに沿って立ち位置を選べる（`ServeSideMin` 0.3 m からサイドラインまで）。
- CPU のぶれ ±4 → ±5 Tick（ラリー平均 15 本、1 試合約 3 分）。最終ハッシュ `0x346EBABB`。

## ルール表（セッション 1 で README に固定する案）

### 1 日の流れ

| 段 | 内容 |
|---|---|
| 朝 | 日の始めに自動セーブ。日付・曜日・天気（シードから）を出す |
| 行動 | 7 つから 1 つ選ぶ：勉強・運動・創作・バイト・休む・天文部へ（先輩）・図書室へ（同級生）。曜日で選べない行動がある（日曜は図書室が閉まる、など。データで宣言） |
| 結果 | 行動の効果（能力値・疲労・お金・好感度）を当てる。結果の段階（大成功・成功・失敗）を、疲労に応じた重みでその日の乱数系列から引く |
| イベント | 枠ごとに、その日のイベントを**高々 1 本**選ぶ。枠は「行動の後」と「夜」の 2 つ。数行の会話と、あれば 2〜3 択（好感度・フラグが動く） |
| 30 日目の後 | ED の判定（優先順位の高い順に条件を見て、最初に成り立つもの。最後は条件なしの既定の ED） |

### 能力値（データで範囲と初期値を宣言）

- 学力・体力・感性：0〜100。
- 疲労：0〜100（80 以上で失敗の重みが上がる。100 で翌日は強制的に休む）。
- お金：0〜9999。
- 好感度：攻略対象ごとに 0〜100。画面には段階（ハート 0〜5）で出す。
- フラグ：bool（「夏祭りに先輩と行った」など）。
- 効果を当てるたびに宣言した範囲で飽和させる。**範囲外に出ないこと**は、実行時の飽和と、コンパイル時の区間の検証（下記）の両方で保証する。

### イベントの選び方（優先順位と乱数の固定）

- 各イベントは **枠**（行動の後／夜）・**期間**（日の範囲・曜日）・**優先度**・**確率**（%）・**1 回だけか**・**条件式**を持つ。
- その日・その枠で、条件の成り立つ候補を**優先度の高い順、同じなら定義の順**に並べる。先頭から順に確率を引き、最初に当たった 1 本を出す。
  - 確率 100 の日付固定イベント（夏祭り・流星群）は優先度を最高にする。
- 乱数は**用途ごとに別の系列**にする：試合のシード・日・用途（行動の結果／イベントの確率／天気）から `RandomSeries.Derive` で派生する。
  - ある用途で引く回数が変わっても、ほかの用途の結果は変わらない（015 の知見）。
  - **同じシードと同じ行動の列なら、同じイベントの列**になる（完了判定）。
- **同日排他**：1 つの枠に出るのは高々 1 本。さらに `@exclusive a b` で宣言した組は、枠が違っても同じ日には出さない（先に選ばれた方が勝つ）。

### 条件式

- 比較（`学力 >= 40`・`先輩 >= 60`・`day >= 10`・`weekday == sat`・`action == club`・`money >= 500`）と、`and`・`or`・`not`・括弧。フラグは単独で真偽。
- 型の検証（int と bool を混ぜない・未定義の名前を拒否）は行番号付き。

### エンディング（3 つ）

| ED | 条件（案。セッション 2 で数値を決める） |
|---|---|
| 先輩 ED | 先輩の好感度 ≥ 70、感性 ≥ 50、「夏祭りに先輩と行った」 |
| 同級生 ED | 同級生の好感度 ≥ 70、学力 ≥ 50、「読書会に参加した」 |
| 天文部の夏 ED（既定） | 条件なし（上の 2 つに当てはまらない） |

- 両方の条件が成り立つときは、優先度の高い方。優先度は宣言の必須項目にし、同じ値を拒否する。

## DSL（セッション 1 で README に固定する文法の案）

1 行 1 文。`#` 以降はコメント。

| 文 | 例 | 意味 |
|---|---|---|
| 能力値 | `@stat study 学力 0..100 = 10` | ID・表示名・範囲・初期値 |
| 好感度 | `@heart sumi 澄 0..100 = 0` | 攻略対象の好感度 |
| フラグ | `@flag festival_sumi` | 初期値は偽 |
| 人物 | `@char sumi 星野 澄 #9fc8ff` | 話者 |
| 行動 | `@action study 勉強 days mon..sat : study += 3..5 ; fatigue += 8` | 効果の幅（乱数で引く）・選べる曜日 |
| 結果の段階 | `@outcome great x150 weight 20 when fatigue < 50` | 効果の倍率と重み（条件で重みが変わる） |
| イベント | `@event e_club_first slot after day 1..10 priority 60 chance 100 once when action == club` | 枠・期間・優先度・確率・1 回だけ・条件 |
| 本文 | `sumi「今夜、屋上で月を見ない？」` | 台詞・地の文（046 と同じ） |
| 選択肢 | `- 行きます : sumi += 5 ; set rooftop_sumi` | 選んだら効果を当てる（2〜3 行） |
| 排他 | `@exclusive e_festival_sumi e_festival_shiori` | 同じ日に出さない組 |
| ED | `@ending sumi 先輩ED priority 30 when sumi >= 70 and art >= 50 and festival_sumi` | 優先度・条件（既定の ED は `default`） |

- コンパイル結果は、能力値の表・行動の表・イベントの表（条件式は式の木）・ED の表と、**データの指紋**。
- 実行器（`Summer`：試合の状態）は構文解析の型を参照しない。リフレクションで確かめる（046）。

## 検証（コンパイル時。誤りは行番号と理由付き）

- **構文**：未知の文・括弧の不一致・選択肢の数・範囲の書式。
- **名前と型**：未定義の能力値・人物・フラグ・行動・イベント、int と bool の混在、重複した ID。
- **範囲**：初期値が範囲外、効果の幅が逆向き、確率が 0〜100 の外、日が 1〜30 の外、ED の優先度の重複、既定の ED がちょうど 1 つ。
- **区間の検証**（条件式のデータ表現の要）：
  - 各能力値の「d 日目に取りうる範囲」を、初期値と行動・イベントの効果の最大・最小から上界と下界で求める。
  - それを使い、**どの日にも成り立たないイベントの条件と ED の条件**（例：10 日目までに学力 90 以上）を拒否する。
  - 区間は過大評価なので、「成り立たない」と言い切れるものだけを拒否する（偽陽性を出さない）。
- **到達の確かめ**（テスト側）：攻略対象ごとの操縦役が、複数のシードで各 ED に届くこと。
- **データの個数**：行数・イベント数・選択肢数の上限を、展開の前に検証する（044）。
- **ビルド前の検証**：`IPreprocessBuildWithReport` で同じ検証を通し、誤りがあればビルドを止める（046）。

## セーブ（日の始めに 1 枠）

- 保存するもの：試合のシード・日・能力値・好感度・フラグ・1 回だけのイベントの済み・直前の行動・データの指紋。
- 形式：行指向テキスト・版番号・指紋・末尾のチェックサム。041・046 の `SaveText`・`ISaveStore`・`FileSaveStore` を写す。
- 書き込みは一時ファイルから原子的に置き換える。
- 読み込みの拒否（切れた・改変・版違い・指紋違い・値が範囲外）は、理由を付けてタイトルで案内する（移行はしない）。
- ED に着いたら枠を消す。読み書きの失敗は案内に変え、遊び続けられるようにする（041）。

## テスト（主なもの）

- **同日排他イベントは重複しない**
  - 乱択の行動列 × 多数のシードの通しで、毎日の各枠が高々 1 本・`@exclusive` の組が同じ日に出ないことを確かめる。
  - 同じ枠・同じ優先度の候補が並ぶテスト用の表で、定義の順が勝つことを確かめる。
- **条件を満たさない ED に入らない**
  - 通しの終わりに、選ばれた ED の条件が成り立ち、より優先度の高い ED の条件が成り立たないことを、全シードで確かめる。
  - 境界の負例：好感度 69・フラグなしなど、閾値の 1 つ手前で上の ED に入らない。
- **能力値の範囲外逸脱なし**
  - 効果の上限・下限ちょうどと 1 超えで、飽和することを確かめる。
  - 乱択の長い通しで、毎日の全能力値が範囲内にあることを確かめる。
  - 区間の検証が、範囲外の初期値・逆向きの幅・成り立たない条件を拒否することを確かめる。
- **シード固定でイベント列一致**
  - 同じシードと同じ行動の列なら、イベントの列とハッシュが一致することを確かめる。
  - 行動の結果の系列を余分に引いても、イベントの列が変わらないことを確かめる（用途ごとの系列）。
  - 最終ハッシュを .NET と Mono で固定値と照合する。
- **セーブ**
  - 日の始めの保存を読み直すと、同じ状態とハッシュから同じ続きになることを確かめる。
  - 全ての切り位置・1 文字の改変・版違い・指紋違いを拒否することを確かめる（041）。
- **共通の必須テスト**
  - 状態遷移（タイトル → 遊ぶ → ED → タイトル → 再戦は新しいシード）と、結果の後の入力を無視することを確かめる。
  - 負テストとして、選べない曜日の行動・範囲外の選択肢・重複したイベントの適用は拒否で状態不変になることを確かめる。
- **PlayMode 実シーン**
  - 仮想キーボードとマウスだけで 30 日を遊び、ED の画面まで届く（操縦役の方針を入力に変換）。
  - つづきからの再開と、タイトルへ戻った表示が起動直後と同じこと（021）を確かめる。
  - フォーカス喪失の一時停止を確かめる。
- **ビルド前の検証**：わざと壊したデータで `dev build` が行番号付きで止まることを一度確かめる。

# 039 2D対戦格闘 実装計画

## Context

- 039 2D対戦格闘（難易度 4・Phase 2）は未着手。仕様書 [plan/games/039-fighting.md](../../dev/unity/100games/plan/games/039-fighting.md) の中心課題は「**フレームデータ駆動で攻撃状態を管理**」、重点は「**当たり・被弾・投げ領域を分離**」。
- In scope：2 キャラ・通常技 3・必殺技 1、ラウンド制 2 先取、投げ・ガード、タイトル→操作説明→結果→再プレイ。Out of scope：オンライン Rollback、多数コンボキャラ、素材の量産。

- ユーザーと決めたこと：
  - **1P 対 CPU のみ**。CPU は App の操縦役として作り、撮影・テストと共有する（002・021）。
  - **必殺技はコマンド入力**（↓↘→＋攻撃など）。入力履歴と受付猶予を Core に持つ。
  - **技表の違う 2 人**。同じエンジン・同じ技表の書式で、歩く速さ・リーチ・必殺技（飛び道具／突進）が違う。タイトルで自キャラを選び、CPU は残りの 1 人（同キャラ戦はなし）。
- 作品名はオリジナル（仮）：**EMBER DUEL**。参考作品の名称・キャラ・演出は使わない。
- 作業は `main` から `feature/game039` を切る。この計画は session 0 で `plan/games/039-fighting-implementation.md` に置き、ルールの正は作品 README の「採用ルール」とする。

## ルール表（セッション1・2で README に固定する要点）

| 項目 | 採用ルール |
|---|---|
| 時間 | 60 Tick/秒（1 Tick = 1 フレーム）。入力は起きた時刻を含む Tick に反映（022・037 の時刻つき入力、フレーム単位の Tick 上限） |
| 座標 | 1 単位 = 1/256 ピクセル相当の整数（画面 1 px = 256）。x 右・y 上。浮動小数点は使わない。ステージは左右の壁で閉じ、画面端で押し合う |
| 向き | 地上で相手の側を自動で向く（振り向きは空中・攻撃中はしない）。入力の「前・後」は向きで解釈する |
| 状態 | `Idle / Walk / Crouch / Jump(予備動作・空中・着地) / Attack(発生・持続・硬直) / HitStun / BlockStun / Thrown / Knockdown / Wakeup / KO`。各状態は残り Tick で進む |
| 技表 | `Assets/Game/Data/Moves.txt`（キャラごと）。技ごとに 発生・持続・硬直、ダメージ、ヒット硬直・ガード硬直、ヒットストップ、ノックバック、段（上段/中段/下段）、キャンセル可否、Tick ごとの判定箱の列。**状態機械は技表を読むだけで、技固有のコードを持たない** |
| 判定箱 | 3 種を別の列で持つ：**攻撃箱**（Hit）、**喰らい箱**（Hurt）、**投げ箱**（Throw：投げる側）／**被投げ箱**（Throwable：投げられる側）。加えて押し合い箱（Push）。当たりは攻撃箱 × 喰らい箱、投げは投げ箱 × 被投げ箱だけで判定し、混ぜない。向きで左右反転 |
| 通常技 | 弱（上段・発生早い）、強（中段・リーチ長い）、足払い（下段・しゃがみで出す・当たればダウン）。弱 → 必殺技はヒット/ガード時にキャンセル可 |
| 必殺技 | A：**飛び道具**（↓↘→＋攻撃、画面に 1 つまで、相手の喰らい箱か相手の飛び道具に当たると消える）。B：**突進**（同コマンド、前進しながら複数 Tick 持続、ガードされると不利が大きい） |
| コマンド | 方向は 9 方向のテンキー表記で Tick つきの履歴（直近 `HistoryTicks`）に積む。↓→↘→ の順で各方向が `StepWindow` Tick 以内、最後の方向から攻撃ボタンまで `ButtonWindow` Tick 以内で成立。攻撃の押下は `BufferTicks` だけ先行入力として保持し、硬直が解けた最初の Tick に出す |
| ヒット | 攻撃箱が喰らい箱に重なった最初の Tick に 1 回だけ成立。**同じ技の発動 1 回につき 1 人に 1 ヒット**（発動ごとの番号で記録し、持続中に重なり続けても 2 回目を出さない）。成立したらダメージ・ヒット硬直・ノックバック・ヒットストップ |
| ガード | 後ろ入れでガード。立ちは上段・中段、しゃがみは上段・下段を防ぐ（中段はしゃがみで防げない、足払いは立ちで防げない）。ガード成功は **ダメージ 0（必殺技だけ削り `ChipDamage`）**、ガード硬直、ノックバック、短いヒットストップ。削りで KO しない |
| 投げ | 弱＋強の同時押し（1 Tick の猶予）。地上・相手が地上で、ヒット/ガード硬直中・ダウン中・投げられ中でない（被投げ箱が無い）ときだけ成立。ガード不能。同じ Tick に両者が投げたら番号の小さい方ではなく **両方とも外れ（投げ抜け扱い）** にして離す |
| 相打ち | 同じ Tick に両者の攻撃が成立したら両方当てる（相打ち）。KO も同時なら引き分けのラウンド |
| ヒットストップ | 成立した Tick の後、両者とも状態の残り Tick・位置・飛び道具が `HitStop` Tick 止まる。止まっている間も入力の履歴と先行入力は積む（コマンド・ボタンは止まりの後で効く）。止まりの間に新しいヒットは起きない |
| 1 Tick の順序 | ①入力を履歴へ ②ヒットストップ中なら残りを 1 減らして終わり（④以降を飛ばす） ③両者の状態を同時に進める（入力の解釈・技の開始・移動） ④押し合い・壁 ⑤投げ判定 ⑥攻撃判定（両者・飛び道具を同時に集めてから適用） ⑦KO・ラウンド判定。順序は README とテストで固定 |
| 体力 | 各 `MaxHealth`。0 で KO。KO の Tick 以後の入力は状態を変えない |
| ラウンド | 制限 `RoundTicks`（99 秒）。KO か時間切れ（体力の割合が多い方、同じなら引き分け）。**2 本先取で試合終了**。引き分けは両者に 1 本。両者同時に 2 本なら延長ラウンド（最大 `MaxRounds` で打ち切り、引き分けの試合） |
| CPU | `CpuPilot`（App）：距離と相手の状態で行動を選ぶ（歩く・ガード・対空・弱で差し返し・必殺技・投げ）。反応遅れ `ReactionTicks` と判断のぶれは試合のシード。人と同じ入力（方向＋ボタン）を作って Core に渡し、コマンドも入力として組む |
| 乱数 | Core は乱数を使わない。CPU のぶれだけ `SeededRandom`。1 試合 = 1 シード、再戦は起動時の値から進めた新しいシード（010） |
| 操作 | ←→ 移動（後ろでガード）、↓ しゃがみ、↑ ジャンプ、J 弱・K 強・L 足払い、J＋K 投げ、Esc 一時停止、F1 判定箱の表示。フォーカス喪失で一時停止し、先行入力と履歴を捨てる |

## セッション1：技表とフレーム状態機械（Core）

- `MoveData`・`MoveTable`（`Moves.txt` の読み込みと検証：発生 ≥ 1、Tick ごとの箱の数が発生＋持続＋硬直に一致、キャンセル先が存在、箱が有限で大きさ > 0）
- `Fighter`（状態・残り Tick・位置・速度・向き・体力・発動番号）、`Hitbox`（`Rect` の 5 種の列を向きで反転）、`CommandReader`（履歴・猶予・先行入力）、`Projectile`
- `Duel`（2 人と飛び道具・ヒットストップ・1 Tick の順序・`Hash`・`Clone`）、`FrameLog`（Tick ごとに各人の状態・フェーズ・箱の有無を記録）

### テスト（セッション1）

- **技表のログ照合**：全キャラの全技を中立から 1 回出し、`FrameLog` の発生・持続・硬直の Tick 数と、ヒット・ガード時の有利 Tick（硬直差）が `Moves.txt` と一致。README の技表は `Moves.txt` から生成した表で、テストが一致を確かめる（完了判定「技表がログと一致」）
- **ヒットストップの更新順**：止まり中に状態・位置・飛び道具が進まない、履歴とボタンは積まれて止まり明けの Tick に効く、止まり中に重なり続けても新しいヒットが起きない、止まりの長さちょうど・1 Tick 前後の境界
- **ガード**：立ち/しゃがみ × 上段/中段/下段の 6 通り、成功時はダメージ 0（必殺技は削り）・ガード硬直、失敗時は通常のヒット。削りで体力 1 からは KO しない
- **多重ヒット防止**：持続 5 Tick の技が全 Tick 重なっても 1 ヒット。突進の複数 Tick 持続でも 1 ヒット。次の発動では再びヒット。ヒットストップ明けでも重複しない
- **領域の分離**：攻撃箱だけ重なって喰らい箱が離れていれば当たらない、投げ箱が届いても被投げ箱が無い（硬直中・空中）なら投げない、投げ箱は攻撃判定に使われない
- **投げ**：ガード中の相手を投げる、同時の投げは両方外れる、空中・硬直中は投げられない
- **コマンド**：↓↘→＋攻撃が猶予ちょうどで成立・1 Tick 超えで不成立、向きが逆だと ↓↙← が必要、ヒットストップ中の入力でも成立、先行入力が硬直明けに 1 回だけ出る
- **相打ち**・押し合いと壁・振り向き・飛び道具どうしの相殺
- 同じ入力列の最終ハッシュが .NET と Mono で一致。ハッシュは止まりの残り・履歴・先行入力・発動番号まで含める（022）

## セッション2：ラウンド・試合・CPU（Core / App）

- `Match`（ラウンドの開始待ち・KO 演出の待ち・時間切れ・2 先取・延長と打ち切り）
- App：`DuelFlow`（Title / CharacterSelect / Intro / Fighting / RoundEnd / Paused / Result、時刻つき入力、フレームの Tick 上限）・`CpuPilot`・`Intent`

### テスト（セッション2）

- KO・時間切れ（多い方・同じ）・引き分け・相打ち KO・2 先取・延長・打ち切りの各終わり方。結果後と KO 後の入力は状態を変えない
- タイトル → 選択 → ラウンド → 結果 → 再戦（新しいシード・体力とラウンド数が初期化）、途中で一時停止・タイトルへ戻る
- 操縦役（`CpuPilot` をプレイヤー側に）vs CPU で 20 シード全部が規定 Tick 内に試合終了、入力なしのプレイヤーは 2 本取られて負ける
- 人寄りの操縦役（反応を遅らせ、キー入力に丸める）が CPU に勝ちうる（勝率を数字で記録して難易度を決める、038）
- 30〜240fps・不規則な間隔で同じ入力を届けてハッシュ一致、フォーカス喪失で先行入力を捨てる

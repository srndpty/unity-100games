# 026 ツインスティックSTG 実装計画

## Context

- 026 ツインスティックSTG（難易度2・Phase 2）に着手する。仕様書 [plan/games/026-twin-stick.md](026-twin-stick.md) の中心課題は「**方向入力とポインタ照準の分離**」、重点は「**スポーンレート制御**」。In scope：移動と照準を独立入力、5 分間に敵 3 種、スコアと再挑戦、タイトル→操作説明→結果→再プレイ。Out of scope：ローカル協力・大量の武器種（武器は 1 種のみ。ボム・パワーアップも作らない）。
- 題材固有テスト：移動方向と射撃方向を独立指定／画面外の敵が累積しない／無敵時間中の被弾無効。完了判定：5 分生存または死亡までプレイ、敵密度上限を維持。
- ユーザーと決めたこと：
  - 入力は **WASD（矢印キーも可）で移動、マウス位置で照準、左ボタン押しっぱなしで連射**。ゲームパッドは対応しない
  - フィールドは **画面より広いアリーナ（約 2 画面分）＋自機に追従するカメラ**
  - **残機 3＋被弾後の無敵**（その場で再開、周囲の敵は消さない）。0 で敗北、5 分生存で勝利

作品名はオリジナル（仮）：**HALO SIEGE**。参考作品の名称・素材・演出（ネオンの格子の歪みなど）は使わない。

## セッション1：ルール表（README に固定）と Core / App

### ルール表（要点）

| 項目 | 採用ルール |
|---|---|
| 単位 | 位置・速さは整数（1 セル = 256 単位、tile-motion の `Units`）。60 Tick/秒、時間の設定は Tick 数。5 分 = 18000 Tick。浮動小数点を使わず Mono と .NET で一致させる |
| アリーナ | 48×27 セルの矩形（画面に見えるのは 32×18 セル）。壁は外周のみ、障害物なし。自機は外周で止まる |
| 視野 | `View.Of(自機, アリーナ, 視野の大きさ)`：自機中心、アリーナの端で寄せ止め。**Core の規則としてカメラと同じ関数を使う**（「画面外」の定義を Core で持つ） |
| 移動 | 8 方向・速さ一定。斜めは `speed*181/256`（最低 1、022 の知見）。移動キーは射撃方向に影響しない |
| 照準 | App から毎 Tick「照準点（アリーナ座標の整数）」を受け取る。弾の向き＝自機→照準点のベクトルを整数平方根で弾速に正規化。照準点が自機と一致する（長さ 0）なら直前の向きを保つ。**移動方向とは独立** |
| 射撃 | 押している間、`FireIntervalTicks` ごとに 1 発（`Countdown`）。弾は直進、寿命 Tick またはアリーナ外で消える。同時に存在できる弾の上限は設定の検証で保証（寿命 ÷ 間隔 ≤ 上限、超えたら例外＝fail-closed） |
| 敵 3 種 | **Chaser**（自機へ向きを変えながら遅く追う・体力 1）／**Bouncer**（直進し外周で反射・体力 1）／**Lancer**（停止して予告 → 自機の方向へ突進 → 停止を繰り返す・体力 3）。敵は弾を撃たない |
| 出現 | 出現位置に予告マーカーを `SpawnWarnTicks` 出してから実体化（予告中は当たらない）。位置は**視野内で自機から `SafeRadius` 以上**離れた点を乱数で選ぶ（候補が尽きたらその Tick は見送る） |
| スポーンレート | `SpawnDirector`：経過時間の区間ごと（例：0–60s, 60–120s…）の表に「出現間隔 Tick」と「種類の重み」を持つ。出現の予算は Tick ごとに貯まり、**生存数（予告中を含む）が `MaxAlive` に達している間は出さず、予算も上限 1 体分で頭打ち**（上限から外れた瞬間にまとめて湧かない） |
| 画面外の敵 | 視野の外に `OffscreenLimitTicks` 続けて居た敵は得点なしで消える。生存数は常に `MaxAlive` 以下、視野外の敵の数も上限付き（検証可能な不変条件） |
| 当たり判定 | 自機・敵・弾はすべて円。**Tick 中の相対軌跡どうしの掃引**で最初に触れた時刻を求める（002/009/021 の知見）。弾は速いので端点だけで判定しない。弾 1 発は最初に触れた 1 体だけに当たる |
| 被弾 | 自機が敵に触れたら残機 -1、その場で `InvincibleTicks` 無敵（無敵中の接触は無視）。触れた敵は消える（得点なし）。残機 0 で敗北 |
| 得点 | 撃破で種類ごとの点（Chaser 10・Bouncer 20・Lancer 50 を既定）。勝利時は残機ボーナスを加算 |
| 乱数 | 1 試合 = 1 シードの xorshift（`SeededRandom`）。出現位置・種類の選択・敵の行動で系列を分ける（015 の知見） |
| 終了後 | 勝利・敗北の後の Tick と入力は状態を変えない |

### Core（`Assets/Game/Core/`、`com.games100.tile-motion` の `Units`・`Countdown`・`StateHash` を参照）

- `Vec2i`・`IntMath`（整数平方根・長さの正規化）、`Circle`・`Sweep.First`（2 つの円の相対軌跡の最初の接触時刻。分数で返す。025 `Geometry.cs` の `Touch`/`Time` の書き方を流用）
- `Arena`・`View`（アリーナの矩形、視野の寄せ止め、視野内判定）
- `Ship`（位置・照準の向き・射撃の `Countdown`・残機・無敵の `Countdown`）、`Bullet`
- `Enemy`（種類・位置・速さ・体力・行動フェーズ・視野外の連続 Tick）、`EnemyBrain`（3 種の 1 Tick の動き）
- `SpawnDirector`（区間表・予算・`MaxAlive`・予告・位置選び）
- `SiegeRun`：試合全体。1 Tick の順序＝入力反映 → 自機移動 → 射撃 → 敵の移動 → 弾×敵の掃引 → 自機×敵の掃引 → 視野外の除去 → 出現 → 時間判定。`Step(ShipCommand)`・`Hash()`・`Clone()`
- `SiegeConfig`：公開フィールド＋検証（有限・範囲・弾数の上限・`SafeRadius` が視野に収まる・区間表が 5 分を覆う）

### App（`Assets/Game/App/`）

- `SiegeFlow`：Title / Playing / Paused / Result、実時間 → 固定 Tick、フレーム単位の Tick 上限（025 の `VaultFlow` を土台に）。フォーカス喪失時は保留入力も消して停止
- `Intent`・`HeldControls`（025 から流用）：移動 4 キー・射撃ボタンの押下状態。照準点は Unity 層がマウス座標から毎フレーム渡す（`SetAim(Vec2i)`）
- `Autopilot`：最も近い脅威から離れつつ最も近い敵を狙う。試合ごとに判断状態を捨てる（023 の知見）

### テスト（題材固有を優先）

- **移動方向と射撃方向を独立指定**：右へ移動しながら上・左・斜めを狙い、弾の速度の向きが照準どおり・自機の移動が移動キーどおり。照準点＝自機位置では直前の向き。移動なしで照準だけ変える場合も
- **画面外の敵が累積しない**：自機を隅に置いたまま長時間進め、毎 Tick「生存数 ≤ `MaxAlive`」「視野外の敵は `OffscreenLimitTicks` 以内に消える」を検査。上限に張り付いた後、空きが出ても 1 Tick に 1 体しか出ない（予算の頭打ち）
- **無敵時間中の被弾無効**：無敵の最後の Tick と、切れた直後の Tick の境界で残機の減り方を確認。無敵中に複数体に触れても残機は減らない
- スポーンレート：区間ごとの出現数が表どおり（上限に当たらない設定で数える）、予告中は当たらない、`SafeRadius` 未満には出ない
- 掃引：弾が速く敵をすり抜ける位置関係（端点では重ならない）でも当たる、斜めのかすり、同じ Tick に 2 体へ届く弾は先に触れた方だけ
- 共通：状態遷移（開始→進行→終了→再戦・終了後の入力無視）、負テスト（NaN/範囲外の設定・未定義の操作・終了後の Step・同 Tick の重複入力）、再現性（同シード同入力で同ハッシュ）、**完走**（Autopilot で 30 シードが 18000 Tick 以内に勝利または敗北で終わる。固定シードの最終ハッシュを .NET と Mono で照合）

## セッション1の結果（2026-11-23）

- ルール表は [README](../../games/026-twin-stick/README.md) の「採用ルール」を正とする。
- Core（`Geometry`・`SiegeConfig`・`Ship`・`Enemy`・`SiegeRun`）と App（`Intent`・`HeldControls`・`SiegeFlow`・`Autopilot`）を実装。Core 70 件・App 17 件が .NET で、tile-motion の 10 件を含む 97 件が Mono で通った。
- 計画との差：
  - 出現の制御は `SpawnDirector` クラスに分けず、`SiegeRun` の中の予算 1 つ（`SpawnStep`）にした。状態が整数 1 つと乱数 2 系列だけで、分けると複製・ハッシュの受け渡しが増えるため。
  - 被弾の無敵は「被弾した Tick を含めて 120 Tick」（tile-motion の `Countdown` の数え方にそろえた）。
  - 外周では、Bouncer の反射も含め「着いた時点で止まる」にして、その Tick の軌跡を直線に保った（掃引と食い違わない）。
- 自動操縦はシード 1〜8 で全勝・被弾なし（最大生存 6〜8 体、平均 12381 点）。上限 36 体には届かないので、密度の上限は自機が隅にとどまるテストと、セッション3の負荷計測（上限いっぱいの設定）で確かめる。難しさ（出現の間隔・敵の速さ）は試遊で調整する。
- シード 1 の最終ハッシュ `0xC45939FC` は .NET と Mono で一致。
- 次（セッション2）：Unity 層（生成ドット絵・Stage Prefab・`View.Of` に合わせる追従カメラ・マウス照準とカーソル・HUD・音・シーン生成・撮影台本）。

## 試遊の指示を受けた調整（2026-11-23）

- 指示：5 分は長いので 1 分に。出現の頻度は最初は今のままでよく、徐々に増やして最後は 3 倍くらいに。
- 試合の長さ 18000 → 3600 Tick。出現の区間を 60 秒 × 5 から 10 秒 × 6 にし、間隔を 75 → 62 → 51 → 42 → 33 → 25 Tick（最後は最初の 3 倍の頻度）。仕様書の「5 分間」からの変更として README に記録した。
- 設定アセットは生成スクリプトが上書きしないので、新しい既定値をアセットにも書いた。
- 自動操縦の完走テストを 30 シードに増やした（全勝、平均 3417 点）。シード 1 の最終ハッシュは `0xE8B259C2`（.NET と Mono で一致）。
- 1 分だと最初の試合が被弾の場面の前に終わり撮影が失敗したので、台本を「自動操縦で勝利まで」「撃たずに敵へ向かって被弾・一時停止・上限・敗北」の 2 試合に分けた。同じビルドで 2 回撮影し、11 枚の SHA-256 が一致した。

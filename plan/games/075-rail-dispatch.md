# 075. 鉄道運行管理

> Unityゲーム制作100本ノック v1.1 / Phase 4：経営・生活・シミュレーション・競技  
> 参考作品：Rail Route（ゲームメカニクスの参考。素材・名称・演出の複製は不要）  
> 実装難易度：★★★★☆  
> 状態：未着手

## 1. 学習目的

**この題材の中心課題**：線路セクションの占有・予約。

学習上の重点：信号・ルート競合を検証。

## 2. 最小完成スコープ（In scope）

- 駅4、列車3、信号機と閉塞
- 時刻表通りに発着
- 衝突/遅延を評価
- タイトル/開始、基本操作説明、勝利・敗北または結果、再プレイまでを一巡できる。

## 3. 今回は実装しない（Out of scope）

- 大規模鉄道網
- 運転シミュレーション
- アセットの大量制作、追加ステージ量産、課金・実績・外部ランキングなど学習目標と無関係な製品化要素。

## 4. 内部設計・コンポーネント境界

- 線路セクションの占有・予約
- 信号・ルート競合を検証
- **Core**：状態、ルール、検証、乱数の受け口。可能な範囲でUnity APIに依存しないC#コードとする。
- **Presentation**：MonoBehaviour/UI ToolkitまたはuGUI/描画/効果音・演出。Coreの結果を反映する。
- **Orchestration**：入力を意図に変換しCoreへ渡す。状態遷移と再開・リセットを統括する。
- パラメータ（速度、制限時間、スコア、敵挙動など）は設定アセットまたはデータへ分離する。ただし単純な作品で過剰な抽象化をしない。

## 5. テスト仕様

### 題材固有のテスト（優先）

- [ ] 同じ閉塞へ2列車を入れない
- [ ] 閉塞解放後に信号が更新
- [ ] 対向列車のデッドロックを検出

### 共通の必須テスト

- [ ] **Core**：主要な合法/非合法操作と境界値を確認する。再現可能な入力は自動テスト化する。
- [ ] **状態遷移**：開始→進行→終了→再戦の順序を守り、終了後の不正操作を無視または拒否する。
- [ ] **再現性**：乱数利用箇所ではシード固定。物理/ネットワーク系は許容誤差・計測条件を明記する。
- [ ] **負テスト**：不正入力、値域外、途中終了、重複イベントを最低1ケースずつ確認する。
- [ ] **ビルド**：エディターの再生だけでなく、選択した対象プラットフォーム向けに一度ビルドして起動確認する。

## 6. 完了判定（Acceptance criteria）

- [ ] 時刻表を完走できる。
- [ ] 事故ゼロの運行が可能。
- [ ] **Core**：主要メカニクスが動作し、設計境界が説明できる。
- [ ] **Playable**：チュートリアルなしでも最低限の操作案内があり、プレイを完走できる。
- [ ] **Verified**：題材固有テスト＋共通テストが通過し、未解決の問題を記録した。

## 7. 成果物・記録

- 実行可能なUnityプロジェクト（原則、1題材＝1プロジェクト）。
- README：起動手順・操作・採用ルール・設計上の選択・未実装範囲。
- `Tests/`：CoreのEditModeテスト、必要ならPlayModeテスト。
- `evidence/`：動作スクリーンショットまたは短い動画、ビルド結果、主要テスト結果。
- `retrospective.md`：新たに学んだ点／想定との差／次回の改善点を各3行以内。

## 8. 着手前に固定する事項

- 使用Unityバージョンと対象プラットフォーム、入力方式を`README.md`に記載する。
- 参考作品固有の細部で曖昧なルールは、**実装前に小さなルール表として固定**する。原作完全互換を要求しない。
- 性能目標・物理許容誤差・ネットワーク条件が必要な題材では、測定環境と成功基準を先に決める。

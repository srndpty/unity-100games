# 048 脱出ゲーム 実装計画

## Context

- 仕様書は [plan/games/048-escape-room.md](plan/games/048-escape-room.md)。
  - 中心課題：**Interactable の状態機械**。
  - 重点：**カメラとヒットテスト**。
- In scope：
  - 3D の 1 部屋に仕掛けが 5 種。
  - 観察・回転・ズームの操作。
  - 鍵を連鎖させて出口を開ける。
  - タイトル → 操作説明 → 結果 → 再プレイの一巡。
- Out of scope：
  - 部屋を複数にすること、高精細なアセット。
  - 計画で足さないもの：セーブ、時間切れ、自由な見回し。
- 題材固有テスト：
  - **未解除ロックを操作で迂回できない**
  - **ヒント表示と実状態が一致**
  - **同時操作で状態破綻なし**
- 完了判定：
  - **5 つの仕掛けを解いて脱出**できる。
  - **リセットで初期状態へ戻る**。
- ユーザーと決めたこと：
  - **視点の切り替え式**のカメラ。
    - 部屋の中央から、左右キーまたはドラッグで 4 面の壁へ向き直る。
    - 仕掛けをクリックすると、その近景へ寄る（ズーム）。右クリックまたは Esc で戻る。
    - 手に取れる物は、近景でドラッグして回し、裏や側面を見る。
  - **敗北はなく、結果画面だけ**。経過時間・操作の回数・使ったヒントの数を出す。時間切れはない。
  - **ヒントは「次の一手」を段階的に**出す。段階は方向付け → 具体的な手がかり → 答え。どの仕掛けを案内するかは、Core が実際の状態から決める。
  - 舞台は**古い天文学者の書斎**。作品名（オリジナル）はセッション 3 で決める。
- 進め方：047 を main にマージしたので、main から `feature/game048` を切る。`dev new 048 -Template 3d` で作る（029・038 と同じ URP 3D）。
- 乱数：
  - 試合のシードから仕掛けの答えを作る。作るのはダイヤルの数字、天球儀の星座、時計の時刻、金庫の順番。
  - 1 試合 = 1 シード。再戦では新しいシードにする。
  - 撮影では `EvidenceCapture.Seed` を使う。
  - 再現性は「同じシードと同じ命令列なら、同じ状態ハッシュ」で保つ。

## ルール表（セッション 1 で README に固定する案）

### 仕掛け 5 種と鍵の連鎖

| # | 仕掛け（種類） | 操作 | 手がかり | 解くと |
|---|---|---|---|---|
| 1 | 机の引き出しの**数字ダイヤル錠**（3 桁） | 桁をクリックして 1 つ進める（0〜9 で循環） | 手に取った**真鍮の筒**を回すと、底に刻まれた 3 桁が見える | 引き出しが開き、**真鍮の鍵**が出る |
| 2 | キャビネットの**鍵穴** | 持ち物の鍵を選んで鍵穴をクリック | — | 扉が開き、**星図の円盤**が出る |
| 3 | **天球儀のリング合わせ**（3 本） | リングをクリックして 45° ずつ回す（8 段） | 星図の円盤を手に取って回すと、3 つの星座の印と並び順が見える | 天球儀の中が開き、**歯車**が出る |
| 4 | **柱時計の針合わせ** | 歯車をはめると針が動くようになる。長針・短針をクリックで進める（12 段） | 本棚の本を手に取って回すと、裏表紙に時刻が書いてある | 振り子の扉が開き、**金庫のハンドル**が出る |
| 5 | **金庫の順番ボタン**（4 つの宝石） | ハンドルを付けたあと、宝石を順に押す。間違えると最初から | 望遠鏡をのぞくと、窓の外の星が順に瞬く | 金庫が開き、**出口の鍵**が出る |
| 出口 | 扉の鍵穴 | 出口の鍵を使う | — | 脱出（結果画面へ） |

- 依存は 1 → 2 → 3 → 4 → 5 → 出口の鍵の連鎖。
  - 一本道にしないため、手がかり（筒・本・望遠鏡）は最初から触れる。
  - そのため、ダイヤルと時刻の答えは先に知ることができる。
- 状態の数：答えは手がかりから、操作の値は状態として持つ。探索では、ダイヤルの値などを「正解か否か」に縮めた抽象状態で扱う（下記）。

### Interactable の状態機械（Core の中心）

- 仕掛けごとに明示的な状態を持つ：`Locked`（前提の不足）→ `Active`（操作できる）→ `Solved`（解けた・以後は不変）。開く物にはさらに `Open` を持つ。
- 遷移は、各仕掛けが持つ**表**（状態 × 操作 → 次の状態・効果）で決める。表にない操作は `Rejected` を理由付きで返し、状態・ハッシュ・操作の回数を変えない。
- 前提（必要な持ち物・ほかの仕掛けの解決）は、宣言から `Locked` の解除として評価する。
  - 状態を個別に変えず、**前提の評価を 1 か所に置いて**全ての仕掛けで共有する。
- 仕掛けの種類（ダイヤル・鍵穴・リング・針・順番）は `IMechanism` の 5 つの実装にする。部屋はそれらと持ち物・視点・出口を束ねた `Room` にする。
- 命令は `Command` にまとめる：`Turn(視点)`・`Focus(仕掛け)`・`Back`・`Operate(部品)`・`UseItem(持ち物, 部品)`・`Take(物)`・`Inspect(物)`・`Rotate(dyaw, dpitch)`・`Hint`・`Reset`。
- `World.Apply(Command)` だけで状態を変える。出来事（開いた・解けた・拾った・拒否・ヒント）を記録し、音と表示は出来事から作る（039）。

### カメラとヒットテスト（Core）

- 視点は離散にする：部屋の中央からの 4 面と、仕掛けごとの近景（位置・向き・画角を整数で宣言）。
- 手に取った物の回転は、ヨー 45° 刻み・ピッチ 90° 刻みの離散の向きにする。
  - 「手がかりの面がカメラを向いているか」を Core が判定する。手がかりは向いているときだけ読める（表示も判定も Core）。
- ヒットテストは Core に置く。
  - 画面の正規化座標（整数）からレイを作り、部品の箱（整数の AABB、mm 単位）とスラブ法で交差させる。最も近い面の部品が当たる。
  - 当たりの判定は long で厳密に行う（int-geometry の `IntMath` を使う）。
  - **閉じた扉・引き出しの前板は、中の物を遮る**。前板も当たりの箱として扱い、中の物には届かない。
  - 遮る物を消すのは状態だけにし、ヒットテストは状態から作った箱の列で行う。
- Unity 側では `Camera` の行列を Core の視点の宣言から作る（同じ関数）。
  - PlayMode で、全ての視点の部品の中心と縁を `Camera.WorldToScreenPoint` で画面へ写し、Core のヒットテストと `Physics.Raycast` のどちらも同じ部品に当たることを照合する。
  - コライダーは照合専用で、遊ぶときの判定は Core だけで行う。
- カメラの移動の演出は、App が補間で描く。Core の視点は命令の時点で切り替わる。演出中のクリックは入力の受付で捨てる（015）。

### ヒント（Core の `HintEngine`）

- 今の状態から、**前提が揃っていて未解決の仕掛け**を依存の順で選ぶ。
  - 前提が足りない仕掛けしか残っていない場合は、前提を生む操作（拾う・使う）を案内する。
- 段階は仕掛けごとに 0 → 1 → 2 と進む。仕掛けが変わったら 0 から始める。
- 文は**今のシードの答え**から作る。例：「ダイヤルは 4・7・1」。
- 検証（テスト）：到達しうる全ての抽象状態で、次を確かめる。
  - 案内した仕掛けが `Active` であること、または案内した操作が受け付けられること。
  - 解いた仕掛けや、未解除のロックの先を案内しないこと。
  - 答えの段階のとおりに操作すると、その仕掛けが解けること。

### 状態空間の検証（047 の `StateSpace` の方式）

- 抽象状態：仕掛けの状態（ダイヤルなどの値は「正解か否か」に縮める）・持ち物・取った物・手がかりを見たか。
- 全ての命令の候補を `World.Check` で絞って幅優先にたどる（047 の知見）。そこから次を拒否する。
  - **迂回**：出口が開いた状態で、5 つの仕掛けのどれかが未解決。仕掛けの前提が揃う前にその仕掛けが解ける。
  - **詰み**：脱出に届かない到達状態がある。
  - **持ち物の違反**：二重に拾う、使って消えた物を使う。
- 探索は部屋の定義の検証としてコンパイル時に 1 回行い、状態数を README に記録する。

## 操作

| 入力 | 動き |
|---|---|
| 左右キー・A/D・壁の端のドラッグ | 4 面の壁へ向き直る |
| 左クリック | 仕掛けへ寄る／部品を操作する／物を拾う |
| 右クリック・Esc | 一段戻る（近景 → 壁）。壁の視点では一時停止 |
| 近景で手に取った物をドラッグ | 回す |
| 持ち物の枠をクリック | 選ぶ／外す。選んだまま部品をクリックすると「使う」 |
| H | ヒント |
| R（一時停止の中） | リセット（同じシードで最初から） |

- フォーカス復帰の直後のクリックは捨てる（010）。
- 押した画面の版は、意図を当てはめる直前に照合する（044・047）。
- 一時停止中は時計も止める（044）。
- フォーカスを失ったら保留中の入力も消す（046）。

## テスト（主なもの）

- **未解除ロックを操作で迂回できない**
  - 状態空間の全ての到達状態で、迂回がないことを確かめる。
  - 個別の負例：
    - 鍵なしで鍵穴を操作する。
    - ハンドルなしで金庫の宝石を押す。
    - 歯車なしで針を回す。
    - 閉じた引き出しの中の鍵を、前板越しにクリックする（ヒットテストが前板に当たる）。
    - 出口の鍵なしで扉を開ける。
  - いずれも `Rejected` になり、状態とハッシュが変わらないことを確かめる。
- **ヒント表示と実状態が一致**
  - 全ての到達状態で、上の 3 条件を確かめる。
  - シードを変えると、文の答えも変わる。
  - 解いた後は、その仕掛けを案内しない。
- **同時操作で状態破綻なし**
  - 同じフレームに、次の組み合わせの意図を 1 本の列で送る。
    - 2 つの部品のクリック。
    - 向き直りとクリック。
    - ヒントとクリック。
    - リセットとクリック。
    - ダブルクリック。
  - 列の順に 1 つずつ当てはまり、カメラの演出中のクリックは捨てる。
  - 乱択の命令列を長く流し、毎回の不変条件を確かめる。
    - 持ち物が重複しない。
    - `Solved` が戻らない。
    - 出口は全て解いた後にだけ開く。
- **リセットで初期状態へ戻る**：途中まで進めてリセットすると、新しく作った試合とハッシュが一致する。視点・持ち物・ヒントの段階・時計も戻る。
- **カメラとヒットテスト**
  - スラブ法を、細かい格子でレイを刻む素朴な参照実装と乱択で照合する。
  - 近い面が勝つ、縁ちょうどで当たる、遮りが効く、を確かめる。
  - 回した物の向きと手がかりの面の判定を確かめる。
  - PlayMode では、Core と `Physics.Raycast` の当たりが一致することを確かめる。
- **再現性**：同じシードと同じ命令列なら同じハッシュになる。シードが違えば答えが違う。最終ハッシュを .NET と Mono で固定値と照合する。
- **共通の必須テスト**：状態遷移（タイトル → 遊ぶ → 結果 → タイトル → 再戦）と、結果の後の入力を無視することを確かめる。負テストとして、範囲外の部品番号・不正な視点・重複したイベントを確かめる。
- **PlayMode 実シーン**
  - 仮想マウスとキーボードの入力だけで脱出まで遊ぶ（047 の P2-3）。
  - 部屋を一巡して戻ると、物が保持されている。
  - リセットした後の表示が、起動直後と一致する（021）。
  - フォーカス復帰のクリックを捨てる。

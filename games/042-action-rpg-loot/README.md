# 042. ASHEN RELIQUARY（仮）

仕様書：[plan/games/042-action-rpg-loot.md](../../plan/games/042-action-rpg-loot.md)　実装計画：[plan/games/042-action-rpg-loot-implementation.md](../../plan/games/042-action-rpg-loot-implementation.md)

状態：完了（2026-11-26 人間の動作承認）。[検証記録](evidence/README.md)、[振り返り](retrospective.md)。

灰に沈んだ聖堂の地下 3 階を降り、最奥の番人を倒すハクスラ ARPG。敵が落とす装備には、シードで決まる Affix（能力修飾）が付く。

## 環境

- Unity：6000.6.9f1
- 対象プラットフォーム：Windows (StandaloneWindows64)
- 入力方式：キーボード＋マウス（WASD 移動・マウス照準）

## 起動手順

```
dev gui 042      # エディタで開く
dev build 042    # Windows ビルド
dev run 042      # ビルドを起動
dev capture 042  # 証跡を evidence/ に撮る（画像は captures/<画像世代>/、撮影記録は runs/）
```

## 操作

| キー | 操作 |
| --- | --- |
| WASD | 移動 |
| マウス | 照準（攻撃の向き） |

## 採用ルール

### 戦利品（セッション1で固定）

データは [Assets/Game/Data/Loot.txt](Assets/Game/Data/Loot.txt)。Core の `LootData.Parse` が読み込みと検証を同時に行う。

| 項目 | 採用ルール |
| --- | --- |
| 能力値 | 最大HP・最小/最大攻撃力・攻撃速度（%）・移動速度（%）・防御・会心率（%）・会心倍率（%）・吸収（与ダメージの %）・火耐性・冷気耐性。装備なしの値は `hero` の行 |
| 修飾 | `StatMod`＝（能力・種類・値）。種類は `Flat`（足し算）と `Increased`（％の掛け算）。`Increased` は値が個数の能力（最大HP・攻撃力・防御）だけ。基礎品も Affix も修飾の列でしかない |
| 算出 | **基礎 + Σ Flat → × (100 + Σ Increased) / 100**。0 方向へ切り捨て、long で計算し、能力ごとの上下限で止める（最大HP 1〜99999、攻撃速度 25〜300%、移動速度 50〜200%、会心率 0〜75%、会心倍率 100〜500%、吸収 0〜20%、耐性 0〜75% など）。最大攻撃力は最小を下回らない。足し算だけなので修飾の順序に依らない。装備が変わるたびに装備一式から計算し直す（差分を足し引きしない） |
| 装備 | 枠は武器・鎧・兜・指輪・首飾りの 5 つ。基礎品 20 種（武器 6・鎧 4・兜 3・指輪 4・首飾り 3）。基礎品は出る階の下限と重みを持つ |
| 希少度 | 普通（Affix 0）・魔法（1〜2）・希少（3〜4）。接頭は 2 つ、接尾は 2 つまで |
| Affix の段 | Affix は段（出る階の下限と値の範囲）を持ち、その階で出る最も上の段を使う。値は範囲から整数を等確率で引く |
| **禁止の組合せ** | ①同じ**群**の Affix は 1 品に 1 つ（例：「鋭い」と「残忍な」はどちらも攻撃力の群） ②**排他の組**（`exclusive` の行。「重い」と「疾風」、「耐火」と「耐寒」）は同時に付かない ③**枠に合わない** Affix は付かない。生成は残った候補から重みで引き、候補が尽きたら Affix を減らす（規則を破って埋めない） |
| 生成の乱数 | **敵の配置ごとに独立した系列**（`LootRng.For(試合シード, 階, 配置番号)`）。倒す順・倒した Tick・他の敵のドロップに依らず同じ品が出る |
| ドロップ | 敵の種類ごとの表：装備を落とす確率・個数・希少度の重み・回復薬の確率。番人は希少を 2 つ必ず落とす |
| 説明 | `ItemText.Describe` が名前・希少度と枠・基礎の性能・Affix ごとの行を作る（接頭は《》、接尾は〔〕）。装備中との比較は、付け替えた装備で能力値を計算し直した差（`ItemText.Compare`） |
| データの検証 | ID の重複、未定義・自分自身・重複の排他、付く枠のない Affix、段のない Affix、段の階が増える順でない、範囲の逆転、％で増やせない能力への `inc`、重みが 0 以下、重みの合計が int を超える、出る基礎品がない階、必要なドロップ表の欠け を理由付きで拒否（`LootDataException`） |

### 戦闘と探索（セッション2で固定）

地図は [Assets/Game/Data/Floors.txt](Assets/Game/Data/Floors.txt)、遊んで決める値は Core の `DelveConfig`（Unity では設定アセット）。

| 項目 | 採用ルール |
| --- | --- |
| 時間・座標 | 60 Tick/秒。1 タイル = 256 単位（16 px）の整数。壁との解決は tile-motion の `BodyMotion`（横 → 縦）、突進・飛び道具と自機の接触は int-geometry の `Sweep.Touches`（1 Tick の線分と円の厳密な判定） |
| 階 | 手作りの固定地図 3 階（40×23 タイル）。各階の入口から始まり、階段のタイルに触れると次の階へ（戻らない、地面の品は持ち越さない）。3 階の奥に番人。地図の検証：幅・入口 1 つ・階段は 1・2 階に 1 つずつ・番人は 3 階に 1 体・入口から階段と全ての敵へ歩いて届く |
| 移動 | WASD の 8 方向。速さは `HeroSpeed`（24 単位/Tick）× 移動速度%。斜めは 181/256（最低 1）。攻撃・薙ぎ払いの構えの間は動けない |
| 基本攻撃 | 押している間、攻撃間隔 `30 × 100 / 攻撃速度%` Tick ごとに振る。振り始めの照準の向きへ、構え 6 Tick の後に「自機から 14 px 先の点を中心に半径 12 px＋敵の半径」の円に入った全ての敵に当たる |
| 薙ぎ払い | 右ボタンで 1 回。構え 10 Tick の後、自機から半径 30 px＋敵の半径の全ての敵に攻撃力の 150%。待ち 240 Tick |
| 与えるダメージ | 最小〜最大攻撃力から整数を等確率で引き、会心率で会心倍率を掛ける（戦闘の乱数の系列）。吸収は与えたダメージ × 吸収% を回復（最大 HP まで） |
| 受けるダメージ | 物理：`威力 × 100 / (100 + 防御)`、火・冷気：`威力 × (100 − 耐性) / 100`（耐性の上限 75%）。最低 1。受けた後 30 Tick は無敵 |
| 敵 3 種 | **灰鬼**（近づいて構え 24 Tick → 殴る）・**骨弓**（3 タイルより近ければ離れ、5 タイルより遠ければ寄り、構え 20 Tick → 冷気の矢）・**角獣**（5 タイル以内で構え 36 Tick → 向きを固定して 28 Tick 突進、壁で止まる。1 回の突進で当たるのは 1 回）。気づく距離に入るか攻撃を受けるまで動かない。体力・威力は階の倍率（体力 100/160/230%、威力 100/135/170%） |
| 番人 | 体力 440。近接（灰鬼と同じ）、160 Tick ごとに火の弾の扇 5 発。HP 半分以下では扇が 110 Tick ごとになり、240 Tick ごとに突進を加える。番人には階の倍率を掛けない |
| 回復薬 | Q で最大 HP の 40% を回復。待ち 60 Tick、満タンでは使わない。最大 5 個、始めは 2 個。敵が落とし、触れると拾う |
| 拾う | E で 1.5 タイル以内の最も近い装備品。名前札のクリックは 3 タイル以内の指定した品。持ち物は 20 マス、満杯なら拾わない（地面に残る） |
| 装備 | 持ち物の画面で選んだ品を装備（前の品は同じ番号へ）、外す（持ち物に空きが必要）、捨てる（足元へ。地面が満杯なら捨てない）。装備が変わると能力値を一式から計算し直し、HP は新しい最大 HP を超えない。始めは片手剣（普通）を装備 |
| ドロップ | 敵が倒れた Tick に 1 回だけ判定し「落とした」印を立てる（同じ Tick の複数の攻撃・倒れた敵への追撃・復活・複製でも 1 回）。品は敵の位置の周りに並べる |
| 死亡 | HP 0 で倒れ、90 Tick 後にその階の入口で HP 全快で復活する。持ち物・装備・倒した敵・地面の品はそのまま、生きている敵（番人を含む）は初めの位置と体力に戻り、気づく前の状態になる。残機はない |
| 勝利 | 番人を倒すと勝利。120 Tick 後に結果（時間・撃破数・倒れた回数・拾った品・最高の希少度）→ タイトル。結果の後の操作は無視 |
| 品の数 | 敵は再出現しないので品の総数は有限。地面の品は階ごとに 48 まで（超えた分は消え、数える）、持ち物は 20 マス |
| 乱数 | 1 試合 = 1 シード。戦闘の系列（試合シードから派生）と、敵の配置ごとの戦利品の系列を分ける。再戦は必ず新しいシード |
| 画面 | タイトル → 操作説明 → プレイ（持ち物・一時停止の間は Tick が進まない）→ 結果 → タイトル。フォーカスを失うと一時停止し、押していたキーを捨てる |

## 設計上の選択

- **Core（`Assets/Game/Core`）**：Unity API に依存しない。戦利品は `LootData`（表の読み込みと検証、データの指紋）・`StatMod`／`StatSheet`（修飾と能力値の算出）・`Item`／`Equipment`（不変の品と 5 枠）・`LootGenerator`／`AffixRules`（シード駆動の生成と組合せの規則）・`ItemText`（説明と比較の文）。
- 規則の判定 `AffixRules.IsAllowed` は生成とテストで同じものを使い、テスト側の素朴な全組合せの数え直しとも照合する。
- 試合は `DelveRun`（`Step`・`Clone`・`Hash`）。地図は `FloorSet`／`FloorMap`（`ISolidGrid`）、設定は `DelveConfig`（検証・複製・指紋）。状態のハッシュには設定・戦利品・地図の指紋を混ぜる。
- 装備の変更は `DelveRun.Equip`・`Unequip` だけを通し、能力値を必ず計算し直す。外へは枠ごとの参照（`EquippedAt`）と試算用の複製（`CopyEquipment`）だけを出し、可変の `Equipment` を渡さない。
- 設定の検証 `DelveConfig.Validate(LootData)` は範囲に加えて、初期武器が戦利品のデータにあり武器枠であることを確かめる（`DelveFlow`・`DelveRun`・設定アセットの検証で呼ぶ）。
- **App（`Assets/Game/App`）**：`DelveFlow`（画面遷移、時刻付きの入力を Tick に割り当て、1 フレーム 5 Tick まで）、`HeldControls`（押したままと押下の印を分ける）、`Autopilot`（タイルの幅優先探索で動き、良い装備を拾って付け替え、階を一掃してから階段・番人へ）、`HumanlikePilot`（攻撃・照準・薬を 10 Tick 遅れて決める）。

- **Unity（`Assets/Game/Unity`）**：`AshenStage`（Stage Prefab）は 3 階の `AshenFloorView`（床と壁の Tilemap・階段・入口・配置番号の順の敵の SpriteRenderer）と、自機・照準・攻撃の弧・薙ぎ払いの輪・突進の筋・飛び道具と地面の品の見本を持つ。敵は配置の SpriteRenderer をそのまま動かすので、プレイ前から Scene ビューで見える。`Mismatch` が Prefab の全タイル・階段・入口・敵の種類と位置を地図と照合する。`AshenGame` は入力（キー・マウスのボタンは時刻付きの意図、マウスの位置は照準点）・追従カメラ・音、`AshenHud` は HUD・名前札・持ち物の画面（UI Toolkit の `PanelRenderer`）。名前札・持ち物の操作も意図にして入力と同じ列で処理する。
- **生成**：`unity run games/042-action-rpg-loot -- -executeMethod Game.Unity.Editor.AshenSceneBuilder.Build` でドット絵・設定アセット・Stage Prefab・シーンを作る（既存の Prefab と設定アセットは上書きせず、地図との一致だけ確かめる）。
- **物理エンジン**：使わない。移動・衝突は Core の整数（tile-motion・int-geometry）。

## 未実装範囲

仕様書の Out of scope のとおり、オンライン協力・無制限アイテム生成は実装しない。セーブ・宝箱・店・敵の再出現・上の階へ戻る階段は作らない（品は敵のドロップだけで、総数は有限）。

証跡画像はJPEG（`.jpg`）、品質85を標準とし、保存したJPEGのSHA-256をマニフェストに記録する。

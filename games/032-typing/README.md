# 032. タイピングゲーム — INK VIGIL（仮）

仕様書：[plan/games/032-typing.md](../../plan/games/032-typing.md)　実装計画：[plan/games/032-typing-implementation.md](../../plan/games/032-typing-implementation.md)

夜の回廊の奥から、言葉を背負った影が迫ってくる。影の頭上の言葉をローマ字で打ち切ると消える。手前の線まで来られると体力が減る。参考作品からはメカニクスだけを採用し、名称と見た目は独自に作る。

## 環境

- Unity：6000.6.9f1（Universal 2D、C# 9.0）
- 対象プラットフォーム：Windows (StandaloneWindows64)
- 入力方式：Input System のキーボード（物理キーを読む。IME と配列の文字変換を通さない）。HUD は PanelRenderer / UI Toolkit
- 共通パッケージ：[com.games100.int-geometry](../../packages/com.games100.int-geometry/)（シード付き乱数 `SeededRandom` だけを使う）

## 起動手順

```
dev gui 032      # エディタで開く
dev build 032    # Windows ビルド
dev run 032      # ビルドを起動
dev capture 032  # 証跡を evidence/ に撮る（画像は captures/<画像世代>/、撮影記録は runs/）
```

## 採用ルール

| 項目 | 採用ルール |
|---|---|
| 時間 | 60 Tick/秒の整数。敵の奥行きは出現からの Tick で決まる（奥 10000 → 手前の線 0）。浮動小数点を使わないので Mono と .NET で同じ結果になる |
| 出題 | 単語帳（`Assets/Game/Data/Words.txt`）の 50 語。1 語は **表示文**（漢字かな交じり、画面に出すだけ）と **読み**（ひらがな、照合に使う）と段（1〜3、長いほど高い）を持つ |
| 打鍵 | 受け付けるキーは `a`〜`z` と `-`（長音「ー」）と Backspace。大文字小文字は区別しない。IME の変換は使わない |
| 綴り | 読みを「区切り」（1〜3 かな）ごとの綴りの候補で受け付ける（下の表）。区切り方が複数ある読み（「きゃ」＝`kya`／`ki`＋`xya`）も全て並べ、打った文字と矛盾しない道筋だけを残す。**どの道筋でも続かない文字は誤字** |
| ん | `nn`・`xn` はいつでも可。単独の `n` は、次の区切りの綴りが母音・`y`・`n` で始まらないときだけ（「かんたん」＝`kantann`、「かんい」＝`kanni`、「ほんや」＝`honnya`）。語末の「ん」は `nn`／`xn` のみ |
| っ | 次の区切りの綴りの先頭の子音を重ねる（`kitte`・`maccha`・`mattya`。`matcha` は不可）。母音・`n`・`-` で始まる区切りの前は重ねられない。単独は `xtu`・`ltu`・`xtsu`・`ltsu`。読みの最後の「っ」は単語帳で拒否する |
| 誤字 | 進行しない。誤字数を数え、連続正解（コンボ）を 0 に戻す。狙いは保つ |
| 狙い | 狙いがないとき、打った 1 文字を受け付ける敵のうち **最も手前**（出現からの Tick が多い）、同じなら出現順の早い敵を狙う。受け付ける敵がいなければ誤字。狙いがある間は、打鍵はその敵だけに効く（他の敵の言葉の文字は誤字）。打ち切ると倒し、狙いが外れる |
| Backspace | 狙いがあれば外し、その敵の進み具合を最初に戻す（別の綴りで打ち直せる）。誤字にも連続正解の途切れにも数えない。狙いがなければ何もしない |
| 出現 | 難度ごとの山（段の範囲の語を切り混ぜたもの）から引き、山が尽きるまで同じ語を出さない。画面にいる語は出さず、画面の敵と最初の 1 打の候補が重ならない語を山の上から優先する。列（横の位置）は空いた列から乱数で選ぶ |
| 被弾 | 敵が手前の線に着いた Tick に体力 −1、その敵は消える（狙っていれば外れる） |
| 勝敗 | 規定数を倒したらクリア。体力 0 で失敗。打鍵は Tick の間に反映するので、**同じ Tick なら打鍵の撃破 → 敵の前進 → 被弾**の順。規定数に届いた打鍵の時点でクリアになり、その後の Tick は進まない |
| 難度 | 下の表。体力 3、列 5。値は設定（`InkVigilSettings`）で変えられる |
| 得点 | 受け付けた 1 打ごとに 10 ×（1 ＋ 連続正解 ÷ 20 の整数部、最大 5）。倒すと読みのかな数 × 50 |
| 結果 | クリア／失敗、倒した数、受け付けた打鍵・誤字・正確さ（‰）、打鍵の速さ（受け付けた打鍵 / 分、遊んだ時間から）、最大の連続正解、得点。起動中の難度ごとの最高得点 |
| 乱数 | 1 試合 = 1 シードの xorshift（`SeededRandom`）。単語の山と出現（間隔・列）で系列を分ける。再戦は起動時の値から試合ごとに進めた新しいシード |
| 終了後 | クリア・失敗の後の打鍵と Tick は状態を変えない |

| 難度 | 出題の段 | 同時に出る数 | 手前まで | 出現の間隔 | 規定数 |
|---|---|---|---|---|---|
| やさしい | 1 | 2 | 600 Tick（10 秒） | 150〜210 Tick | 10 |
| ふつう | 1〜2 | 3 | 540 Tick（9 秒） | 120〜180 Tick | 15 |
| むずかしい | 2〜3 | 4 | 600 Tick（10 秒） | 120〜180 Tick | 20 |

既定値で一定間隔の操縦役を 20 シードずつ走らせると、勝てる打鍵の速さの下限はやさしい約 1 打/秒・ふつう約 2 打/秒・むずかしい約 4 打/秒（操縦役は反応の遅れがないので、人間はこれより速く打つ必要がある）。

### ローマ字の綴り

先頭が案内に使う既定の綴り。打った綴りに合わせて案内が変わる（「し」で `s` の次に `i` を打てば `si` の続き）。

| かな | 綴り | かな | 綴り |
|---|---|---|---|
| し | `shi` `si` `ci` | しゃ しゅ しょ | `sha` `sya`（ゅ・ょも同様） |
| ち | `chi` `ti` | ちゃ ちゅ ちょ | `cha` `tya` `cya` |
| つ | `tsu` `tu` | じゃ じゅ じょ | `ja` `zya` `jya` |
| ふ | `fu` `hu` | しぇ ちぇ じぇ | `she` `sye`／`che` `tye` `cye`／`je` `zye` `jye` |
| じ | `ji` `zi` | ふぁ ふぃ ふぇ ふぉ | `fa` `fi` `fe` `fo` |
| か く こ | `ka` `ca`／`ku` `cu` `qu`／`ko` `co` | てぃ でぃ うぃ うぇ | `thi`／`dhi`／`wi`／`we` |
| せ | `se` `ce` | きゃ など他の拗音 | `kya` `gya` `nya` `hya` `bya` `pya` `mya` `rya` `dya` |
| い う | `i` `yi`／`u` `wu` `whu` | ぁぃぅぇぉ | `xa` `la` など（`x`・`l` 始まり） |
| を | `wo` | ゃゅょゎ | `xya` `lya` など |
| ー | `-` | 拗音の分け打ち | 「きゃ」＝`ki`＋`xya` なども可 |

その他のかなは訓令式・ヘボン式で 1 通り（`ka` `ki` … `po`、ぢ `di`、づ `du`）。カタカナ・ゔ・ゐ・ゑは単語帳で使わない（使うと拒否する）。

## 設計上の選択

- **入力文字列と表示文の分離**：Core の照合（`RomajiMatcher`）は読み（`Reading`）だけを見て、表示文を知らない。表示文は単語帳（`WordEntry.Display`）にあり、描画だけが使う。
- **綴りの照合は非決定性の道筋の集合**：`Reading` が読みの各位置から打てる区切り（「ん＋次」「っ＋次」の結合を含む）を前もって並べ、`RomajiMatcher` は「区切りの開始位置・区切り・その中の打った長さ」の組を全て持つ。道筋の集合は打った文字列だけで決まるので、誤字は状態を何も変えない。テストでは、読みを表の単位に区切る全ての方法 × 全ての綴りを総当たりで並べて「ん」「っ」の条件で絞る別の組み立て方（参照実装）と、受け付ける文字列・途中の文字列の集合を全 50 語と境界の読みで照合する。
- **狙いは Core が持つ**：打鍵 1 つを「どの敵の何打目か」に解決する規則（最も手前・出現順）を `TypingRun` に置き、App・Unity は文字を渡すだけ。敵の照合は読み取り専用の窓口（`MatcherView`）で公開し、進めたり戻したりできるのは `TypingRun.Type`・`Backspace` だけ。テスト・撮影用の `Place` は敵のいる列には置かない。
- App（`VigilFlow`）は画面遷移・時刻付き打鍵の Tick への対応・フレーム単位の Tick 上限・遊んだ時間・最高得点を持つ。操縦役（`Typist`）は一定間隔で案内の先頭を打ち、割合を決めてわざと誤字を混ぜる。撮影と App テストで共有する。
- Unity（`InkVigilGame`）は文字キーと Backspace を 1 つの PassThrough のアクションで読み、同時押しでも押下ごとに 1 打にする。物理キーを読むので IME と配列の文字変換を通らない（プレイ中は IME も切る）。敵の位置・大きさは `InkVigilPerspective`（奥行き t で大きさ 1 / (1 + 3t)）だけで決め、札（UI Toolkit）は敵の頭の上を画面座標に直して置く。打鍵の案内と札は（試合・敵の番号・照合の版 `Revision`）が変わったときだけ書き換える（打った文字数ではなく版で決めるので、Backspace の後に別の綴りで同じ文字数まで打ち直しても書き換わる）。タイトルの難度の一覧は、印（▶）・難度名・最高得点を固定幅の列に分けて置き、選び直しても難度名が動かない。撃破の煙・被弾の閃光と揺れ・誤字の赤は、Core が残す最後の撃破・被弾・誤字の Tick から決め、撮影でも同じ絵になる（以後の動きに影響しないのでハッシュには入れない）。
- 描画は Stage Prefab（`Art/InkVigilStage.prefab`：回廊・手前の線・見張り・敵の置き場 5 つ・演出）を正とし、シーンは `unity run games/032-typing -- -executeMethod Game.Unity.Editor.InkVigilSceneBuilder.Build` で生成する（既存の Prefab と設定アセットは上書きしない）。絵は `InkVigilArtGenerator` が描く。難度の値・音量・演出の長さは `InkVigilSettings.asset` にある。

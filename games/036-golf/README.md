# 036. ゴルフ — BREEZEWAY LINKS（仮）

仕様書：[plan/games/036-golf.md](../../plan/games/036-golf.md)／実装計画：[plan/games/036-golf-implementation.md](../../plan/games/036-golf-implementation.md)

参考作品の名称・素材・演出は使わないオリジナル作品。真上から見た 3 ホール（par 3・4・5）を、向き・クラブ・打点を決めて 2 回押しのメーターで打ち、合計の打数を競う。

## 環境

- Unity：6000.6.9f1
- 対象プラットフォーム：Windows (StandaloneWindows64)
- 入力方式：キーボード（Input System）

## 起動手順

```
dev gui 036      # エディタで開く
dev build 036    # Windows ビルド
dev run 036      # ビルドを起動
dev capture 036  # 証跡を evidence/ に撮る（画像は captures/<画像世代>/、撮影記録は runs/）
```

## 操作

| キー | 動作 |
|---|---|
| ← → | 向きを変える（押し続けると繰り返す） |
| ↑ ↓ | クラブを替える（グリーンの上はパターだけ） |
| W A S D | 打点（球のどこを打つか）を上下左右へ |
| Space | スイング：振り始め → パワー → インパクト。タイトル・結果では開始 |
| Enter | 開始・再開・再戦 |
| Esc | 一時停止／再開、結果からタイトルへ |
| R | 一時停止中に新しいラウンドをやり直す |
| Backspace | 一時停止からタイトルへ |

## 採用ルール

| 項目 | 採用ルール |
|---|---|
| 時間 | 60 Tick/秒。入力はイベント時刻を含む Tick の境目に反映する（メーターの止めどころがフレームレートに依らない） |
| 単位・座標 | 整数。長さは µm（1 m = 1,000,000）、速度は µm/Tick。x はホールの奥へ、y は横、z は高さ。地面は z = 0 の平面で、起伏はなく、傾きはグリーンの転がりにだけ効く。浮動小数点を使わない |
| 地面 | 1 m のマスの格子。ラフ・フェアウェイ・ティー・グリーン・バンカー・池・OB（ホールの外も OB）。種類ごとに着地の鉛直の反発・水平の残り・転がりの減速・その場所から打つパワー（ライ）を持つ |
| クラブ | ウッド・アイアン・ウェッジ・パター。最大初速・打ち出し角・最初の着地の水平の残り（スピンの効き）だけを持つ。構えると、向きはカップへ、クラブは届く中で最も短いもの（グリーンの上はパター）を選ぶ |
| 打点 | 上下左右 5 段（−2〜+2）。下を打つと高く出てよく止まり、上を打つと低く出て転がる。左右は横のスピン（打点の向きへ曲がる）。パターでは効かない |
| メーター | Space で振り始め、ゲージは 0 → 100% → 0 を 90 Tick で往復。1 回目の押下でパワー（その Tick のゲージ）、戻りの 0 の Tick（90）の ±8 Tick のインパクト帯で 2 回目。ずれ e（Tick、負は早い）だけ曲がる（早いと左・遅いと右。パターは向きがずれる）。帯の外で押す・押さずに帯を過ぎる → ミスショット（ずれ ±8・パワー半分）。パワーを決めずに帯の手前へ来たら取り消し（打数に数えない） |
| 飛行 | 1 Tick に：抵抗（速度の 150/65536 を 0 方向へ）→ 風（風速の 413/65536 を足す）→ 横のスピン（進む向きの右へ一定の加速）→ 重力（9.8 m/s²）→ 移動 |
| 風 | ホールごとに一定（突風なし）。16 方位 × 0〜6 m/s を、ラウンドのシードからホールごとに別の系列で引く |
| 木 | 平面上の円柱（中心・半径・高さ）。1 Tick の経路を 256 等分した点の列とみなし、円の内側（距離 &lt; 半径）に入った最初の点が高さ以下なら横から当たる：その手前の点で水平の速度を反射して 1500/4096 に減らし、**その Tick の残りの点を新しい速度で計算し直す**（同じ木には 1 Tick に 1 回）。上から入ったら水平の速度を減らし鉛直の速度を 0 にして真下へ落とす |
| 着地 | 高さが 0 以下になる最初の点で着地。池・OB ならその打球は終わり。それ以外は鉛直の速さを反発で返し、水平の速さを減らす（最初の着地だけクラブと打点の残りを掛け、横のスピンは消える）。反発が 1 m/s 以下なら転がる。着地した Tick の残りは進めない |
| 転がり | 傾きの加速（g × 傾き × 5/7）を足し、地面の減速で遅くする。速さが小さく、傾きの加速が減速以下なら止まる（坂の上では止まらない）。地面の種類は Tick の始め・終わりの位置で決める |
| カップ | グリーン上の半径 54 mm の円。転がる球の点の列が円の外から内へ入った点で、その Tick の速さ（減速の後）が 1.2 m/s 以下なら入る。速ければ上を通り過ぎ、円から出るまで入らない（円の上で止まったら入る）。着地した点が円の内側で、着地後の水平の速さが上限以下でも入る。飛んでいる球は入らない |
| OB・池 | 地面に触れた位置（着地・転がりの終わり）が OB・池・ホールの外なら、その打球は終わり、**1 打罰を加えて前の位置から打ち直す**（池も OB と同じ扱い。救済の位置は採用しない）。OB の上を飛んで場内に落ちれば罰はない。1 打球で 1 回だけ数える |
| 打数 | 打った時点で +1、池・OB で +1。打数の上限は par + 5。上限に達したらそのホールは上限の打数で終わる |
| 1 打の上限 | 1 打は 3600 Tick（60 秒）まで。超えたらその場で止めたとみなす |
| 予測線 | 今の構えとパワー（パワーを決める前は 100%、決めた後はその値）・ずれ 0 で、実際と同じ関数で進めた最初の着地までの軌跡（木への衝突を含む）。パターは最初の 40 Tick だけ描く（傾きの読みを残す）。打った後、ずれ 0 の予測と実際の着地点（パターは止まった位置）の差を 1 打ごとに記録する |
| 終了・結果 | 3 ホールの後、スコアカード・合計とパー差・起動中の最少打数。終了後の入力は状態を変えない。再戦は新しいシード（ラウンドごとにシードを進める） |
| 乱数 | ホールごとの風だけ |

コースは [Assets/Game/Data/Course.txt](Assets/Game/Data/Course.txt) に置き、Core の `Course.Parse` が検証する（ちょうど 3 ホール、par 3〜5、ホールの大きさ、ティー・カップのマスの種類、カップがグリーンの端にかからない、木の大きさと位置（グリーン・OB の上やティー・カップの 3 m 以内に置かない）、傾きの大きさとグリーンの上か）。

## 設計上の選択

- **物理を Core の整数で持つ。** 中心課題の「投射軌道と地形摩擦のモデル化」を自前で書いてテストするため、Unity の物理は使わない。予測線と実際の球は同じ `BallSim.Step` で進むので、ずれ 0 なら全 Tick で一致する（テストで確かめる）。.NET と Mono（Unity）で同じ結果になる（操縦役のラウンドの最終ハッシュを固定値で照合）。
- **接触は 1 Tick の経路の点の列で決める。** int-geometry の `Sweep.First` は扱える値（`Sweep.FirstLimit`）が µm の座標に足りない。経路を 256 等分した点の列と定めると、判定は N 倍した座標の厳密な整数の比較だけになる。点の間隔は最大でも 2 m / 256 ≈ 8 mm なので、細い木も半径 54 mm のカップも 1 Tick で飛び越えない（1 Tick の移動の上限と円の半径の上限を設定とコースの検証で保証し、計算が long に収まる）。
- **木に当たったら、その Tick の残りを計算し直す。** 当たった点の手前から新しい速度で残りの点を進めるので、その Tick の中で別の木や地面に触れることも拾う。
- **カップは「入った点の速さ」で決める。** 円の中にいる間に遅くなって落ちる、という扱いにすると、上限 + 1 の速さでも次の Tick に入ってしまい、速さの条件が意味を失う。通り過ぎている途中（`OverCup`）は入らない。
- **App**：`GolfFlow`（画面遷移・時刻から Tick への変換・1 フレームの Tick 上限 5・向きのキーの繰り返し・一時停止とフォーカス喪失で振りを取り消す）、`Autopilot`（構えるたびにクラブ × 向き × パワーの候補を `Predictor.Finish` で打ってみて、池・OB を避けてカップに近いものを選ぶ。15% の確率でインパクトを 1 Tick ずらす）。

## 予測と実際の差分

ずれ 0 なら予測と実際は同じ `BallSim.Step` なので、着地点の差は 0（木を含む全 Tick の一致と、操縦役の 154 打で確かめた）。差は打った後に 1 打ごとに記録する。

平らなフェアウェイ（木なし・風なし）のティーから、パワー 100%・打点は中心・向きはまっすぐで打った着地点の、ずれ 0 からの距離（m）。± は早い側と遅い側の大きいほう。ミスはパワーを半分にし、ずれを 8 Tick にする。値は整数の計算なので .NET と Mono で同じ（`PredictionDifferenceTests` の出力）。

| クラブ | ずれ 0 | ±1 | ±2 | ±4 | ±8 | ミス |
|---|---:|---:|---:|---:|---:|---:|
| ウッド | 0.00 | 2.50 | 5.00 | 9.98 | 19.92 | 130.19 |
| アイアン | 0.00 | 3.08 | 6.14 | 12.26 | 24.44 | 103.10 |
| ウェッジ | 0.00 | 3.92 | 7.82 | 15.58 | 30.76 | 71.00 |

パターは着地せず転がる。ずれは向きそのものが変わり、2 Tick のずれで設定の角度の 2 倍だけ線が回る。

操縦役の 20 シード（3 ホール、全ホール par 以内、合計 164 打）。15% の確率でインパクトを ±1 Tick ずらす。ずれ 0 の 154 打は差 0。ずれ ±1 の 10 打は平均 2.07 m、最大 2.95 m。

予測線（ウッド、最初の着地まで）は p50 0.086 ms、p95 0.089 ms、最大 0.143 ms。飛んでいる球の Step は p95 0.001 ms。描画が実際の軌跡を打ち出しから進め直す更新は p50 0.125 ms、p95 0.212 ms。割り当ては 0 バイト。計測は Unity エディタのバッチ実行（Mono）、300 サンプル。`ProfilerRecorder` の「GC Allocated In Frame」で、4096 バイトを割り当てたフレームは 4458 バイトとして検出した。

## 再現性の範囲

- 物理は整数だけなので、同じシードと同じ操作なら .NET と Mono で軌道が一致する。シード 1 は 7 打・4086 Tick・最終ハッシュ 0x6E6BB7DA。
- 入力は起きた時刻を含む Tick に反映する。同じ操作を 30〜240fps と不規則な間隔で届けても状態は同じ。
- 乱数はホールごとの風だけで、ラウンドのシードからホールごとに別の系列で引く。再戦は起動時の値からシードを進める。
- 同じビルドの撮影は 11 枚の SHA-256 が一致する（[evidence/README.md](evidence/README.md)）。

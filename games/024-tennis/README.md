# 024. テニス — BASELINE BLOOM（仮）

仕様書：[plan/games/024-tennis.md](../../plan/games/024-tennis.md)　実装計画：[plan/games/024-tennis-implementation.md](../../plan/games/024-tennis-implementation.md)

CPU と 1 セットを戦うシングルスのテニス。斜め上から見下ろしたコートで、球の高さは影との離れで表す。打つ時機が早いか遅いかで球筋が変わり、CPU は球の着地点を予測して動く。参考作品からはメカニクスだけを採用し、名称と見た目は独自に作る。

## 環境

- Unity：6000.6.9f1（Universal 2D、C# 9.0）
- 対象プラットフォーム：Windows (StandaloneWindows64)
- 入力方式：Input System のキーボード。HUD は PanelRenderer / UI Toolkit
- 共通パッケージ：[com.games100.tile-motion](../../packages/com.games100.tile-motion/)（`Countdown`・`StateHash` だけを使う）

## 採用ルール

| 項目 | 採用ルール |
|---|---|
| 単位 | 長さは整数（1 単位 = 0.1 mm）、速さは単位/Tick、60 Tick/秒。時間の設定は Tick 数。浮動小数点を使わないので Mono と .NET で同じ結果になる |
| 座標 | x：横（センターが 0、右が正）、y：縦（ネットが 0、プレイヤーは手前 y < 0）、z：高さ（球の下端）。シングルスのコート 23.77 × 8.23 m、サービスライン 6.40 m、ネットの高さ 0.914 m（幅全体で一定、ポストの外を回る球はない） |
| コートチェンジ | しない。プレイヤーは常に手前（風・日差しがないので勝敗に影響しない） |
| 球 | 1 Tick：重力（9.8 m/s² ≒ 27 単位/Tick²）で縦の速さを減らしてから位置に足す。その線分の中でネットの面と地面のどちらに先に触れるかを割合で求める。地面に触れた位置で弾み（縦は 72%、横は 70% が残る）、残りの割合を新しい速さで進む。**空気抵抗・回転はない**（仕様書の Out of scope） |
| ネット | ネットの面（y = 0）を通るときの高さがネットより低ければネット。その位置で止まる（死に球）。打った側の失点、サーブならフォルト。レットは採用しない |
| ライン | 弾んだ位置（球の中心の真下）がライン上ならイン |
| ラリーの判定 | 最初のバウンドが相手のシングルスのコートの外（打った側のコートを含む）→ 打った側の失点（OUT）。相手のコートで 2 回目のバウンド → 受けた側の失点（2 BOUNCES）。1 回弾んだ球が壁の線（ベースラインの 6 m 後ろ・サイドラインの 4 m 外）を越える → 受けた側の失点（NOT UP）。ラリー中のボレー（バウンド前に打つ）はできる |
| サーブ | サーバーはポイント数の和が偶数ならデュースサイド（自分の右）、奇数ならアドサイドのベースラインの後ろに立つ。ストロークのキーでトスを上げ、トス中にもう一度押して打つ。頂点から ±12 Tick の間だけ当たり、外れると空振り（打ち直せない）。打たずにトスが落ちたら持ち直す（フォルトにしない）。対角のサービスボックス（ライン上を含む）に入らなければフォルト、2 本続けばダブルフォルト。サーブはバウンドする前に打ち返せない |
| 打点ウィンドウ | 振りは押した Tick から 24 Tick。押してから 8 Tick 目（打点）に、球が届く範囲（水平 1.3 m 以内）・打てる高さ（0.1〜2.2 m）にあり、自分の側にあって自分へ向かっていれば打つ。そうでなければ空振り。振りの途中は次を振れず、移動は 40% に遅くなる |
| 早打ち・遅打ち | 打点で、球が理想の打点（体の 0.5 m 前）よりネット寄りなら早打ち、後ろなら遅打ち。1.2 m のずれで最大（±1000‰）。早打ちほど打つ人の左（引っ張り）へ・長く（最大 +4 m 横・+3.6 m 深く）、遅打ちほど右（流し）へ・ネットの余裕が小さく（最大 −0.9 m）なり、アウトやネットになる |
| ショット | 狙う着地点：ストロークは深さ 8.5 m、ロブは 9.5 m。振った瞬間に ← → を押していれば横 2.6 m に狙う。初速は「最高速（ストローク 40 m/s・ロブ 15 m/s）以下で、ネットの面を通る高さがネット＋余裕（ストローク 0.5 m・ロブ 3 m）以上になる、いちばん平らな弾道」を整数で解く |
| サーブの球筋 | 狙いはサービスボックスの中央（深さ 5.5 m）、← → で ±1.3 m。頂点で打てば入る。早いほど長く（フォルト）、遅いほど短く低く（ネット） |
| 移動 | 自分の側（ネットから 1 m 以上離れ、壁の線の 0.5 m 内側）を 8 方向に。プレイヤー 5.5 m/s、CPU 5.1 m/s。斜めは各成分を 181/256 倍（最低 1） |
| 得点 | 既定は **7 ポイント先取（2 点差）の 1 ゲームだけの 1 セット**（`TiebreakAtGames = 0`）。設定で通常の 1 セットにできる：T ゲームを 2 差で取れば勝ち、T-T でタイブレーク（T = 6 なら 6-4・7-5・7-6）。通常のゲームは 0・15・30・40・デュース・アドバンテージ |
| サーブ順 | 通常のゲームはゲームごとに交代。タイブレーク（既定の試合を含む）は最初の 1 点を A、以後 2 点ごとに交代（A・BB・AA・…）。最初のサーバーはプレイヤー |
| ポイントの間 | 判定を 90 Tick 見せてから、次のポイント（または試合終了）。押したままのキーで次のトスは上がらない（押し始めでしか振らない） |
| CPU | 相手が打ってから 8 Tick 後に、球を複製して本番と同じ `Ball.Step` で軌跡を予測する。最初のバウンドがアウト（サーブならボックスの外）かネットなら見送る。1 回弾んだ後に打てる高さにある Tick のうち、理想の打点にできる位置へ間に合うもの（下りてくるものを優先）を選び、そこへ動いて打点の 8 Tick 前 ±2 Tick に振る。狙いは左・中・右から乱数、相手がネットから 5 m 以内なら必ずロブ、そうでなければ 12% でロブ。打った後はベースラインの中央へ戻る |
| 1 Tick の順序 | 押し始めの判定（サーブ待ちならトス、トス中ならサーブ、打ち合いなら振り始め）→ 移動 → 球の 1 Tick と判定（トスが落ちたら持ち直す、打ち合いならネット・バウンド・壁の線）→ 打点の Tick の選手の当たり判定と打球 → 振りを進める → ポイントが決まっていれば得点を入れて間を置く |
| 時刻と Tick | 022・023 と同じ。入力は起きた時刻を持ち、その時刻を含む Tick から効く（打点の時機がフレームレートに依らない）。1 フレームで進めるのは入力と時計で合わせて 5 Tick まで |
| 乱数 | CPU だけが使う。1 試合 = 1 シードの xorshift で、判断（時機のぶれ・狙い・ロブ）とサーブで系列を分ける。再戦は起動時の値から 1 ずつ進めたシード |
| 終了後 | 試合が終わった後の Tick と入力は状態を変えない |

## 設計上の選択

| 層 | 責務 |
|---|---|
| Core | `Units`・`Vec3`、`Court`・`Positions`（寸法・内外・サービスボックス・立ち位置）、`Ball`（1 Tick の軌跡とネット・バウンド）、`ShotSolver`・`Shots`（狙いと時機から初速）、`HitWindow`（打点の判定とずれ）、`Athlete`、`Rally`（1 ポイントの状態機械）、`MatchScore`（得点・ゲーム・タイブレーク・サーブ順の状態機械）、`BallPredictor`（着地点・打点の予測）、`CpuBrain`、`TennisMatch`（試合の 1 Tick）、`TennisConfig`・`ShotCheck`（設定と検証） |
| App | `TennisFlow`（画面遷移・時刻付きの入力から Tick への対応・再戦のシード）、`Intent`・`HeldControls`、`Autopilot`（手前を `CpuBrain` で動かす撮影・テスト用の操縦役）、`ScoreBoard`（得点と判定の表示文字） |

- **物理エンジンには何も委譲しない。** 球は整数の放物運動と、Tick の中で触れた割合で求めるネット・バウンド。
- **予測と実際を同じ関数にする。** CPU の着地点予測は球を複製して `Ball.Step` で進めるだけなので、誰も打たなければ予測と実際の軌跡は Tick 単位で一致する（テストで照合）。
- **ポイント（`Rally`）と得点（`MatchScore`）を別の状態機械にする。** `Rally` は球の出来事を判定に変え、`MatchScore` は勝者を受けて得点・サーブ順を進める。得点の規則（通常のゲーム・タイブレーク・セット）はラリーと無関係にテストできる。
- **打点は「押してから決まった Tick」にする。** 球が範囲に入った最初の Tick に自動で当てると、早く押すほど常に早打ちになり時機の意味が薄れる。押す時機がそのまま打点の位置になり、早打ち・遅打ちが操作で選べる。
- **ずれの効き方を向きで分ける。** 早打ちは長く（アウト）、遅打ちは低く（ネット）なる。サーブは高い打点から打つので、余裕を減らすだけではネットにかからず、遅いほど短く狙わせて急に落とす。
- **設定の検証で「狙いどおりに打てば入る」を実際に飛ばして確かめる（`ShotCheck`）。** コートの手前・中・ネット際、左・中・右、低い・高い打点から、ストローク・ロブを左・中・右に打ち、両方の側・両方のコートからサーブを打つ。1 Tick の球の移動が届く範囲より小さいこと（打点を飛び越えない）も確かめる。
- **CPU の強さは打点の時機のぶれで決める。** CPU どうしの試合で、ぶれ ±1 Tick ではラリーが平均 129 本続いて終わらず、±2 Tick で平均 5 本（ネット・アウト・返せないが混ざる）、±3 Tick で 2.5 本だった。既定は ±2。

## テスト

| 種類 | 場所 | 件数 | 実行 |
|---|---|---|---|
| Core | `Assets/Tests/Core/` | 134 | `dev test`（.NET）／`dev test 024 -Unity`（Mono） |
| App | `Assets/Tests/App/` | 18 | 同上 |

- 題材固有：
  - ネット・アウト・ツーバウンドで正しく失点（`RallyRuleTests`）：判定ごとの勝者、ラインちょうどはイン・1 単位外はアウト、壁の線、打った側のコートへの落下、サーブのボックス（対角・ライン上・サービスラインの外）とフォルト・ダブルフォルト、トスを落としてもフォルトにならない。試合の中で、実際に飛ばした球がネット・アウト・返せない・遅いサーブ 2 本でダブルフォルト・早いサーブで長いフォルトになる。
  - 得点後にサーブ権が更新（`ScoreTests`）：タイブレークの A・BB・AA、サーブのコートの交互、通常のゲームのデュースとアドバンテージ、ゲームごとのサーバーの交代、6-4・7-5・6-5 は未決・6-6 からタイブレーク、試合の中でポイントのたびにサーバー・コート・立ち位置が変わる。
  - 届かない球を打てない（`HitWindowTests`）：届く範囲・高さの境界ちょうどは打て、1 単位外は打てない。離れていく球・ネットの向こうの球・自分が打った球・バウンド前のサーブは打てない。試合の中で、届かない位置で振ると空振りし、届けば返る。振りの途中に振り直せない。
  - 早打ちと遅打ちで球筋が変化（`HitWindowTests`）：同じ入球を 2 Tick 早く・遅く打つと、着地が左（引っ張り）・右に分かれ、早打ちは長くなる。ずれ 0 は狙いの 0.1 m 以内に落ちる。最大の遅打ちはネット、最大の早打ちはアウト。ロブはストロークより 2 m 以上高い。
- 予測（`BallTests`）：ストローク・ロブ各 100 本（狙い・時機・打点は乱数）で予測と実際のバウンドの Tick・位置が一致。予測はアウトになる球を見送る。
- 完走（`MatchTests`）：CPU どうしで 50 シードの既定の試合と、通常の 1 セット 2 シードが決着し、スコアが規則どおり。シード 1 の最終状態のハッシュ `0x2A9FD882` を .NET と Mono の両方で照合する。同じシードと入力で同じハッシュ、複製から続けても同じ。
- 画面遷移（`TennisFlowTests`）：タイトル → 試合 → 結果 → 再戦（シードが進む）、結果では進まない、時刻を含む Tick から入力が効く、短い押下、処理落ちの上限、一時停止とフォーカス喪失でキーを持ち越さない、30・60・144・240fps と不規則な間隔で同じキー操作が同じハッシュ、途中でやめた試合の後でも自動操縦が同じ結果。

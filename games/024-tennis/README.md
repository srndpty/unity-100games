# 024. テニス — BASELINE BLOOM（仮）

仕様書：[plan/games/024-tennis.md](../../plan/games/024-tennis.md)　実装計画：[plan/games/024-tennis-implementation.md](../../plan/games/024-tennis-implementation.md)

CPU と 1 セットを戦うシングルスのテニス。斜め上から見下ろしたコートで、球の高さは影との離れで表す。打つ時機が早いか遅いかで球筋が変わり、CPU は球の着地点を予測して動く。参考作品からはメカニクスだけを採用し、名称と見た目は独自に作る。

## 環境

- Unity：6000.6.9f1（Universal 2D、C# 9.0）
- 対象プラットフォーム：Windows (StandaloneWindows64)
- 入力方式：Input System のキーボード。HUD は PanelRenderer / UI Toolkit
- 共通パッケージ：[com.games100.tile-motion](../../packages/com.games100.tile-motion/)（`Countdown`・`StateHash` だけを使う）

## 採用ルール

| 項目 | 採用ルール |
|---|---|
| 単位 | 長さは整数（1 単位 = 0.1 mm）、速さは単位/Tick、60 Tick/秒。時間の設定は Tick 数。浮動小数点を使わないので Mono と .NET で同じ結果になる |
| 座標 | x：横（センターが 0、右が正）、y：縦（ネットが 0、プレイヤーは手前 y < 0）、z：高さ（球の下端）。シングルスのコート 23.77 × 8.23 m、サービスライン 6.40 m、ネットの高さ 0.914 m（幅全体で一定、ポストの外を回る球はない） |
| コートチェンジ | しない。プレイヤーは常に手前（風・日差しがないので勝敗に影響しない） |
| 球 | 1 Tick：重力（9.8 m/s² ≒ 27 単位/Tick²）で縦の速さを減らしてから位置に足す。その線分の中でネットの面と地面のどちらに先に触れるかを割合で求める。地面に触れた位置で弾み（縦は 72%、横は 70% が残る）、残りの割合を新しい速さで進む。**空気抵抗・回転はない**（仕様書の Out of scope） |
| ネット | ネットの面（y = 0）を通るときの高さがネットより低ければネット。その位置で止まる（死に球）。打った側の失点、サーブならフォルト。レットは採用しない |
| ライン | 弾んだ位置（球の中心の真下）がライン上ならイン |
| ラリーの判定 | 最初のバウンドが相手のシングルスのコートの外（打った側のコートを含む）→ 打った側の失点（OUT）。相手のコートで 2 回目のバウンド → 受けた側の失点（2 BOUNCES）。1 回弾んだ球が壁の線（ベースラインの 6 m 後ろ・サイドラインの 4 m 外）を越える → 受けた側の失点（NOT UP）。ラリー中のボレー（バウンド前に打つ）はできる |
| サーブ | サーバーはポイント数の和が偶数ならデュースサイド（自分の右）、奇数ならアドサイドのベースラインの後ろに立つ。トスを上げるまでは ← → でセンターマークの 0.3 m 外からサイドラインまで横に動いて立ち位置を選べる（球も手と一緒に動く）。ストロークのキーでトスを上げ、トス中にもう一度押して打つ。頂点から ±20 Tick の間だけ当たり、外れると空振り（打ち直せない）。打たずにトスが落ちたら持ち直す（フォルトにしない）。対角のサービスボックス（ライン上を含む）に入らなければフォルト、2 本続けばダブルフォルト。サーブはバウンドする前に打ち返せない |
| 打点ウィンドウ | 押すと構える。押した Tick に球が届く範囲（理想の打点＝体の 0.5 m 前から水平 1.8 m 以内）・打てる高さ（0.1〜2.6 m）にあり、自分の側にあって自分へ向かっていれば、その場で打つ。まだ向かってくる途中なら構えたまま最大 90 Tick 待ち、球が理想の打点に来たら打つ。届かないまま通り過ぎた・待ちきれなかったら空振り。**球が体の周りを通るなら、押す時機によらず必ず返る**（ネット・アウトはありうる）。打った後は 16 Tick 振り抜き、その間は次を振れず移動が 40% に遅くなる（構えている間はふつうに動ける） |
| 早打ち・遅打ち | その場で打ったとき、球が理想の打点よりネット寄りなら早打ち、後ろなら遅打ち。1.8 m のずれ（届く範囲の端）で最大（±1000‰）。早打ちほど打つ人の左（引っ張り）へ・長く（最大 +3 m 横・+3.6 m 深く）、遅打ちほど右（流し）へ・短く（最大 −8 m）なり、アウトやネットになる。**プレイヤーのずれ（サーブを含む）は補助で 50% に弱める**（CPU は 100%）。補助の後のずれでは、真ん中を狙えば必ず入り、左右に狙ったときの大きなずれだけがアウトになる |
| ショット | 狙う着地点：ストロークは深さ 8.5 m、ロブは 9.5 m。押した瞬間に ← → を押していれば横 2.6 m に狙う。飛行 Tick 数は「ずれ 0 の狙いへ、最高速（ストローク 40 m/s・ロブ 15 m/s）以下で、ネットの面を通る高さがネット＋余裕（ストローク 0.5 m・ロブ 3 m）以上になる、いちばん平らな弾道」で決め、ずれのある球も同じ時間で飛ぶ（時機で球の速さは変わらない）。初速は整数で解く |
| サーブの球筋 | 狙いはサービスボックスの中央（深さ 5.5 m）、← → で ±1.3 m。頂点で打てば入る。早いほど長く（フォルト）、遅いほど短く（最大 −5 m、ネット）。プレイヤーは補助があるので、頂点の 18 Tick 前から 14 Tick 後まで入る |
| 移動 | 自分の側（ネットから 1 m 以上離れ、壁の線の 0.5 m 内側）を 8 方向に。プレイヤー 5.5 m/s、CPU 5.1 m/s。斜めは各成分を 181/256 倍（最低 1） |
| 得点 | 既定は **7 ポイント先取（2 点差）の 1 ゲームだけの 1 セット**（`TiebreakAtGames = 0`）。設定で通常の 1 セットにできる：T ゲームを 2 差で取れば勝ち、T-T でタイブレーク（T = 6 なら 6-4・7-5・7-6）。通常のゲームは 0・15・30・40・デュース・アドバンテージ |
| サーブ順 | 通常のゲームはゲームごとに交代。タイブレーク（既定の試合を含む）は最初の 1 点を A、以後 2 点ごとに交代（A・BB・AA・…）。最初のサーバーはプレイヤー |
| ポイントの間 | 判定を 90 Tick 見せてから、次のポイント（または試合終了）。押したままのキーで次のトスは上がらない（押し始めでしか振らない） |
| CPU | 相手が打ってから 8 Tick 後に、球を複製して本番と同じ `Ball.Step` で軌跡を予測する。最初のバウンドがアウト（サーブならボックスの外）かネットなら見送る。1 回弾んだ後に打てる高さにある Tick のうち、理想の打点にできる位置へ間に合うもの（下りてくるものを優先）を選び、そこへ動いて、球が打点に来る Tick ±5 Tick（乱数）に押す（早い分は構えて待つので、ミスは遅れたとき）。狙いは左・中・右から乱数、相手がネットから 5 m 以内なら必ずロブ、そうでなければ 12% でロブ。打った後はベースラインの中央へ戻る |
| 1 Tick の順序 | 押し始めの判定（サーブ待ちならトス、トス中ならサーブ、打ち合いなら構える）→ 移動（サーブ待ちのサーバーは横だけ）→ 球の 1 Tick と判定（トスが落ちたら持ち直す、打ち合いならネット・バウンド・壁の線）→ 構えている選手の当たり判定と打球 → 振りを進める → ポイントが決まっていれば得点を入れて間を置く |
| 時刻と Tick | 022・023 と同じ。入力は起きた時刻を持ち、その時刻を含む Tick から効く（打点の時機がフレームレートに依らない）。1 フレームで進めるのは入力と時計で合わせて 5 Tick まで |
| 乱数 | CPU だけが使う。1 試合 = 1 シードの xorshift で、判断（時機のぶれ・狙い・ロブ）とサーブで系列を分ける。再戦は起動時の値から 1 ずつ進めたシード |
| 終了後 | 試合が終わった後の Tick と入力は状態を変えない |

## 設計上の選択

| 層 | 責務 |
|---|---|
| Core | `Units`・`Vec3`、`Court`・`Positions`（寸法・内外・サービスボックス・立ち位置）、`Ball`（1 Tick の軌跡とネット・バウンド）、`ShotSolver`・`Shots`（狙いと時機から初速）、`HitWindow`（打点の判定とずれ）、`Athlete`、`Rally`（1 ポイントの状態機械）、`MatchScore`（得点・ゲーム・タイブレーク・サーブ順の状態機械）、`BallPredictor`（着地点・打点の予測）、`CpuBrain`、`TennisMatch`（試合の 1 Tick）、`TennisConfig`・`ShotCheck`（設定と検証） |
| App | `TennisFlow`（画面遷移・時刻付きの入力から Tick への対応・再戦のシード）、`Intent`・`HeldControls`、`Autopilot`（手前を `CpuBrain` で動かす撮影・テスト用の操縦役）、`ScoreBoard`（得点と判定の表示文字） |
| Unity | `CourtProjection`（Core の座標 → 斜め見下ろしの画面）、`BaselineBloomGame`（時刻付きの入力・カメラ・HUD・案内・音）、`BaselineBloomStage`（コート・ネット・両選手・球・影・バウンドの跡）、`BaselineBloomSettings`（設定アセット）、`BaselineBloomArtGenerator`・`BaselineBloomSceneBuilder`（素材・Stage Prefab・シーンの生成）、`BaselineBloomCaptureScenario`（撮影台本） |

- **物理エンジンには何も委譲しない。** 球は整数の放物運動と、Tick の中で触れた割合で求めるネット・バウンド。
- **予測と実際を同じ関数にする。** CPU の着地点予測は球を複製して `Ball.Step` で進めるだけなので、誰も打たなければ予測と実際の軌跡は Tick 単位で一致する（テストで照合）。
- **ポイント（`Rally`）と得点（`MatchScore`）を別の状態機械にする。** `Rally` は球の出来事を判定に変え、`MatchScore` は勝者を受けて得点・サーブ順を進める。得点の規則（通常のゲーム・タイブレーク・セット）はラリーと無関係にテストできる。
- **押すと構え、球が来たら打つ。** 1 回目は「押してから 8 Tick 目に打点」で、早打ち・遅打ちが押す時機だけで決まったが、試遊で難しすぎるとされた。マリオテニスを手本に、球が来る前に押せば構えて待って理想の打点で打ち、球が届く範囲に入ってから押せばその場で打つ（早打ち・遅打ち）ようにした。球が体の周りを通るなら、押す時機によらず必ず返る。
- **ずれは着地点だけを変え、飛ぶ時間は変えない。** 1 回目は遅打ちでネットの余裕を減らしていたが、余裕が小さいほど平らで速い弾道になり、補助のない CPU の球が速く見えた（実測で CPU 25.4 m/s・プレイヤー側 23.9 m/s）。飛ぶ時間をずれ 0 の弾道で決め、遅打ちは同じ時間で手前に落ちる（低くなってネットにかかりうる）ようにして、どちらも約 22 m/s にそろえた。
- **設定の検証で「狙いどおりに打てば入る」を実際に飛ばして確かめる（`ShotCheck`）。** コートの手前・中・ネット際、左・中・右、低い・高い打点から、ストローク・ロブを左・中・右に打ち、両方の側・両方のコートからサーブを打つ。1 Tick の球の移動が届く範囲より小さいこと（打点を飛び越えない）も確かめる。
- **届く範囲を理想の打点を中心にした円にする。** 体を中心にすると、体の前に理想の打点があるぶん早打ち側が狭く、早打ちのずれが大きくならなかった。半径は試遊を受けて 1.3 m から 1.8 m に広げ、体の正面や少し離れた球も返せるようにした。
- **CPU の強さは打点の時機のぶれで決める。** プレイヤー側を補助つきの自動操縦にした 20 試合で、ぶれ ±4 Tick ではラリーが平均 31 本、±5 Tick で 15 本（1 試合約 3 分、CPU のネット・アウトが主な失点）、±6 Tick で 8 本だった。既定は ±5。
- **斜め見下ろしは 1 つの式（`CourtProjection`）で描く。** 縦を 0.46 倍に縮め、高さを上へずらし、奥ほど少し小さくする。コートの絵は生成スクリプトが画素ごとに同じ式の逆で地面へ戻して塗るので、線の位置と球・選手の位置が食い違わない。手前ほど前に描く（描く順を y から決める）ので、ネットの向こうの球はネットの後ろに見える。
- **選手と球は実寸より大きく描く（1.35 倍・1.6 倍）。** 当たり判定は Core の値のままで、見やすさのためだけ。
- **案内は試合の Tick で消す。** 打ったときの「ちょうど／少し早い／遅い」（補助の後のずれ 150‰ 未満・350‰ 未満・それ以上）と、サーブの手順（「Z でトス」「頂点でもう一度 Z」）。2 本目のサーブの前は FAULT、ポイントの間は判定と得点した側を出す。

## テスト

| 種類 | 場所 | 件数 | 実行 |
|---|---|---|---|
| Core | `Assets/Tests/Core/` | 141 | `dev test`（.NET）／`dev test 024 -Unity`（Mono） |
| App | `Assets/Tests/App/` | 18 | 同上 |
| パッケージ | `packages/com.games100.tile-motion/Tests/` | 10 | `dev test 024 -Unity`（Mono） |
| PlayMode | `Assets/Tests/Unity/` | 33（実シーン 17、共通証跡公開 16） | `dev test 024 -Unity -Mode PlayMode` |

- 題材固有：
  - ネット・アウト・ツーバウンドで正しく失点（`RallyRuleTests`）：判定ごとの勝者、ラインちょうどはイン・1 単位外はアウト、壁の線、打った側のコートへの落下、サーブのボックス（対角・ライン上・サービスラインの外）とフォルト・ダブルフォルト、トスを落としてもフォルトにならない。試合の中で、実際に飛ばした球がネット・アウト・返せない・遅いサーブ 2 本でダブルフォルト・早いサーブで長いフォルトになる。
  - 得点後にサーブ権が更新（`ScoreTests`）：タイブレークの A・BB・AA、サーブのコートの交互、通常のゲームのデュースとアドバンテージ、ゲームごとのサーバーの交代、6-4・7-5・6-5 は未決・6-6 からタイブレーク、試合の中でポイントのたびにサーバー・コート・立ち位置が変わる。
  - 届かない球を打てない（`HitWindowTests`）：届く範囲・高さの境界ちょうどは打て、1 単位外は打てない。離れていく球・ネットの向こうの球・自分が打った球・バウンド前のサーブは打てない。試合の中で、届かない位置で構えると球が通り過ぎて空振りし、構え直しはできない。球が向かってくる間のどの Tick に押しても返る（届く範囲を通り過ぎる前まで）。早く押すと構えて待ち理想の打点で打ち、待ちきれないと空振りする。体の真横に来てから押しても返る。
  - 早打ちと遅打ちで球筋が変化（`HitWindowTests`）：同じ入球を 2 Tick 早く・遅く打つと、着地が左（引っ張り）・右に分かれ、早打ちは長くなる。ずれがあっても飛ぶ時間は同じ。ずれ 0 は狙いの 0.1 m 以内に落ちる。最大の遅打ちはネット、最大の早打ちはアウト。ロブはストロークより 2 m 以上高い。プレイヤーのずれは補助で半分になり、CPU はそのまま。
- 予測（`BallTests`）：ストローク・ロブ各 100 本（狙い・時機・打点は乱数）で予測と実際のバウンドの Tick・位置が一致。予測はアウトになる球を見送る。
- 完走（`MatchTests`）：CPU どうしで 50 シードの既定の試合と、通常の 1 セット 2 シードが決着し、スコアが規則どおり。シード 1 の最終状態のハッシュ `0x346EBABB` を .NET と Mono の両方で照合する。同じシードと入力で同じハッシュ、複製から続けても同じ。
- 実シーン（`BaselineBloomSceneTests`）：サーブ待ちのサーバーは ← → で横にだけ動き球も手と一緒に動く、Z でトス・頂点近くでもう一度 Z でサーブ、レシーバーは ← で動き離すと止まる、届く球は Z で返り時機の案内が出る、届かない球は返らない、X のロブは高い、アウトの判定と跡と得点板、ネットの向こうの球はネットの後ろに描く、自動操縦で結果の画面まで進み最後の得点が出る、タイトルへ戻った表示が起動直後と一致、一時停止・HUD のボタン・フォーカスの喪失、設定アセットの値で決着する。
- 画面遷移（`TennisFlowTests`）：タイトル → 試合 → 結果 → 再戦（シードが進む）、結果では進まない、時刻を含む Tick から入力が効く、短い押下、処理落ちの上限、一時停止とフォーカス喪失でキーを持ち越さない、30・60・144・240fps と不規則な間隔で同じキー操作が同じハッシュ、途中でやめた試合の後でも自動操縦が同じ結果。

証跡と検証の記録は [evidence/README.md](evidence/README.md)。

## 未実装範囲

- 仕様書の Out of scope：ダブルス、回転空力の精密モデル、アセットの大量制作・追加ステージ量産・製品化要素。
- 球の回転・空気抵抗・ネットに触れて越える球（ネットコード）・レット・ポストの外を回る球はない。
- フォアハンドとバックハンドの区別はない（どちらの側の球も同じ打ち方）。
- コートチェンジはしない。

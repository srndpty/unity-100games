# 018. ソリティア — SEVEN LANTERNS

仕様書：[plan/games/018-solitaire.md](../../plan/games/018-solitaire.md)　実装計画：[plan/games/018-solitaire-implementation.md](../../plan/games/018-solitaire-implementation.md)

7 列の灯籠の下に伏せた札を開きながら、4 つのスートをそれぞれ A から K まで組札に積み上げる1人用のカードゲーム。参考作品（Klondike）からはメカニクスだけを採用し、名称、絵、配色、音は独自に作る。スートは一般的なハート・ダイヤ（赤）とクラブ・スペード（黒）で、赤と黒の 2 色で描く（試遊で、独自の 4 種の印と朱・紅の色分けは紛らわしいとの指摘を受けて変更）。

## 環境

- Unity：6000.6.9f1（Universal 2D、C# 9.0）
- 対象プラットフォーム：Windows (StandaloneWindows64)
- 入力方式：Input System のマウスとキーボード。札の操作はマウスだけ（ドラッグ＆ドロップ、クリック→クリック、ダブルクリック）。キーボードは取り消し・一時停止・画面遷移。HUD は PanelRenderer / UI Toolkit。日本語は Windows の Yu Gothic で表示する

## 採用ルール

| 項目 | 採用ルール |
|---|---|
| 札 | 52 枚（4 スート × A〜K）。赤＝ハート・ダイヤ、黒＝クラブ・スペード |
| 配札 | 試合のシードでシャッフルし、場札 7 列へ 1〜7 枚を 1 段ずつ左から配る。各列の一番上だけ表。残り 24 枚が山札（全部伏せ） |
| 山札 | クリックで 1 枚（設定で 3 枚、足りなければ残り全部）を 1 枚ずつ表にして捨て札へ積む。山札が空ならクリックで捨て札を全部伏せて戻す（元の山札と同じ並び、回数無制限） |
| 捨て札 | 一番上の 1 枚だけ動かせる（3 枚めくりでも同じ） |
| 組札 | 4 つ。空の組札にはどのスートの A も置ける。以後は同じスートで 1 つ上のランクを 1 枚ずつ置く |
| 場札 | 表の札は、色違いで 1 つ上のランクの上へ置ける。空の列には K だけ。表の札の連続（列の途中から上全部）をまとめて動かせる。伏せ札は動かせない |
| 組札から場札 | 一番上の 1 枚を場札の規則どおりに戻せる。組札から組札へは動かさない |
| 自動で開く | 移動で列の一番上が伏せ札になったら、同じコマンドの中で表にする |
| 取り消し | 回数無制限。めくり・戻し・移動（自動で開いた札を伏せ直すことも含む）を 1 手ずつ戻す。手数も 1 減る。試合が終わった後はできない |
| 手数 | 成立したコマンドで +1、取り消しで -1 |
| 勝利 | 52 枚がすべて組札に入ったら勝利 |
| 手詰まり | 下記の探索で前進できないと確定したら、その場で試合を終える（結果画面） |
| あきらめる | 一時停止から選ぶと試合を終える（結果画面） |
| 自動で仕上げる | 山札と捨て札が空で、場札に伏せ札がなくなると「自動で仕上げる」ボタンを出す。押すと、組札へ送れる場札の一番上の札のうちランクの最も小さいものを、一定の間隔（既定 5 Tick）で 1 枚ずつ送る。この状態からは必ず勝てる（下記）。送っている間は札の操作と取り消しを受け付けず、一時停止中は止まる |
| 再戦 | 試合ごとに新しいシード |

### 手詰まりの判定

「前進」を、組札の枚数が増える・伏せ札が開く・山札と捨て札の合計が減る、のどれかとする。どれも元に戻せない変化で、勝つまでに必ずどれかが起きる。そこで、コマンドを適用するたびに今の局面から合法な全コマンド（めくり・戻し・組札から場札も含む）で局面を深さ優先に調べ、前進できる局面に届かなければ手詰まり＝その盤はもう勝てない、と判定する。

- 各局面では、潜る前にその局面の合法手のどれかが前進になるかを先に見る。
- 同じ局面は 1 回だけ調べる。場札の列どうし・組札どうしの並べ替えは同じ局面とみなす。
- 調べる局面数には上限（設定、既定 2,000）がある。超えたら手詰まりとはしない。まだ勝てる盤を手詰まりと判定しない側に倒し、見逃した手詰まりは次の手の後に判定されるか、あきらめるで終える。
- 乱数で遊んで手詰まりと判定された局面を、同一視をしない素朴な幅優先探索でも照合している（テスト）。

### 自動で仕上げる

山札と捨て札が空で、場札に伏せ札がなければ必ず勝てる。場札の各列は色違いで 1 つずつ下がる並びなので、残っている札のうち最も小さいランクの札は、その上に乗れるより小さい札がなく、どこかの列の一番上にある。そのスートの組札は 1 つ下まで積み終わっているので、その札を組札へ送れる。これを繰り返すと 52 枚が入る。組札が揃った盤から逆向きの合法手を乱数でたどって作った伏せ札のない盤 200 通りで、必ず勝つことをテストしている（試遊の要望で追加）。

## 設計上の選択

| 層 | 責務 |
|---|---|
| Core | `Card` / `PileId`（札と 13 の山）、`Table`（札の位置。コマンドの適用と取り消し、不変条件の検査）、`Command` / `MoveRecord`（意図と適用の記録）、`MoveRules`（合法性の判定と合法手の列挙）、`Deal`（配札）、`DeadlockDetector`（手詰まり）、`AutoComplete`（自動で仕上げられるかと次の 1 手）、`SolitaireGame`（試合：手数・履歴・勝敗）、`SolitaireConfig`（設定）、`TableText`（盤の文字表記） |
| App | `SolitaireFlow`（画面遷移、操作の窓口、経過時間）、`CardDragInput`（押す・動かす・離すを、山札のクリック・移動・組札へ送る意図に変える。ドラッグ中の札と選択を持つ）、`TableLayout`（札の置き場所、クリックした札、落とす先）、`Autopilot`（撮影とテストの操縦役）、`DemoTables`（勝利・手詰まりの直前の局面） |
| Unity | `SevenLanternsGame`（入力・HUD・音）、`SevenLanternsTableView`（52 枚の札と 13 の枠の描画、札を新しい位置へ寄せる）、`SevenLanternsSettings`（設定アセット）、素材とシーンの生成、撮影台本 |

- **移動の規則は 1 か所で決める。** `MoveRules.Check` が、コマンド（移動・めくり・戻し）を盤を変えずに検証し、拒否の理由（伏せ札・同じ色・ランク違い・空の列に K 以外 など）を返す。適用（`Table.Execute`）も内部で同じ検証を通し、合法手の列挙・ダブルクリック・手詰まりの探索もこれを使う。
- **取り消しは差分で行う。** `Table.Execute` が返す `MoveRecord`（動いた枚数、自動で開いたか）を逆に適用して戻す。盤のスナップショットは持たない。乱数で遊んで取り消しを混ぜ、各時点の盤が以前の盤と一致すること、全部取り消すと配札直後に戻ることをテストしている。
- **不変条件を盤が自分で検査する。** 52 枚がちょうど 1 つの山にある（同じ札が二重に属さない）、伏せ札は山札と場札の下側だけ、組札と場札の並びが規則どおり。手で書いた盤（`TableText`）も同じ検査を通す。
- **合法手は置き先から逆引きする。** 置き先ごとに底になれる札は 1 つのランクに決まるので、動かす元の表の札からそれを探して候補にし、`Check` で確かめる。全コマンドを総当たりで `Check` にかける列挙と、乱数で遊んだ全局面で一致することをテストしている。
- **カード状態とドラッグ UI を分ける。** 札がどこにあるかは Core の `Table` だけが持ち、ドラッグ中の札の位置と選択は App の `CardDragInput` が持つ。ドラッグ中も盤は変わらず、離したときに 1 つのコマンドとして Core に渡す。拒否されれば盤はそのままで、描画は札を元の位置へ寄せ戻すだけでよい。
- **置き場所の計算を 1 か所にする。** 描画（Unity）と、クリックした札・落とす先の判定（App）が同じ `TableLayout` を使う。卓の座標は札の幅が 1 で、Unity では卓の親の Transform で拡大して画面に合わせる。
- **撮影もポインタの操作で進める。** 撮影台本は札を動かすときも Core を直接呼ばず、押す・動かす・離すを Flow に渡す。
- **Core は整数だけで動かす。** シード 1 のシャッフルの並びを固定値として .NET と Mono の両方で照合している。

## 未実装の範囲

仕様書の Out of scope（他のソリティアのルール、必勝保証の配札）は実装しない。自動で仕上げるのは、必ず勝てると決まった状態（山札・捨て札が空で伏せ札なし）からだけ。

## 未解決事項

- 手詰まりの判定はメインスレッドで同期に呼ぶ。ほとんどの手は 1 局面で終わるが、乱数で遊んだ局面ではまれに千局面ほど調べる手があり、Mono で最大 0.12 秒かかった。人の手で引っかかりとして気になるようなら、上限（`DeadlockSearchStates`）を下げるか、判定を数フレームに分ける。
- 手詰まりは上限の局面数以内で確定したものだけを判定する。上限を超える局面は手詰まりとせず、あきらめるで終える。

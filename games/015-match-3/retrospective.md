# 015 振り返り

## 新たに学んだ点

検出（`MatchFinder`）と補充（`Refiller`）を互いに知らない純粋関数にし、`CascadeResolver` だけでつなぐと、補充の乱数を引く条件（並びがあるときだけ）を1か所で決められた。乱数を「初期生成」「補充」「作り直し」の系列に分けたことで、同じシードと手順の最終盤面を固定値で照合でき、Mono と .NET でも一致した。

目標スコアは、Core だけで多数の試合を自動で遊んで分布を見てから決めると、最初の試遊で大きく外さずに済んだ。

## 想定との差

演出中の入れ替えは Core が `Busy` で拒否するので、入力の持ち越しは起きないと考えていた。レビューで、1マス目の選択のように Core を呼ばない操作は拒否されず、選択が次の手番まで残る不具合が見つかった。既存のテストは演出中に2マスを続けて選んでいたため、入れ替えの拒否だけを確かめて通っていた。

落下・補充の描画は撮影画像で目視しただけで、途中の位置を確かめるテストがなかった。

## 次回の改善点

「演出中の入力を捨てる」は Core の拒否ではなく、入力を受け付ける層で判定し、選択やドラッグの状態も一緒に消す。テストは単独の操作（1回のクリック、押したまま、Space だけ）ごとに、解決後に持ち越していないことを確かめる。

途中の演出は、`Time.timeScale = 0` で実時間を止め、Tick をテストから進めて、始め・途中・終わりの描画を PlayMode で確かめる。

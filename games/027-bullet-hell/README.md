# 027. 弾幕STG — LANTERN VEIL（仮）

仕様書：[plan/games/027-bullet-hell.md](../../plan/games/027-bullet-hell.md)　実装計画：[plan/games/027-bullet-hell-implementation.md](../../plan/games/027-bullet-hell-implementation.md)

縦長のプレイ領域で、2 体のボスがそれぞれ 3 つの弾幕を撃ってくる。弾幕は小さなテキストの言語（弾道 DSL）で書き、Core のパーサが読む。参考作品からはメカニクスだけを採用し、名称・キャラクター・弾幕の名前と見た目は独自に作る。

## 環境

- Unity：6000.6.9f1（Universal 2D、C# 9.0）
- 対象プラットフォーム：Windows (StandaloneWindows64)
- 入力方式：Input System のキーボードのみ。HUD は PanelRenderer / UI Toolkit
- 共通パッケージ：[com.games100.tile-motion](../../packages/com.games100.tile-motion/)（残り Tick の `Countdown`・状態ハッシュ `StateHash`）

## 操作

| 入力 | プレイ中 |
|---|---|
| ← → ↑ ↓ / W A S D | 動く（8 方向） |
| Shift（押している間） | 低速で動き、当たり判定の点を表示する。ショットが前に集まる |

## 採用ルール

| 項目 | 採用ルール |
|---|---|
| 単位 | 位置は 1 px = 256 単位の整数、60 Tick/秒、時間の設定は Tick 数。浮動小数点を使わないので Mono と .NET で同じ結果になる |
| 座標 | プレイ領域は 384×448 px。原点は左下、y は上向き（Unity のワールド座標と同じ）。画面は 16:9 で、領域を左に、HUD を右に置く。カメラは固定 |
| 角度 | 1 周 = 65536 の整数。0 が右、反時計回りに増える（下向きは 49152）。sin / cos は 1 周を 4096 分割した表（Q14）を引く。表は起動時に**整数だけのテイラー展開**で作るので、`Math.Sin` の実装差に依らない（.NET と Mono で表の検査値が一致） |
| 弾の運動（弾道式） | 1 Tick ごとに、向き += 角速度 → 速さ = clamp(速さ + 加速, 0, 上限) → 位置 += 速さ × (cos, sin)。弾の内部の位置は 1 px = 2^30 の整数で持ち、速さ（1 px/Tick = 2^16）× cos（Q14）をそのまま足すので丸めの誤差が溜まらない。直進の弾の t Tick 後の位置は「出た位置 + t × 速度」にちょうど一致する |
| 弾の出現 | 撃った Tick に出た位置に置かれ、同じ Tick の弾の移動で 1 回目の移動をする（その Tick の当たりの通り道は「出た位置 → 1 回目の移動の後」） |
| 弾の消滅 | Tick の初めに、寿命（動いた回数）に達した弾と、**前の Tick に余白（32 px）の外へ出た弾**を取り除く。余白の外の弾は自機に届かない（余白 > 最大の弾の半径 + 自機の半径）。取り除いても残りの弾の順序は変えない |
| 弾の形 | small（半径 3 px）・rice（2.5 px）・orb（4.5 px）・large（9 px）。色は 8 色で見た目だけ |
| 弾数の上限 | 敵弾の置き場は固定容量（既定 2048）。満杯のときの発射は**捨てて数える**（`Dropped`）。例外にしない・配列を伸ばさない |
| 弾幕 | ボス 1 体 = 台本 1 ファイル = 弾幕 3 つ。各弾幕は体力と制限時間を持ち、体力 0 か時間切れで終わる（時間切れはボーナスなし）。終わると敵弾を全消去し、少し間を置いて次の弾幕 |
| ボスの動き | 台本の動きの列（決まった点へ・待つ・範囲の中の乱数の点へ）を、弾幕の間くり返す。各動きは始めの Tick に行き先を決め、指定の Tick 数で一定の速さで動く |
| 発射器 | 弾幕の開始から delay Tick 後に 1 回目、以後 every Tick ごとに撃つ。n 回目（0 始まり）の中心の向き = angle + n × spin（aimed なら自機への向きを足す）。ring は全周を count 等分、fan / aimed は spread を count-1 等分。弾はボスの位置（その Tick の移動の後）＋ offset から出る |
| 自機 | 通常 4.0 px/Tick・低速 1.75 px/Tick（斜めは各軸 181/256 倍、最低 1）。領域の中で止まる。当たり判定は半径 2.5 px の円（低速中だけ表示） |
| ショット | Z を押している間、決まった間隔で上へ直進弾を撃つ（低速中は幅を狭めて集中）。ボスの円への接触は掃引で判定し、体力を減らす |
| 被弾 | 敵弾と自機の判定円を **Tick の中の相対軌跡どうしの掃引**で判定する（026 の `Sweep.First`）。被弾で残機 -1・敵弾を全消去・無敵（被弾した Tick を含めて数える）。**同じ Tick に複数の弾に触れても 1 回**、無敵中は無視 |
| ボム | X で 1 個使う（初期 3、被弾・再挑戦で 3 に戻す）。敵弾を全消去し、決まった Tick の間無敵＋ボスへ継続ダメージ。ボム中はもう 1 個使えない。仕様書の In scope にない追加（ユーザーの指定） |
| 残機と結果 | 残機 3。0 になった Tick で敗北。ボス 2 体の 6 弾幕を終えたら勝利 |
| 再挑戦 | 敗北の結果画面から「このボスから」：そのボスの 1 つ目の弾幕・残機 3・ボム 3・得点はボス開始時の値で、新しいシードで始め直す。「最初から」も選べる |
| 乱数 | 1 試合 = 1 シードの xorshift。台本の `rand` は弾幕ごと・発射器ごとに系列を分け、ボスの動きも別の系列（ある発射器に rand を足しても、他の発射器とボスの動きは変わらない） |
| 終了後 | 勝利・敗北の後の Tick と入力は状態を変えない |

自機・ショット・ボム・残機の具体的な値は、セッション2で設定（`VeilConfig`）に出し、試遊で調整する。

## 弾道 DSL

1 ファイル = ボス 1 体。行単位で、`#` から行末は注釈。字下げに意味はない。

```
boss "Ember Warden" radius=24
pattern "Cinder Bloom" hp=900 time=40s
  move to at=192,360 over=60
  move wait over=30
  emit ring every=20 count=24 speed=1.8 spin=7 shape=orb color=blue
  emit aimed every=45 delay=10 count=5 spread=30 speed=3 accel=0.02 maxspeed=4.5
pattern "Ash Spiral" hp=1200 time=2400
  move wander area=96,280,288,400 over=120
  emit fan every=4 count=3 angle=rand(-10,10) spread=20 speed=rand(1.5,2.5) curve=0.4 offset=0,-8 life=300 shape=rice
```

| 文 | 引数（* は必須） |
|---|---|
| `boss "名前"` | `radius*`（px、1〜64） |
| `pattern "名前"` | `hp*`（1〜100000）・`time*`（Tick、1〜36000） |
| `move to` | `at*`（x,y px、領域内）・`over*`（Tick） |
| `move wait` | `over*` |
| `move wander` | `area*`（x1,y1,x2,y2 px）・`over*` |
| `emit ring` / `fan` / `aimed` | `every*`（Tick）・`speed*`（px/Tick、0〜16）・`delay`（Tick、0）・`count`（1〜256、1）・`angle`（度、0。aimed では自機の向きからのずれ）・`spread`（度、0〜360、fan / aimed のみ）・`spin`（度/回、0）・`accel`（px/Tick²、-1〜1、0）・`maxspeed`（px/Tick、16）・`curve`（度/Tick、-45〜45、0）・`offset`（x,y px、-200〜200、0,0）・`life`（Tick、0 = 領域を出るまで）・`shape`（small）・`color`（red） |

- 数は浮動小数点を通さずに整数の単位へ直す（小数点以下 6 桁まで、0 から遠いほうへ四捨五入）。時間は `40s` のように s を付けると秒（1/60 秒の倍数に限る）。
- `rand(a, b)` は両端を含む一様な整数（単位へ直した後）。`angle`・`offset` は 1 回の発射で 1 回選び、`speed`・`accel`・`curve` は弾ごとに選ぶ。
- 誤りは行・列付きで集め、1 つの文では最初の 1 つだけを報告して次の行へ進む（未知の語・必須の引数がない・引数の重複・範囲外・型違い・pattern の外の move / emit・emit のない pattern・閉じていない文字列）。

## 設計上の選択

- **物理エンジンは使わない。** 弾・自機・ボスの移動と当たりはすべて Core の整数演算で行う。
- **弾はデータ指向の置き場（`BulletPool`）。** 固定容量の配列を成分ごとに持ち（SoA）、弾 1 発ごとのオブジェクトを作らない。`Step` は割り当てをせず、消える弾は残りの順序を保って前へ詰める。
- **台本の読み込み（`ScriptParser`）と演じる処理（`PatternPlayer`）を分ける。** パーサの出力は不変の `BossScript`（`PatternSpec` → `MoveSpec` / `EmitterSpec`）で、範囲の検証はパーサで済ませる。実行時の弾数の上限は置き場の「捨てて数える」で守る。
- 計画の `spiral` は、`ring` に `spin` を付ければ同じ弾になるので作らなかった。

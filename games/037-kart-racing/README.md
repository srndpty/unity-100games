# 037. カートレース

THISTLE CIRCUIT（仮）。真上から見る 1 周のカートレース。仕様書：[plan/games/037-kart-racing.md](../../plan/games/037-kart-racing.md)

## 環境

- Unity：6000.6.9f1
- 対象プラットフォーム：Windows (StandaloneWindows64)
- 入力方式：キーボード（Input System）

## 起動手順

```
dev gui 037      # エディタで開く
dev build 037    # Windows ビルド
dev run 037      # ビルドを起動
dev capture 037  # 証跡を evidence/ に撮る（画像は captures/<画像世代>/、撮影記録は runs/）
```

## 操作

| キー | 操作 |
|---|---|
| ← → または A D | 旋回 |
| W または ↑ | 加速 |
| S または ↓ | ブレーキ（後退まで） |
| Space | ドリフト（加速と旋回を押しているとき） |
| Enter | スタート、再開、再戦 |
| Esc | 一時停止、再開。結果ではタイトルへ |
| R | 一時停止中にやり直し |
| Backspace | 一時停止からタイトルへ |

フォーカスを失うと一時停止し、押したままのキーとドリフトの溜めを消す。ブーストにはしない。復帰は Enter か Esc。

## 採用ルール

| 項目 | ルール |
|---|---|
| 時間 | 60 Tick/秒。入力はその時刻を含む Tick の前に反映し、次の Tick から効く |
| 座標 | 1 単位 = 1 mm。向きは 1 周 = 65536。速さは mm/Tick。浮動小数点は使わない |
| 車 | 半径 600 mm の円。位置、向き、速さ、ドリフトの溜め、ブースト残り、周回、次のゲート、回復の残り |
| 加速 | 押している間 `Accel`（8）ずつ上限へ。ブースト中の上限は 500。離すと `Drag`（3）で 0 へ向かい、0 は越えない |
| ブレーキ | `Brake`（14）ずつ、後退の上限 140 まで |
| 旋回 | 低速で大きく（700）、`MaxSpeed`（340）で小さい（160）。速さ 0 では向きも位置も変えない。後退中は符号を反転する |
| ドリフト | 加速中、旋回が左右どちらか一杯、速さ 160 以上で開始できる。押している間は旋回を 280 足し、速さを 4 減らし、移動を向きより 600 遅らせる。ボタンだけを離したとき溜めが 8 Tick 以上なら 40 Tick のブースト。1 Tick 不足、加速を離す、壁に当たった Tick は溜めを消してブーストを出さない |
| 芝 | ターマック（左右の端の点を結んだ四角形、描画と同じ形。端の線の上を含む）の外から、ガードまで幅 3 m（`runoff`）。Tick の始めに車の中心が芝なら、加速・ブレーキの後で速さを 150 へ 12 ずつ下げる（ブースト中も）。それより遅ければ変えない |
| 壁 | 芝の外側のガード（左右の折れ線）。食い込んだら内側へ押し出して接線方向へ滑る。1 Tick に 2 回まで。まだ食い込んでいたら速さを 0 にする。ちょうど接するだけでは触れない。ガードは閉じた輪なので、内側を横切る近道はできない |
| 車同士 | 全車の加速・旋回の後、壁の前に解決する。Tick の中で始めから終わりへ直線で動くとみなして相対軌跡を掃引し、最初に触れた組から順に、触れた時刻の位置から中心を結ぶ向きに直径 + 1 mm まで押し離す。近づいているときだけ等しい質量で法線方向の速度を反発 0.4 で分け合い、向きへの成分を新しい速さにする（向きは変えない）。Tick の残りは新しい速度で進む。1 組は 1 Tick に 1 回まで。触れた Tick はドリフトの溜めを消す（壁と同じ）。完走した車は幽霊で触れない |
| 周回 | 次のゲートを、手前から奥へ横切ったときだけ印が進む。ゲートはガードからガードまで張る（芝の上でも数える）。線の上は手前の側として扱う（線の上で止まった次の Tick に奥へ出れば数える。線の上で止まる・線から手前へ戻る移動は数えない）。逆走、飛ばしでは進まない。0 番を前向きに横切ると周回 +1。3 周目の 0 番で完走し、その場で止まる |
| 順位 | 完走は記録の早い順、未完走は周回・ゲート・区間の進みの順。同着は番号の小さい方が上。必ず 1〜4 が 1 つずつ |
| 終了 | プレイヤーが完走した Tick か 20000 Tick。CPU の完走は待たず、走行中の CPU は進みの順で順位が付く。1 位が勝利。結果の後は操作で順位を変えない |
| スタート | 90 Tick は車を動かさない |
| CPU | 中心線の 8 m 先へ向き、32 m 先までの曲率で目標の速さを決める。前 7 m 以内に横の間が直径 + 0.4 m より狭い車がいれば、自分のいる側で、その車と中心線の両方から直径 + 0.4 m 離れた筋（ターマックの端から 0.5 m 内）を狙って追い越す。角ではドリフトし、8 Tick 溜めたら離してブーストする。進みが 40 Tick 止まると後退して向きを直す（後退中は停滞を数えない）。直線の速さは 880 / 800 / 720（1000 がプレイヤー） |
| 再現 | 乱数は使わない。初期配置と設定と入力列だけで決まる。再戦は同じコースを最初からやり直す |

実装で当初の表から変えた点：上限の速さは 340（380 だと角で壁に張り付く）。ミニターボは 8 Tick（25 Tick ドリフトし続けるとコースを外れる）。横滑りは 600。CPU の先読みはハンドル 8 m、曲率は 32 m。スタートグリッドは 0 番ゲートの手前にいるため、立ち往生の判定は区間の進みではなく中心線に沿った進みで行う。

試遊を受けて変えた点（2026-11-25）：タイトル画面、プレイヤーのゴールで結果へ、ミニマップ、車同士の接触（当初は「すり抜ける」）、ターマックの外の芝とガード（当初はターマックの端が壁）、車の絵、煙。車の絵を大きくしたので当たりの半径を 450 → 600 mm にした。

## 設計上の選択

- 車両の積分（`Vehicle`）、壁（`WallContact`）、車同士（`KartContact`）、ゲート（`Progress`）、順位（`Standings`）、CPU の意図（`CpuPlan`）は Core。画面遷移と時刻付きの入力、ミニマップの写像（`MinimapFrame`）、煙を出すかの判定（`TyreSmoke`）は App。Unity は描画と入力と音だけを行う。物理エンジンには委譲しない。
- 車同士の接触は、検証を通る設定なら掃引の値が `Sweep.FirstLimit` に収まる（1 回の接触で移動は「前の移動と BoostSpeed の大きい方 + 半径 + 3」までしか伸びず、相手は 3 台まで。`KartConfig.ContactSweepBound` で検証する）。
- CPU の操作は Tick の始めの全車の状態から決める（他の車をよけるため）。全車の操作を先に決めてから動かすので、車の番号の順に動かしても結果は順序に依らない（接触は最初に触れた組から解決する）。
- 煙は Unity の粒のプール（384 個）で、レースの Tick で歳を取る。実時間を使わないので撮影が同じ絵になる。描画の間に何 Tick も進んだときは、その Tick 数だけ今の位置から出す。
- コースの地面（外の芝、ランオフ、ガード、ターマック、縁石、白線、チェッカー）は Track の点から作った 1 枚のメッシュで、Prefab に保存したメッシュと頂点を照合する。
- 固定ハッシュ `108021296`（400 Tick の同じ操作。芝に入り、ドリフトする）。.NET と Mono で一致する。

## 性能

実コースを走っている 300 Tick（4 台、車同士の接触、このコースのガード壁）で、Core の Step は p95 0.077 ms、車・煙・追従カメラの更新は p95 0.088 ms、割り当て 0 バイト。計測の条件と画面は [evidence/README.md](evidence/README.md)。

## 試遊で見てほしい点

加速の伸び、高速での曲がりにくさ、ドリフトの滑りとミニターボの溜め（8 Tick）、芝での減速（150・12 ずつ）と芝の幅（3 m）、ガードに擦ったときの止まり方、車同士の当たりの強さ（反発 0.4）と CPU の追い越し方、CPU との速さの差、カメラの寄り（縦 20 m）、煙の量、車の絵、スタート待ち（1.5 秒）、音量。

## 操作

| キー | 操作 |
| --- | --- |
| 矢印 / WASD | 移動（上下で奥と手前） |
| J | 攻撃（ヒットすると 3 段まで繋がる）。空中で跳び蹴り。掴み中は膝、3 回目か左右＋J で投げ |
| K | ジャンプ |
| L | 緊急技（体力を払って周りを吹き飛ばす） |
| 敵へ歩いて触れる | 掴み |
| Esc | 一時停止 |
| F1 | 判定箱と奥行きの帯の表示 |

## 採用ルール

| 項目 | 採用ルール |
| --- | --- |
| 時間 | 60 Tick/秒。座標は整数で 1 px = 256 |
| 座標 | x は横（面の進行）、z は奥行き（0 が手前、帯 `[ZMin, ZMax]`）、y は高さ。画面の縦位置 = z × DepthNum / DepthDen ＋ y（既定 1/2） |
| 描画順 | z の大きい（奥の）順に描き、同じ z は出現番号の小さい順。高さは順に影響しない。順序は Core の `Depth.DrawOrder` が決め、描画はそれを写すだけ |
| 判定箱 | 横・高さの矩形と奥行きの半幅の 3 軸。攻撃箱と喰らい箱は 3 軸すべてが重なったときだけ当たる。端がちょうど接するだけ（奥行きなら z の差が半幅の和ちょうど）では当たらない。掴み・押し合いも奥行きを見る |
| コンボ | 攻撃でジャブ。ヒットした技の硬直の始めから受付窓の間に攻撃が押されていれば次段へ。空振りは繋がらず、硬直が解けてから 1 段目。3 段目（アッパー）はダウンを奪う。押下は先行入力として `BufferTicks` Tick 保持 |
| 掴み | 地上を敵の方へ歩いて押し合いで触れ（横の余裕 `GrabReach`）、奥行きの差が `GrabDepth` 以内、敵が立ち・歩き・怯み中なら掴む。攻撃・ダウン・起き上がり・空中の敵は掴めない。掴み中の攻撃は膝（`MaxKnees` 回まで）、その後か左右＋攻撃で投げ。`GrabTicks` で離す |
| ジャンプ攻撃 | 空中で攻撃。着地まで 1 回。奥行きは跳んだときのまま |
| 緊急技 | 体力 `cost` を払い、左右と奥行きの周りを吹き飛ばす。出してから `invuln` Tick（発生と持続を含む）は無敵。体力が代償以下なら出ない。立ち・歩き・攻撃中・怯み中・掴み中から出せる |
| ヒット | 攻撃箱が喰らい箱に重なった Tick に成立。同じ技の発動 1 回につき 1 体に 1 ヒット（複数の敵には各 1 回）。同じ Tick の攻撃は全組を集めてから同時に適用する（相打ちあり） |
| 怯み | 技の怯み（Stagger）が相手の Poise 以上なら怯む。未満ならダメージだけで動きは止まらない（大男・ボスはジャブで怯まない） |
| ダウン | ダウン技・体力 0・空中で受けた打撃で吹き飛ぶ。倒れ・起き上がりの間は喰らい箱が無く、起き上がり後 `WakeupInvuln` Tick は無敵。体力 0 の敵は倒れた後に消え、以後は攻撃も攻撃権の要求もしない |
| ヒットストップ | 当てた側と当たった側だけが止まる。他の敵は動き続ける。止まりの間も先行入力は減らない |
| 残機 | `Lives`（既定 3）。体力 0 で倒れ、その場で全快・`RespawnInvuln` Tick の無敵で復帰。残機 0 で敗北。終わった後の入力は状態を変えない |
| 得点 | プレイヤーの与えたダメージ ＋ 撃破ごとの点（撃破は体力が 0 になった 1 回だけ数える） |
| 敵 | チンピラ（2 段パンチ）、大男（遅い・体力が多い・ジャブで怯まない振り下ろし）、跳び蹴り屋（離れた所から跳び蹴りで突っ込む）、ボスのガラン（裏拳の 2 段・遠くから奥行きを合わせて突進・近くで掴み投げ、体力が半分を切ると速くなる） |
| 攻撃権 | 攻撃に入れるのは攻撃権を持つ敵だけ。雑魚は同時に `MaxAttackers`（既定 2）体、ボスは別枠で 1 体。権利は待った Tick の長い順（同じなら出現の早い順）に渡す。攻撃が終わる・怯む・倒れる・掴まれる・`TokenTimeout` Tick 攻撃に入れない、のどれかで返し、返した Tick から `TokenCooldown` Tick は求めない。プレイヤーが倒れている間は配らない。画面の外の敵は求めない |
| 待つ敵 | 権利の無い敵はプレイヤーから `keep` 離れた所で待つ。その位置が画面の外なら反対側で待つ（外で待つと権利が回らないため） |
| 出現 | 区画の波は遅れの順の待ち行列。出ている敵が `MaxActiveEnemies`（既定 4）未満のときだけ、先頭から画面の外の左右に出す（追い越さない） |
| 区画 | 区画に入ると画面が止まる。波が尽きて敵がいなくなると「GO →」で、右へ歩くと画面が進み、次の区画の位置で止まる。最後の区画はボスを倒すと面クリア（護衛が残っていてもよい） |
| 1 Tick の順 | 入力 → 出現 → 攻撃権 → 各登場者の状態 → 押し合いと端 → 掴み → 攻撃（同時適用） → 死亡・区画・面 |

## 設計上の選択

- Core（`Assets/Game/Core`）は技表を読む状態機械で、技ごとのコードを持たない。敵の考えと攻撃権も Core に置く（乱数は出現ごとに試合の系列から分けた敵ごとの xorshift）。物理エンジンは使わない。
- App（`Assets/Game/App`）は画面の流れ（タイトル → 操作説明 → 試合 → 一時停止 → 結果）と時刻つき入力、操縦役 `Autopilot`、効果音の出来事 `CombatFeedback`。
- 面は `Assets/Game/Data/Stage.txt`（区画と波）。
- Unity（`Assets/Game/Unity`）は描画・入力・音・カメラ。登場者は Prefab の 9 組（プレイヤー＋敵の置き場 8）の SpriteRenderer を使い回し、位置は `Depth.ScreenY`、重なり順（sortingOrder）は `Depth.DrawOrder` の順位を写すだけ。影は地面（y = 0）の位置に別の層で描く。姿は Core の状態と技の Tick から決め、実時間を使わない。
- 描画の置き場は 9 組なので、`SootSettings` の検証で敵の置き場（`Capacity`）を 8 以下に限る（Core は 32 まで受け付ける）。
- 絵はすべて `SootArtGenerator` で生成したドット絵（登場者 5 種 × 9 姿勢、路地の背景・地面・影・街灯・エフェクト）。シーンと Stage Prefab は `SootSceneBuilder` で作る（`unity run games/040-beat-em-up -- -executeMethod Game.Unity.Editor.SootSceneBuilder.Build`）。Prefab の街灯（区画の右端）とタイトルの配置は Core のデータと同じ関数で照合する（`SootStage.Mismatch`）。
- F1 の判定箱は、箱の正面（奥行きの中心の高さ）と、地面に落とした奥行きの帯を描く。帯が重ならなければ、正面が重なって見えても当たらない。

## テスト

`dev test 040` で Core と App を検証する。Unity 上は `dev test 040 -Unity` と `dev test 040 -Unity -Mode PlayMode`。

| 対象 | 主な内容 |
| --- | --- |
| 奥行き（`DepthTests`） | 3 軸の箱の境界、異なる奥行きの敵に当たらない（ジャブ・跳び蹴り・緊急技・掴み・押し合い）、描画順 |
| 技表（`MoveTableTests`） | README の表との一致、全打撃の発生・持続・硬直のログ照合、壊れた技表の拒否 |
| 戦闘（`CombatTests`） | コンボの受付窓の境界、先行入力、多重ヒット防止、ヒットストップ、怯み、相打ち、掴み・膝・投げ、緊急技、残機、台本の固定ハッシュ |
| 敵（`EnemyTests`） | 攻撃権の上限と偏りの無さ、返す条件、倒れた敵が再攻撃しない、同時出現の上限、区画とボス、壊れた面の拒否、32 体の乱戦の不変条件 |
| 実シーン（`SootSceneTests`、PlayMode） | キー入力でコンボ・ジャンプ攻撃・緊急技・掴み（Core を直接呼ばない）、描画の位置と重なり順が Core の描画順と一致（奥へ回り込むと入れ替わる、跳んでも変わらない）、判定箱と奥行きの帯、タイトルへ戻ると起動直後の絵に戻る、Prefab と Core のデータの照合、操縦役で面クリアと HUD、敗北の画面、8 体の乱戦の性能と割り当て |
| 流れ（`FlowTests`） | 画面の遷移と再戦のシード、一時停止、フォーカス喪失、フレームレートに依らない状態、操縦役が 20 シードでクリア、人寄りの操縦役、固定ハッシュ |

操縦役（毎 Tick 判断）は 20 シード全部で面をクリアする。判断を 6 Tick ごとにし緊急技を使わない人寄りの操縦役も 10 シード全部でクリアし、多くの回で残機を 1 つ失う。

性能（敵の置き場 8 体を全て使った乱戦、Unity エディタのバッチ実行・Mono）：Core の Step p95 0.065 ms、描画の更新 p95 0.026 ms、判定箱ありの描画のフレームの割り当て 0。

## 試遊で見てほしい点

`dev run 040` で遊ぶ。値は `Assets/Game/Unity/SootSettings.asset`（`Rules`）と `Assets/Game/Data/Moves.txt`・`Stage.txt` にある。

- コンボの繋がりやすさ（受付窓 8 Tick、先行入力 `BufferTicks` 8 Tick）
- 掴みの成立しやすさ（奥行きの差 `GrabDepth` 6 px、横の余裕 `GrabReach` 2 px）と、攻撃の奥行きの許容幅（ジャブの奥行きの半幅 8 px ＋ 体の半幅 6 px）
- 囲まれ方（同時に攻める敵 `MaxAttackers` 2、画面の敵 `MaxActiveEnemies` 4、攻撃後に待つ `TokenCooldown` 45 Tick）
- 敵とボスの強さ、緊急技の代償（体力 80）、残機 3、面の長さ（操縦役で約 95 秒）
- 音量（`Volume` 0.15）

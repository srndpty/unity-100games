# 031 リズムゲーム

Unity 6000.6.9f1 / 2D URP / Windows 64-bit / キーボードとマウス

`dev build 031` でビルドし、`dev run 031` で起動する。エディタでは `dev gui 031` から `Rhythm` シーンを再生する。

## 操作

| 入力 | 操作 |
|---|---|
| ↑ / ↓ または曲ボタン | 曲選択 |
| ← / → または ±5 ms ボタン | 音ずれ補正を調整 |
| C または補正テストボタン | 補正テストを開始 |
| Enter | 演奏開始 / 結果画面から同じ曲（補正テスト）をやり直す |
| F / J | 丸 / ひし形のノーツを打つ |
| Esc | 一時停止 / 再開 |
| T | 一時停止・結果画面から曲選択へ |

ノーツが各レーン左側の色付きの線に重なるときに打つ。2本のレーンをまたぐ薄い縦線が小節線。良・可で打ったノーツは判定線の上で砕ける（良は閃光・輪・8つの破片、可は小さく淡い輪と4つの破片）。

音ずれ補正は −200〜+300 ms、5 ms 刻みで保存され、次の演奏から反映される。正の値は音が遅れて聞こえる環境（Bluetooth ヘッドホンなど）向けで、ノーツの流れと判定の両方をその分だけ遅らせる。

補正テストは、1小節のカウントの後に4分音符のクリックだけが8小節鳴る（90 BPM）。画面にはノーツを出さず、音に合わせて F か J を押す。各拍に、拍の間隔の半分未満で最も近い打鍵を1つ対応させ、ずれの中央値を5 ms 単位に丸めて補正値にする。拍に合う打鍵が16回（半数）に満たないときは補正を変えない。テストは補正なしの時計で測るので、今の補正値に関係なく同じ結果になる。

## ルール

| 判定 | 条件 | 配点 |
|---|---|---|
| 良 | 誤差 ±30 ms 以内 | 100 |
| 可 | 誤差 ±80 ms 以内 | 50 |
| ミス | 未判定のまま遅い側の窓を通過 | 0 |

「可」には、ノーツより早ければ FAST、遅ければ SLOW を判定の横に出し、結果画面に件数を出す（「良」とミスには付けない）。最後のノーツまでミスがなければ、曲の余韻の間にレーンの上へ FULL COMBO を出し、結果画面にも記す。「可」もコンボを保つのでフルコンボに含む。

同じ打種の未判定ノーツのうち誤差が最小のものを採点する。同距離では早いノーツを優先する。空打ちでノーツは消費されない。良・可でコンボが増え、ミスで途切れる。コンボは判定が決まった順ではなく譜面の順に数える（後ろのノーツを先に打っても、前のノーツが良・可・ミスに決まるまでコンボに足さない）。音源の再生が終わり、全ノーツの判定が決まると得点と判定の内訳を表示する。曲の終わりは補正前の再生位置で決めるので、補正値で結果画面へ移る時刻は変わらない。

「港の灯」「雨上がり」「夜の軌道」は 96・120・144 BPM、各12小節のオリジナル曲。オンラインランキング、曲ライセンス機能、課金・実績は仕様の対象外。

## 実装と再生成

- Core は譜面（ノーツと小節線）の検証と採点、補正テストの推定（`Calibration`）を担当する。判定は 32 kHz の整数サンプルで比較する。譜面の前後には判定窓と補正の最大幅（300 ms）の余白を求める。
- App は演奏の状態と音ずれ補正を管理する。補正値は曲の時計そのものをずらし、表示位置と判定の両方に効く。入力を曲時刻順に扱えるように採点を50 ms（DSP 時刻の更新間隔より長い）保留し、同時刻では受信順に処理する。破壊演出は採点の確定から始まるので、打鍵からこの保留時間ぶん遅れて出る。打鍵の時刻から保留時間を超えて届いた入力は捨てる（ちょうど保留時間までは受け付けることをテストで確認）。フレームが止まっても、その間の打鍵は次のフレームの採点より先に届くので捨てられない。
- Unity は DSP 開始時刻を共有して曲の予約再生とノーツの位置を決める。`dspTime` はミキサーが書き込んだ位置で、実際に聞こえるのは出力バッファ（`GetDSPBufferSize` の長さ×個数）ぶん後なので、ノーツの位置と判定はその遅れを足した「聞こえる時刻」を基準にする。打鍵は Input System のイベント時刻を DSP 時刻へ換算する。停止中はオーディオと DSP 時間を保持し、復帰後は手動で再開する。
- 破壊演出と FULL COMBO の経過は曲内サンプルで数える。一時停止で止まり、撮影でも同じ絵になる。
- シーンと音源は `unity run games/031-rhythm-notes -- -executeMethod Game.Unity.Editor.RhythmSceneBuilder.Build` で再生成できる。音源と譜面は共通の拍→サンプル変換を使う。WAV はモノラルの16ビット PCM で、最長30秒の曲と補正テスト（約27秒）もコミット時の2,000 KB上限に収まる。配点・判定窓・表示先行時間・音量は `RhythmSettings.asset` にある。

## 検証

Windows 実機での通しプレイと、スピーカーやヘッドホンごとの補正テストの結果・補正後の感触は人間の確認対象。補正テストは拍の間隔の半分（約333 ms）より大きい遅れを測れない。

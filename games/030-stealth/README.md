# 030. ステルスアクション — HUSH WARD（仮）

仕様書：[plan/games/030-stealth.md](../../plan/games/030-stealth.md)　実装計画：[plan/games/030-stealth-implementation.md](../../plan/games/030-stealth-implementation.md)

1 画面の施設に忍び込み、北東の資料室から機密ファイルを取って、南西の入口へ戻る。3 人の警備員は見回り、足音を聞きつけ、見つけたら追い、見失ったら探す。見つからずに抜けても、見つかってから振り切ってもクリアできる。参考作品からはメカニクスだけを採用し、名称と見た目は独自に作る。

## 環境

- Unity：6000.6.9f1（Universal 2D、C# 9.0）
- 対象プラットフォーム：Windows (StandaloneWindows64)
- 入力方式：Input System のキーボード。HUD は PanelRenderer / UI Toolkit
- 共通パッケージ：[com.games100.tile-motion](../../packages/com.games100.tile-motion/)（整数の箱・タイルとの衝突解決・状態ハッシュ）、[com.games100.int-geometry](../../packages/com.games100.int-geometry/)（整数のベクトル・平方根・角度表・シード付き乱数）

## 起動手順

```
dev gui 030      # エディタで開く
```

## 採用ルール

| 項目 | 採用ルール |
|---|---|
| 単位 | 1 タイル = 256 単位の整数。速さは単位/Tick、60 Tick/秒。時間の設定は Tick 数、角度は 1 周 65536 の整数（`Trig`）。浮動小数点を使わないので Mono と .NET で同じ結果になる |
| 施設 | 32×18 タイルの 1 画面（下の地図）。`#` 壁（移動・視線・音を遮る）、`X` 木箱（移動・視線を遮る、音は通す）、`.` 床、`E` 入口兼出口、`O` 目的物（機密ファイル） |
| 自機 | 体は 176×176 単位の箱。8 方向に動き（斜めは各軸 181/256 倍、最低 1）、壁・木箱で止まる（`BodyMotion`、横 → 縦の順）。歩き 18・忍び足 9（C）・走り 32（Shift）。両方押したら忍び足 |
| 足音 | 動いた Tick に、最初の 1 Tick 目と以後 15 Tick ごとに出る。止まると数え直す。届く距離は **壁を回り込む 4 近傍の経路のマス数** で、忍び足 1・歩き 3・走り 7。木箱は音を通す |
| 視覚 | 警備員の体の中心（目）から自機の中心へ、距離が視程以下（平常 6 タイル・警戒/厳戒 8 タイル）、向きとの角が半視野角 40° 以下、かつ **視線が遮られない** とき見える。視線は 2 点を結ぶ閉じた線分で、壁・木箱の閉じた正方形に 1 点でも触れたら遮られる（角をちょうどかすめる・面に沿う線も遮る）。毎 Tick、移動の後の位置で 1 回判定する（走りの 1 Tick の移動は体の半分未満と検証で保証） |
| 気づき値 | 警備員ごとに 0〜1000。見えた Tick は距離に応じて増える（目の前 60・視程ちょうど 10、間は線形・切り捨て）。見えない Tick は 3 減る。**1000 に達したら発見（追跡）** |
| 判断（FSM） | **巡回**：巡回点を順に歩き、各点で見回す（向きを ±50° の三角波で振る、1 往復 160 Tick）。**調査**：見えたが未発見・足音・無線の位置へ歩き、着いたら 120 Tick 見回して巡回へ戻る。**追跡**：最後に見た（追跡中は聞こえた）位置へ走る。**捜索**：見失ったまま最後の位置に着いたら、そこから歩いて 5 マス以内の床を乱数で選んで巡り（各 40 Tick 見回す）、600 Tick で巡回へ戻る。**捜索中に見えたら（触れたら）気づき値によらず追跡へ戻る**（捜索中の足音は調査）。**足音と無線は調査にしかならず、気づき値を増やさない**（音だけでは発見しない） |
| 警備員の体 | マスの中心から隣のマスの中心へ 1 軸ずつ歩き、着いた Tick はそこで止まる。経路は 4 近傍の幅優先（右・上・左・下の順）。向きは 1 Tick に 1024（約 5.6°）まで回す。巡回 12（警戒・厳戒は 16）・調査 14・追跡 26・捜索 16 |
| 警戒レベル | 施設全体で平常／警戒／厳戒。誰かが追跡している Tick は厳戒。追跡のない Tick が 600 続いたら警戒、さらに 900 続いたら平常。警戒・厳戒の間は視程が長く巡回が速い。**平常・警戒から厳戒へ上がった回数を「発見回数」と数える** |
| 無線 | 厳戒へ上がった Tick に追跡を始めた警備員の目標を、次の Tick に全員へ知らせる。追跡していない警備員はその位置の調査に向かう |
| 接触と捕獲 | 体の接触は、自機の横 → 縦の経路と警備員の直線の移動を掃引して判定する（025 の `Sweep.Along`）。**追跡中の警備員に触れたら捕獲**。追跡していない警備員に触れたら捕まらないが、その警備員は次の Tick に触れた位置で発見する |
| 目的物・出口 | 目的物のマスに体が重なったら取る。取った後、体の中心が入口のマスに入ったら脱出。取る前に入口へ戻っても何も起きない |
| 同じ Tick の順序 | 自機の移動 → 足音 → 目的物 → 知覚（視覚・聴覚・前の Tick の接触・無線）→ 判断 → 警備員の移動 → 捕獲 → 脱出 → 警戒レベル。**捕獲と脱出が同じ Tick なら捕獲** |
| 結果 | 脱出：遊んだ時間・発見回数（0 なら「未発見」）。捕獲：その場で終わり。どちらも Enter で新しい試合 |
| 乱数 | 1 試合 = 1 シードの xorshift（`SeededRandom`）。警備員ごとに系列を分ける。乱数を使うのは捜索の行き先だけなので、見つからない限りどのシードでも同じ動きになる。再戦は起動時の値から試合ごとに進めた新しいシード |
| 終了後 | 捕獲・脱出の後の Tick と入力は状態を変えない |

## 設計上の選択

- **Core**（`Game.Core`）
  - **知覚（センサ）と判断を分ける**。`LineOfSight`・`Vision`・`Hearing` は状態を持たない関数・再利用バッファで、判断を知らない。試合（`Infiltration`）がセンサの結果と体の状態（マスの中心に立っているか・向き）を `Percept` にまとめ、`GuardBrain` に渡す。`GuardBrain` は地図も視線も知らず、`Percept` と視程だけで FSM と気づき値を進め、体への指示（`Order`：歩く先と歩き方・見回し・向く点）を返す。捜索の行き先を選ぶときだけ `ISearchArea` を使う。
  - `GuardBody` は指示に従って歩き、向きを回すだけ。`Intruder` は自機の移動と足音。
  - 視線の判定（`LineOfSight.Touches`）は Liang–Barsky の区間を分数で比べる整数の計算。描画用の扇（`Vision.Fan`）も同じ判定を二分探索して作るので、描いた扇と見える範囲が食い違わない。
  - `Infiltration.Hash` は判断・体・自機（足音の間隔の途中まで）・警戒・無線・接触・乱数をすべて含める。`Clone` は操縦役の先読みに使う。
  - 検証済みの設定は試合だけが持ち、`Infiltration.Config` は複製を返す（書き換えても試合には効かない）。描画と操縦役には、複製を作らない `CurrentVision`・`SpeedOf` を渡す。複製した試合とは同じ設定を共有する。
  - 警備員は、その Tick の知覚に使った姿勢（動く前の位置と向き、Tick の始めの視界）を `SightOrigin`・`SightFacing`・`SightVision` に残す。視界の扇はこの姿勢で描くので、扇と「見えたか」が同じ Tick で一致する（体はその Tick に動いた後の位置に描くので、扇の原点は体から最大 1 Tick の移動量だけずれる）。
- **App**（`Game.App`）
  - `WardFlow`：Title / Playing / Paused / Caught / Escaped。時刻付きの入力・1 フレームの Tick 上限・遊んだ時間の分け方は 025 の `VaultFlow` と同じ。F1 の詳しい表示（`ShowDebug`）も同じ入力の列で切り替える。
  - `StealthPilot`：数 Tick ごとに候補の動き（進む・待つ・来た道を戻る）を `Infiltration.Clone` で 150 Tick 先まで試す。経路は「巡回を試走して数えた各マスの見られやすさ」（`Exposure`）を重みにした最短経路。厳しい設定では誰にも気づかれない候補だけを選ぶ（見つからずに脱出）。緩い設定は見つかった後に逃げるために使う。
  - `BoldPilot`：警備員を気にせず目的物へ歩き、離れた警備員に見られたら止まって見つかるのを待ち、見つかったら緩い `StealthPilot` で逃げて目的物と出口へ向かう（見つかってから脱出する経路の確認）。
- **Unity**（`Game.Unity`）
  - `HushWardStage`：Stage Prefab（床・壁・木箱の Tilemap、目的物・自機・警備員）。生成スクリプト（`HushWardSceneBuilder`）が Core の施設から作り、既にあれば上書きせず `Mismatch` で照合する。照合は描画に要る部品（Tilemap・タイルアセット・自機の向きの絵・忍び足の絵・Renderer・警備員の部品）がそろっているか、壁（奥・手前の面）・木箱・床・入口のタイルの種類、目的物・入口・警備員の始めの位置まで見て、欠けや違いは例外ではなく理由で返す。1 タイル = 1 ワールド単位。Tick の状態をそのまま描き、補間しない。
  - `HushWardGuardView`：警備員 1 人の描画。視界の扇は判定と同じ `Vision.Fan` の光線の距離から作る Mesh（状態で色が変わる：巡回 黄・調査 橙・追跡 赤・捜索 紫）。頭の上に状態の記号（調査 ?・追跡 !・捜索 …）と気づき値のゲージ。F1 の詳しい表示では巡回路（線）・向かう先（十字）・最後に見た位置（赤い輪）も出す。
  - 足音が届いたマスは、Core と同じ `Hearing` で数え直して薄い色で重ね、14 Tick で消す（走り 橙・歩き 白・忍び足 水色）。
  - `HushWardGame`：入力（時刻付きの意図の 1 本の列）・カメラ（施設全体。上端の壁の行に HUD の帯が重なる）・HUD（PanelRenderer：警戒レベル・目的物・時間・発見回数・F1 の一覧）・音（矩形波、`AudioPolicy` で消音）。
  - `HushWardSettings`：試合の設定・音量・案内と足音の表示時間・扇の光線の本数。生成スクリプトはこのアセットを上書きしない。
  - 見た目は生成したドット絵（`HushWardArtGenerator`、1 タイル 32 px・Point）。
- 物理エンジンは使わない（衝突・視線・音は Core の整数演算）。

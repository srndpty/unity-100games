# 023. 探索型アクション — MOSSLIGHT DEPTHS（仮）

仕様書：[plan/games/023-metroidvania.md](../../plan/games/023-metroidvania.md)　実装計画：[plan/games/023-metroidvania-implementation.md](../../plan/games/023-metroidvania-implementation.md)

1 画面の部屋を 5 つつないだ小さな探索アクション。二段ジャンプと破壊ショットを手に入れるたびに、通れなかった高い段とひびの壁の先へ進めるようになり、来た道を戻って塔の上のボスを倒す。参考作品からはメカニクスだけを採用し、名称と見た目は独自に作る。

## 環境

- Unity：6000.6.9f1（Universal 2D、C# 9.0）
- 対象プラットフォーム：Windows (StandaloneWindows64)
- 入力方式：Input System のキーボード。HUD は PanelRenderer / UI Toolkit
- 共通パッケージ：[com.games100.tile-motion](../../packages/com.games100.tile-motion/)（整数の箱・タイルとの衝突解決・接地・残り Tick・状態ハッシュ）

## 採用ルール

| 項目 | 採用ルール |
|---|---|
| 単位 | 1 タイル = 16 px = 256 単位の整数。速度は単位/Tick、60 Tick/秒。時間の設定は Tick 数。浮動小数点を使わないので Mono と .NET で同じ結果になる |
| 部屋 | 5 部屋、各 40×22 タイルの 1 画面（カメラ固定）。部屋は地図の格子に並び、扉は辺の隣の部屋の反対側の扉につながる。扉に触れた Tick に隣の部屋の到着位置へ移り、次の Tick からそこで進む |
| タイル | 空 `.`・固体 `#`・ひびの壁 `%`（壊れるまで固体）・扉 `D`（部屋の端だけ）。左右の外は壁、上下の外は空 |
| 自機 | 10×14 px。横の最高速 36、ジャンプ 84、重力 4、落下の最高速 96。押し続けたジャンプで 3.28 タイル。可変ジャンプ（上昇中に離すと 24 まで切る）・接地猶予 6 Tick・入力バッファ 6 Tick は 022 と同じ |
| 二段ジャンプ（能力） | 空中で 1 回だけ上向き 72 で跳び直す。着地で戻る。頂点で使うと 5.66 タイル。持っていなければ空中の押下はバッファで着地を待つ。接地猶予の間は地上のジャンプが優先（二段ジャンプは残る） |
| ショット | 最初から使える。向いている方向へ速さ 96 で真横に進み、40 Tick（15 タイル）で消える。同時に 2 発まで、撃ってから 10 Tick は撃てない。押し始めにだけ撃つ（押したままでは連射しない）。体の中から出るので、壁に密着しても壁の中に生まれない |
| 破壊ショット（能力） | 取得後に撃った弾は、止まった固体の列のうち弾の高さのひびの壁を壊す（ふつう 1 タイル）。**未取得の弾ではひびの壁は壊れない**。壊れるかは撃った時点で決まる |
| ゲート | 高い段：5 タイル（`Rooms.GateRise`）。1 回のジャンプでは届かず、二段ジャンプなら届く。足場の段差は 3 タイル（`StepRise`）で 1 回で届く。設定の検証で自機を実際に動かして確かめる（`JumpReach`）。ひびの壁：塔の右の通路を床から天井までふさぐ |
| 敵 | 歩く敵：速さ 8 で往復し、壁と足場の端で折り返す。体力 2。弾 1 発で 1 減る |
| 被弾 | 敵・ボスに触れると 1、ボスの弾で 1 減る。押し戻し（横 32・上 40、12 Tick は横入力が効かない）と、被弾の次の Tick から 60 Tick の無敵。1 Tick に受けるのは最初に触れた 1 つだけ |
| 接触の判定 | 動く物どうし（弾と敵、自機と敵・ボス・ボスの弾）は相対軌跡の掃引で最初に触れた時刻を求める（021 の EnemyContact）。止まっている物（アイテム・セーブ像・扉）は 022 と同じく「横 → 縦」の 2 区間の経路で判定する |
| 回復 | 回復の実（2 個）：体力 +2（最大 5 まで）。取ると二度と出ない。セーブ像（拠点・塔）：触れると全回復し、世界の状態を記録する。触れたまま止まっていても記録し直さない（離れて触れ直すと記録する） |
| ボス | 28×28 px、体力 20。乱数を使わず「構え 60 Tick → 自機のほうへ突進（速さ 48）→ 壁で気絶 40 Tick → 自機のほうへ 3 方向の弾（速さ 56 と斜め 2 本）」を繰り返す。倒すと勝ち |
| 部屋をまたいで保持 | 取得した能力・壊したひびの壁・取ったアイテム・訪れた部屋（`WorldState`）、自機の体力と向き |
| 部屋ごとに初めから | 敵（入るたびに出現位置・満タン）・自機とボスの弾・ボス（部屋を出ると体力満タンで戻る） |
| 部屋の移動 | 自機は到着位置に置き直し、速さ・猶予・バッファ・押し戻しは捨てる。体力・無敵・押しているキーは持ち越す（押したままのジャンプで移った先ですぐに跳ばない） |
| 敗北と再開 | 体力 0、または扉でない所から部屋の下へ落ちる（その Tick に扉に触れていない）とゲームオーバー。Enter で**最後に触れたセーブ像の時点の世界の状態**に戻し、その像の前から体力満タンで再開。セーブの後に取った能力・アイテム・壊した壁は失う。試合の開始位置が最初のセーブ。死亡回数を数える。ファイルには保存しない（起動中だけ） |
| 勝利 | ボスを倒した Tick で終わり。その Tick の被弾は数えない。結果画面に遊んだ時間・死亡回数・取ったアイテム数 |
| 終了後 | ゲームオーバー・勝利の後の Tick と入力は状態を変えない |
| 1 Tick の順序 | 自機（接地 → 押し始め → 接地猶予 → ジャンプ（地上・猶予 ＞ 二段）→ 横の加減速 → 可変ジャンプ → 重力 → 横移動 → 縦移動 → 接地 → 撃つ）→ 歩く敵・ボス → 自機の弾（地形と敵・ボス。ボスを倒せばここで勝ち）→ ボスの弾 → アイテム・セーブ像 → 被弾 → 扉への接触を求める → 部屋の下への落下（扉に触れていなければ倒れる）→ 扉。被弾で体力 0 になった Tick は扉を通らない |
| 時刻と Tick | 022 と同じ。入力は起きた時刻を持ち、その時刻を含む Tick から効く。1 フレームで進めるのは入力と時計で合わせて 5 Tick まで。遊んだ時間は飛ばした区間も数える |
| 乱数 | 使わない。入力の列だけで結果が決まる |

### 部屋の配置

```
 [4 塔：破壊ショット・セーブ像]──(ひびの壁)──[5 ボスの間]
        │ 床の穴 ↕ 上の扉（高い段：二段ジャンプ）
 [1 拠点：開始・セーブ像]──[2 回廊：敵 2・ひびの壁の奥に回復の実]──[3 洞穴：穴の底に二段ジャンプ]
```

- 3 の二段ジャンプは高さ 5 タイルの穴の底にあり、取らないと戻れない。
- 2 のひびの壁は、破壊ショットを取った後に戻ると開けられる（寄り道）。
- 1 → 4 は二段ジャンプ、4 → 5 は破壊ショットのゲート。

## 設計上の選択

| 層 | 責務 |
|---|---|
| パッケージ | `Box`・`Units`・`ISolidGrid`・`BodyMotion`・`GroundProbe`・`Countdown`・`StateHash`（021・022 から抽出） |
| Core | `TileMap`・`Terrain`（部屋の地形と、壊れた壁を重ねた衝突用の地形）、`Room`・`Rooms`・`World`（文字の地図・5 部屋・格子と扉のつながり・アイテムの通し番号）、`WorldState`（部屋をまたぐ状態）、`Player`、`Shot`・`Walker`・`Boss`・`Bullet`、`Sweep`（相対軌跡の掃引）、`RoomRun`（今いる部屋の 1 Tick）、`Expedition`（試合：部屋の移動・セーブと再開・勝敗・ハッシュ・複製）、`ExplorerConfig`・`JumpReach`（設定とゲートの検証） |
| App | `ExploreFlow`（画面遷移・時刻付きの入力から Tick への対応）、`Intent`・`HeldControls`、`RouteScript`・`RoutePilot`・`Routes`（部屋の滞在ごとの入力の列）、`BossPilot`（ボス戦の先読みの操縦役） |
| Unity | `MossDepthsGame`（時刻付きの入力・カメラ・HUD と地図・案内・音）、`MossDepthsStage`（1 部屋の描画：Tilemap の地形・ひびの壁・扉、セーブ像・アイテム・敵・ボス・自機・弾）、`MossDepthsSettings`（設定アセット）、`MossDepthsArtGenerator`・`MossDepthsSceneBuilder`（素材・Stage Prefab・シーンの生成）、`MossDepthsCaptureScenario`（撮影台本） |

- **物理エンジンには何も委譲しない。** 衝突解決は共通パッケージの整数の 1 軸ずつの解決。
- **能力はフラグ（`Ability`）で持ち、ゲートは能力の有無で地形の振る舞いが変わる場所として作る。** 二段ジャンプは自機のジャンプの解決で、破壊ショットは弾が壁で止まったときに見る。扉そのものには条件を持たせず、ゲートの前の地形（高い段・ひびの壁）が通れるかを能力で決める。
- **世界の状態と部屋の状態を分ける。** `WorldState` は部屋をまたいで残り、セーブ像はその複製を記録する。`RoomRun` は部屋に入るたびに作り直し、敵と弾を持つ。壊れた壁は `WorldState` の配列を `Terrain` が共有して見るので、壊した瞬間から衝突にも保存にも反映される。
- **再開は記録の複製に戻す。** セーブの後に取った物を失う規則が、複製を戻すだけで成り立つ。記録はその後の進行で変わらない（複製）。
- **ゲートの検証は式ではなく自機を動かして行う。** `JumpReach` が `Player.Step` で跳んだ高さを測り、設定の検証で「1 回では高い段に届かず、二段なら届く」を確かめる（021 の Traversal の考え方）。
- **ボスの部屋の入口には段を置かない。** 試作で入口に 1 タイルの段を置いたところ、ボスの突進が段で止まり、真横の弾も段で消えて、段の後ろが安全地帯になった。
- **5 部屋は Core の地図から作った Stage Prefab。** 生成スクリプトが Tilemap（石・苔・ひびの壁・扉の光）と、セーブ像・アイテム・敵・ボス・自機・弾を置いた Prefab を部屋ごとに作るので、プレイ前から Scene ビューで見える。既にある Prefab は上書きせず、地形に加えてセーブ像・アイテム（種類と絵）・敵・ボスの位置を Core の地図から出した期待値と比べ、違えば生成を止める（数だけでは 1 マスずれた玉を見逃す）。シーンには 5 部屋を同じ位置に置き、今の部屋だけを表示する。
- **ひびの壁の表示は世界の状態に合わせて毎回そろえる。** 壊れていればタイルを消し、セーブからの再開やタイトルへ戻ったときに壊れていなければ置き直す。
- **地図は訪れた部屋だけを描く。** HUD の右上に小さく、一時停止中は大きく出す。今いる部屋を明るく、セーブ像のある部屋とボスの部屋を色で分ける。
- **案内（能力を取った・セーブした・回復した・再開した）は試合の Tick で消す。** 実時間を使わないので、撮影でも毎回同じ絵になる。被弾後の無敵の点滅も Tick で決める。
- **自動操縦は滞在ごとの入力の列と、ボス戦の先読み。** 列は App テストの `RouteFinder`（`[Explicit]`）が小目標（玉を取る・像に触れる・扉を抜ける）を順に重み付き A* で探したもので、被弾しない。ボス戦は `BossPilot` が試合の複製で 6 通りの手を 72 Tick 先読みする。

## テスト

| 種類 | 場所 | 件数 | 実行 |
|---|---|---|---|
| パッケージ | `packages/com.games100.tile-motion/Tests/` | 10 | `dev test`（.NET）／`dev test 023 -Unity`（Mono） |
| Core | `Assets/Tests/Core/` | 78 | 同上 |
| App | `Assets/Tests/App/` | 22（＋ルート探索の道具 1、`[Explicit]`） | 同上 |
| PlayMode | `Assets/Tests/Unity/` | 36（実シーン 20、共通証跡公開 16） | `dev test 023 -Unity -Mode PlayMode` |

- 題材固有：
  - 未取得の能力ではゲートを通れない（`GateTests`）：拠点で二段ジャンプなしに到達できる範囲を尽くして塔へ行けず、足は高い段に届かない（約 10 万手）。二段ジャンプの玉を取っただけで能力のない状態では、穴の底から回廊へ戻れない（約 14 万手）。ひびの壁の列は床から天井まで通れず、能力のない弾では壊れない。
  - 取得後に戻れる（`GateTests`・`RouteTests`）：二段ジャンプを取ると穴から回廊へ戻れ、拠点から塔へ行ける。破壊ショットで壁を開けてボスの部屋へ。通しの道順が「拠点 → 回廊 → 洞穴 → 回廊 → 拠点 → 塔 → ボスの間」になる。
  - 部屋再入室で重要状態が保持される（`PersistenceTests`）：壊した壁・取った実・能力・体力が出入りで残り、敵は出現位置・満タンに戻り、弾は部屋をまたがない。
- 到達範囲の探索（`Reachability`）は、位置を横 1/2・縦 1/4 タイル、速さを数単位ずつにまとめた近似。届く高さの差が大きい（1 回 3.28 タイルに対し段 5 タイル）場面でだけ「届かない」の根拠に使う。
- セーブと再開（`SaveTests`）：像で記録・全回復、触れたままでは記録し直さない、セーブ後に取った能力・アイテムは失いセーブ前の物は残る、像がなければ開始位置から。
- 完走：`Routes` と `BossPilot` で全編を 2565 Tick で勝ち、最終状態のハッシュ `0xD0072BE8` を .NET と Mono の両方で照合する。
- フレームレート：拠点 → 回廊 → 洞穴のルートを時刻付きのキー操作に直し、30・60・144・240fps と不規則な間隔で状態のハッシュが一致。
- 実シーン：キーで動く・跳ぶ・二段ジャンプ（能力の後だけ）・撃つ、部屋の切り替えと地図・案内、ひびの壁の表示（壊れる・入り直しても壊れたまま・再開で戻る）、ゲームオーバーと再開・勝利の画面、被弾の姿と点滅、タイトルへ戻った表示が起動直後と一致、一時停止・HUD のボタン・フォーカスの喪失、設定アセットの値で全編が勝てること。

証跡と検証の記録は [evidence/README.md](evidence/README.md)。

## 未実装範囲

- 仕様書の Out of scope：広大なメトロイドヴァニア、複雑な装備システム、アセットの大量制作・追加ステージ量産・製品化要素。

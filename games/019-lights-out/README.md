# 019. Lights Out — FIREFLY HUSH

仕様書：[plan/games/019-lights-out.md](../../plan/games/019-lights-out.md)

夜の草むらに灯った蛍を、すべてしずめる 5×5 の盤面パズル。参考作品からはメカニクスだけを採用し、名称と見た目は独自に作っている。

## 環境

- Unity：6000.6.9f1（Universal 2D、C# 9.0）
- 対象プラットフォーム：Windows (StandaloneWindows64)
- 入力方式：Input System のマウスとキーボード。HUD は PanelRenderer / UI Toolkit。日本語は Windows の Yu Gothic で表示する

## 起動手順

```
dev gui 019      # エディタで開く
dev build 019    # Windows ビルド
dev run 019      # ビルドを起動
dev capture 019  # 証跡を evidence/ に撮る
```

シーンは `Assets/Scenes/FireflyHush.unity`。

## 採用ルール

| 項目 | 採用ルール |
|---|---|
| 盤面 | 5×5 固定 |
| 押下 | 押したマスと上下左右（盤内のみ、端は折り返さない）の点灯を反転する |
| 生成 | 試合のシードから重複のない k マス（設定、既定 10）を選んで「既知解」とし、全消灯の盤にその押下を適用した盤を出題する。全消灯になったら引き直す |
| 手数 | 押すたびに +1（同じマスを 2 回押しても 2 手） |
| クリア | 全消灯になった時点で勝利。結果画面に手数と最短手数を出す |
| あきらめる | 一時停止から選ぶと試合を終え、その時点の盤の最短解のマスに印を出す |
| やり直す | 一時停止から選ぶと出題時の盤に戻し、手数を 0 にする（同じ問題のまま） |
| 終了後の操作 | 盤への操作はすべて拒否し、状態を変えない |
| 再戦 | 1 試合 1 シード。起動時の値から試合ごとに 1 ずつ進め、再戦では必ず新しいシードを使う |

手数の上限はない。最短手数はプレイ中には見せず、結果画面でだけ出す。

### 盤のモデル（GF(2)）

- 盤は 25 ビットの整数で、ビット `y * 5 + x` が 1 なら点灯。各マスの押下は「反転するマスの集合」のマスク（`PressMasks`）との XOR。押下は 2 を法とする加算なので、押す順序は結果に影響せず、同じマスを 2 回押すと元に戻る。したがって解は「各マスを押すか押さないか」の 25 ビットで表せる。
- 解くことは、係数行列の行 j を「マス j を反転させる押下の集合」とする 25 元の連立一次方程式 `A x = b`（GF(2)）を解くことと同じ。行を `uint` のビット列として掃き出す（`Gf2Solver`）。
- 5×5 の係数行列は階数 23 で、核（押しても盤が変わらない押下）は 2 次元。可解な盤は全体の 4 分の 1（2^23 通り）で、それぞれに解が 4 通りある。最短解は特解に核の 4 通りの組み合わせを足したうち、押下数が最少のもの。
- 点灯を直接乱数で決めると 4 分の 3 は解けないので、既知の解から逆向きに作る（`PuzzleGenerator`）。全消灯の盤に解を適用した盤は、同じ解で必ず全消灯に戻る。全消灯になるのは選んだ押下が核の非零の元（3 通り）に一致したときだけなので、引き直しは事実上起きないが、上限（64 回）を超えたら例外にする。
- 既知解の押下数は k だが、核を足すとより少ない手数で解けることがある。最短手数はソルバで求め直している。

## 設計上の選択

| 層 | 責務 |
|---|---|
| Core | `LightsBoard`（25 ビットの盤）、`PressMasks`（押下の反転マスク）、`Gf2Solver`（可解判定・解・核・最短解）、`PuzzleGenerator` / `Puzzle`（既知解からの生成）、`LightsOutGame`（試合：手数・クリア・あきらめ・やり直し）、`LightsOutConfig`（設定）、`SeededRandom`、`BitCount` |
| App | `LightsOutFlow`（画面遷移と意図の処理）、`Intent`（入力を変換した意図）、`BoardCursor`（キーボードのカーソル）、`BoardLayout`（マスの置き場所とクリックの当たり判定）、`Autopilot`（最短解を 1 マスずつ押す操縦役） |
| Unity | `FireflyHushGame`（入力・HUD・音）、`FireflyHushBoardView`（描画）、`FireflyHushSettings`（設定アセット）、シーンと素材の生成、撮影台本 |

- **種類の違う操作も 1 本の列で処理する。** キー・クリック・HUD ボタンを `Intent` に変えて押した順に `LightsOutFlow.Apply` へ渡す。終了ボタンも同じ列を通り、フォーカス復帰直後のクリックとして捨てられる。
- **クリックしたマスは押した瞬間の位置で決める。** 処理する Update までにマウスが動いても別のマスを押さない。マスの間の隙間は押さない。
- **描画と当たり判定は同じ `BoardLayout` を使う。** Stage Prefab のマスの配置も生成スクリプトが同じ計算で置いている。
- **灯の演出は見た目だけ。** 盤の状態は押した時点で変わり、灯の明るさは短い時間（設定、既定 0.18 秒）で追いつく。撮影中は補間せずその状態を描く。
- **タイトルの飾りは固定の形を描く。** 描画のために試合を作らない。
- **あきらめたときの解答は、あきらめた時点の盤の最短解。** 出題時の盤の解ではないので、途中まで押した分を差し引いた押し方になる。
- **物理エンジンは使わない。** ターン制で、時間にも依存しない。

設定アセットは `Assets/Game/Unity/FireflyHushSettings.asset`。問題を作るときに押すマスの数（1〜25）、音量、灯の演出時間を調整できる。盤の大きさは設定に出していない（大サイズ対応は Out of scope）。

シーンの再生成：

```
unity run games/019-lights-out -- -executeMethod Game.Unity.Editor.FireflyHushSceneBuilder.Build
```

素材は `FireflyHushArtGenerator` が図形から描き出した PNG。再生成は既存のファイル、そのインポート設定、Stage Prefab を上書きしない。

## テスト

| 種類 | 場所 | 件数 | 実行方法 |
|---|---|---:|---|
| Core | `Assets/Tests/Core/` | 57 | `dev test` |
| App | `Assets/Tests/App/` | 33 | `dev test` |
| EditMode（Core/App を Mono で実行） | 同上 | 90 | `dev test 019 -Unity` |
| PlayMode（実シーン19、共通証跡16） | `Assets/Tests/Unity/` | 35 | `dev test 019 -Unity -Mode PlayMode` |

- 押下は、bool の 2 次元配列で 1 マスずつ反転する素朴な参照実装と全 25 マスで照合している。
- ソルバの可解判定と最短解は、素朴な「ライト追い」（1 行目 32 通りの総当たりで全解を列挙）と乱数の盤で照合している。
- 生成盤は押下数 1〜25 の全範囲で必ず解けることを確かめ、生成結果のハッシュを .NET と Mono の両方で固定値と照合している（整数だけで作るので一致する）。

結果と画面証跡は [evidence/README.md](evidence/README.md) に記録している。

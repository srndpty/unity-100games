# 振り返り：001. Pong

## 新たに学んだ点

- 衝突を「1 Tick の移動線分と面の交差」で解くと、すり抜けと二重ヒットが同時に防げ、進行方向の考慮も自然に入る。
- Unity 6 のプロジェクト全体の Input Actions（`InputSystem.actions`）なら、アセットの参照を配線せずにアクション名だけで入力を読める。
- バッチモードの PlayMode テストでは、ゲームビューにフォーカスがないため入力が捨てられる。テスト中だけ `InputSettings` でフォーカスを無視させる必要がある。

## 想定との差

- `InputTestFixture` は入力システムを初期化し直すため `InputSystem.actions` が null になり、プロジェクト全体の Actions と併用できなかった。仮想キーボードに状態イベントを送る方式に変えた。
- エディタスクリプトでシーンを開くと未使用アセットがアンロードされ、直前に作ったアセットへの参照が切れた。アセットはシーンを開いた後に読み込む。
- Core の設定を Unity でシリアライズするには公開フィールドが必要で、アナライザー（CA1051）と衝突した。Core に限って無効化した。

## 次回の改善点

- シーン生成スクリプト・固定刻みの進行・白スプライト生成は次の題材でも使いそう。3 題で使ったら共通パッケージへの抽出を検討する。
- 結果画面のスクリーンショットは、実ウィンドウを操作する方式だと作業中の画面を奪う。証跡はゲーム内から撮る仕組み（コマンドライン引数で自動撮影など）を用意したい。
- App 層は Unity 非依存にしたので、Core と同様に dotnet でもテストできるようにすると CI で検証できる範囲が広がる。

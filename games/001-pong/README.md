# 001. Pong

仕様書：[plan/games/001-pong.md](../../plan/games/001-pong.md)

プレイヤー（左）と CPU（右）が打ち合い、先に 5 点取った方が勝ち。

## 環境

- Unity：6000.6.9f1（Universal 2D テンプレート）
- 対象プラットフォーム：Windows (StandaloneWindows64)
- 入力方式：Input System のプロジェクト全体の Input Actions（`Assets/Settings/InputSystem_Actions.inputactions`）。キーボードとゲームパッド

## 起動手順

```
dev gui 001      # エディタで開く（Assets/Scenes/Pong.unity）
dev build 001    # Windows ビルド
dev run 001      # ビルドを起動
dev capture 001  # 証跡を evidence/ に撮る（画像は captures/<画像世代>/、撮影記録は runs/）（自動で終了）
```

シーンは [PongSceneBuilder](Assets/Game/Unity/Editor/PongSceneBuilder.cs) が生成する。シーン構成を変えるときはこのスクリプトを直して再生成する（エディタのメニュー「Game > Rebuild Pong Scene」、またはバッチで `unity run games/001-pong -- -executeMethod Game.Unity.Editor.PongSceneBuilder.Build`）。

## 操作

| 操作 | キーボード | ゲームパッド |
|---|---|---|
| パドル上下 | W / S、↑ / ↓ | 左スティック、十字キー |
| 開始・再戦 | Enter、Space | South ボタン |
| タイトルへ戻る（タイトルでは終了） | Esc | East ボタン |

## 採用ルール

| 項目 | 採用した内容 |
|---|---|
| 勝利条件 | 先に 5 点（`WinScore`） |
| コート | 幅 16 × 高さ 9（ワールド単位）。上下は壁で反射、左右がゴール |
| 得点 | ボールが**完全に**ゴールラインを越えたら、反対側の得点 |
| サーブ | 試合開始は向きを乱数で決定。得点後は**失点した側**へ。1 秒待ってから中央から発射。角度は水平 ±30° の範囲で乱数 |
| パドル反射 | 当たった位置で角度が決まる。中央なら水平、端ほど急になり、最大 55°。上側で打てば上へ。動いているパドルは、ボールが面に届いた瞬間の位置で判定する |
| 再戦 | 結果画面からの再戦は、新しいシードの独立した試合として始める |
| 加速 | パドルで打つたびに +0.5、最高 16（サーブ 7） |
| パドルの側面 | 判定しない。ボールがパドルの内側の面を越えた後は返せず、そのままゴールへ |
| CPU | 向かってくるボールの高さを追い、離れていく間は中央へ戻る。最高速度はプレイヤーの約 5.5 割。狙いに毎回ぶれがあり、ぶれが大きいとパドルの端を外して空振りする。速い球には追いつけない |

パラメータは [PongSettings.asset](Assets/Game/Unity/PongSettings.asset) で調整できる。

## 設計上の選択

| アセンブリ | 主なクラス | 責務 |
|---|---|---|
| `Game.Core` | `BallSim`、`MatchState`、`Paddle`、`CpuController`、`SeededRandom` | ルール。Unity 非依存で、dotnet でもテストする |
| `Game.App` | `PongFlow`、`SeededMatch` | 画面遷移（タイトル → 試合 → 結果 → 再戦）と、実時間から固定刻み（60 Tick/秒）への変換。1 つのシードから試合と CPU を組み立てる。Unity 非依存で、dotnet でもテストする |
| `Game.Unity` | `PongGame`、`CourtView`、`CourtFraming`、`PongHud`、`PongAudio` | 入力の読み取り、スプライト描画、画面比率に合わせたカメラ、UI Toolkit（PanelRenderer）の HUD、効果音 |

- **ボールの移動は掃引判定。** 1 Tick の移動を線分として扱い、壁・パドルのうち最も早く当たるものから順に処理する。高速でもパドルをすり抜けない。
- **パドルとの衝突は進行方向を考慮する。** パドルへ向かっていて、かつその Tick 中に面を越える場合だけ反射する。離れていくボールや、すでに面を越えたボールとは衝突しない。
- **パドルも Tick 中に等速で動いたとみなす。** ボールが面に届いた時刻でのパドル位置と比べ、反射角もその位置から決める。Tick の途中でコートの端に着いたら、そこで止まったとして位置を求める。
- **1 Tick の接触回数には上限（4 回）がある。** 超えたら時間を取りこぼさないよう例外にする。設定の検証で、最高速度での 1 Tick の移動量を「上下の壁の間隔」と「左右のパドル面の間隔」の短い方より小さく抑えている。こうすると 1 Tick の接触は最大 3 回（壁 → パドル → 同じ壁）に収まる（理由は `PongConfig.MaxTravelPerTick` の説明、確認は境界値テストと乱択テスト）。
- **画面比率に依存しない。** カメラの大きさを毎フレーム画面の縦横比から決め、コート全体と余白が収まるようにする（16:9 なら高さ、4:3 や 1:1 では幅で決まる）。
- **物理エンジンは使わない。** 衝突も含めて Core の自前計算で、Unity の 2D 物理には何も委譲していない。描画は Core の状態を写すだけ。
- **再現性。** 乱数は試合（サーブ）用と CPU 用でシードを分けた xorshift。System.Random は Mono と .NET で系列が一致する保証がないため使わない。同じシードと入力列なら勝敗・スコア・Tick 数・ボール位置まで一致することをテストしている。再戦を何度繰り返しても、各試合はそのシードと入力列だけで単独に再現できる。
- **描画は Tick 間を補間する。** 60Hz の Tick と描画フレームのずれは `MatchSnapshot.Interpolate` で埋める。得点直後はボールを中央へ瞬間移動させるため補間しない。
- **処理落ち対策。** 1 フレームで処理する Tick は最大 5 回で、それ以上溜まった時間は切り捨てる。
- **証跡は撮影台本で撮る。** [PongCaptureScenario](Assets/Game/Unity/PongCaptureScenario.cs) がタイトル → 試合中 → 結果を自動で進めて撮影する（`dev capture 001`）。撮影中は固定シードで、試合を Tick 単位で進め、補間せずにその Tick の状態を描くので、同じビルドなら毎回同じ画像になる。プレイヤー入力は読まず、音も鳴らさない。撮った一式は manifest と照合してから、画像は内容で決まる画像世代、記録は撮影ごとの撮影記録として公開し、`evidence/current.json` で指す。
- **実行時に作ったリソースは破棄する。** テクスチャ・スプライト（`CourtView`）と効果音のクリップ（`PongAudio`）は、`PongGame.OnDestroy` で破棄する。
- **素材は作らない。** スプライトは実行時に生成した 1×1 の白テクスチャ、効果音は実行時に合成した矩形波。
- **音量は控えめ。** 矩形波は耳に刺さるため振幅を 0.05 に抑えた。テストなどのバッチ実行（`Application.isBatchMode`）では消音する。

## テスト

| 種類 | 場所 | 実行 | 件数 |
|---|---|---|---:|
| Core（EditMode / dotnet） | `Assets/Tests/Core/` | `dev test`（CI でも実行） | 39 |
| App（EditMode / dotnet） | `Assets/Tests/App/` | `dev test`（CI でも実行） | 14 |
| シーン・入力・カメラ・証跡（PlayMode） | `Assets/Tests/Unity/` | `dev test 001 -Unity -Mode PlayMode` | 20 |

PlayMode テストは実際のシーンを読み込み、仮想キーボードから開始・パドル操作・タイトル復帰・決着・再戦までを確認する。カメラは 16:9・16:10・4:3・1:1 でコートとパドルが画面内に収まることを確認する。証跡の公開は、前の世代のファイルが見えないこと、manifest.json と一致しない一式（欠け・改ざん・余計なファイル・重複・パスを含む名前など）を拒否すること、どのファイル操作で失敗してもポインタが完全な組を指すこと（失敗の注入）、同じ画像を別のビルドで撮り直すと画像世代は同じで撮影記録は新しくなること、名前と中身が合わない既存の世代を使わないこと、強制終了で残った古い一時フォルダを片付けること、同時に公開しないことを確認する。

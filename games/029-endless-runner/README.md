# 029. エンドレスランナー — CINDER LANES（仮）

仕様書：[plan/games/029-endless-runner.md](../../plan/games/029-endless-runner.md)　実装計画：[plan/games/029-endless-runner-implementation.md](../../plan/games/029-endless-runner-implementation.md)

3 本のレーンを自動で走り続け、レーン移動・ジャンプ・スライドで障害物を避ける。障害物はチャンク（数行の配置の表）を無限につなげて並べ、どれも通り抜けられることを設定の検証で保証する。ぶつかったら終わりで、進んだ距離が得点。参考作品からはメカニクスだけを採用し、名称と見た目は独自に作る。

## 環境

- Unity：6000.6.9f1（Universal 3D、C# 9.0）
- 対象プラットフォーム：Windows (StandaloneWindows64)
- 入力方式：Input System のキーボード。HUD は PanelRenderer / UI Toolkit
- 共通パッケージ：[com.games100.tile-motion](../../packages/com.games100.tile-motion/)（`Units`・残り Tick の `Countdown`・状態ハッシュ `StateHash`）、[com.games100.int-geometry](../../packages/com.games100.int-geometry/)（シード付き乱数 `SeededRandom`）

## 操作

| 入力 | タイトル | プレイ中 | 一時停止 | 結果 |
|---|---|---|---|---|
| ← → / A D | — | 隣のレーンへ移る | — | — |
| ↑ / W / Space | （Space：はじめる） | ジャンプ | （Space：つづける） | （Space：もう一度） |
| ↓ / S | — | スライド | — | — |
| Enter | はじめる | — | つづける | もう一度 |
| Esc / P | — | 一時停止 | つづける | — |
| R | — | — | 最初から | 最初から |
| T | — | — | タイトルへ | タイトルへ |

試合を始めた（再開した）押下はジャンプにしない（Space を決定とジャンプの両方に割り当てているため）。HUD のボタンでも同じ操作ができる。

## 採用ルール

| 項目 | 採用ルール |
|---|---|
| 単位 | 長さは 1 m = 256 単位の整数、速さは単位/Tick、60 Tick/秒。時間の設定は Tick 数。進んだ距離は long。浮動小数点を使わないので Mono と .NET で同じ結果になる |
| 座標 | x＝横（中央のレーンが 0、レーンの間隔 2.5 m）、y＝高さ、z＝進行方向。自機は毎 Tick z へ自動で進む |
| 自機の当たり箱 | 幅 0.75 m・奥行き 0.5 m・高さ 1.75 m（スライド中 0.625 m）。Tick の間はその Tick の終わりの高さで掃引する |
| レーン移動 | 隣のレーンへ 8 Tick で移る（横位置は線形）。端より外への移動は捨てる。移動中の次の移動は先行入力 |
| ジャンプ | 接地中だけ。初速 32・重力 2 の整数の放物運動（最高 1.06 m、33 Tick で着地）。空中のジャンプは先行入力（二段ジャンプなし） |
| スライド | 接地中に 36 Tick（押した Tick を含む）。スライド中のスライドは捨てる（延長しない）。スライド中のジャンプはスライドを解いて跳ぶ。**空中のスライドは先行入力**で、着地した次の Tick に始まる（計画にあった急降下は入れなかった） |
| 先行入力 | 横と縦にそれぞれ 1 つ。押した Tick を含めて 10 Tick の間、効くまで毎 Tick 試す。新しい押下で上書き |
| 1 Tick の操作 | 横（← →）と縦（ジャンプ・スライド）を 1 つずつ。同じ Tick に両方押せば両方効く |
| 障害物 | どれも行の中央に置く奥行き 0.5 m の板で、幅はレーンいっぱい。動かない。**Wall**（高さ 3 m。レーン移動で避ける）／**Hurdle**（高さ 0.625 m。ジャンプで越える）／**Beam**（下端 1 m〜3 m。スライドでくぐる）。壁は試遊の指示で行いっぱいの厚さから板にした（通り過ぎた後の横移動でぶつからない） |
| 衝突 | **Hurdle は前・横から触れたときだけ当たり**で、上から触れた（高さの軸が最後に、下向きに重なり始めた）ときと、Tick の始めにもう重なっているとき（上から入った後）は踏み越えた扱いにする（角に触れたときは当たり）。自動操縦とチャンクの検証は、上から触れても当たりにする厳しい判定で道を求める（判定が甘いほうへずれるだけなので、検証の保証は崩れない）。そのほかは、自機の箱の Tick 中の直線の軌跡と障害物の箱を、各軸で重なる時刻の開区間の共通部分で判定する（整数の分数で厳密。ちょうど接するだけでは触れない。速くても薄い障害物をすり抜けない）。横からレーン移動で壁に触れても終わり。1 回触れたら試合終了 |
| チャンク | 文字の表：1 行 = 奥行き 2 m、3 文字 = 左・中・右のレーン、`.` 空・`W`・`H`・`B`。**上の行ほど奥**。入口と出口の行は空にする。難度（1〜3）と出やすさの重みを持つ。既定の 14 個は [ChunkLibrary.cs](Assets/Game/Core/ChunkLibrary.cs) |
| 到達性の検証 | 各チャンクを、出うる全ての速さ（解禁される距離の速さ〜最も速い段階）と全ての入口のレーン（止まって接地）について探索し、出口を止まった状態（接地・移動もスライドもしていない）で越えられなければ設定を拒否する（fail-closed）。入る位相（入口を越えた量 0〜速さ-1）の違いは、障害物を手前へ速さ-1 伸ばし、出口を越えうる Tick ではどれも止まった状態を求めることで覆う（十分条件）。止まった状態でつながるので、どの並びでも通り抜けられる |
| 助走と並べ方 | スタートから 30 m は障害物のない助走。その後にチャンクを隙間なく並べる。自機の前方 120 m までを並べ、後方 16 m を過ぎたチャンクは回収する。生きているチャンクは固定容量 24 のリング（前方・後方の長さと最も短いチャンクから決まる上界以上であることを検証する） |
| 難度曲線 | 速さは**チャンクの入口の距離**で決め、チャンクの中では変えない：40 + 8 ×（200 m ごとの段階、最大 5）＝ 40〜80（9.4〜18.8 m/秒）。出せるチャンクの難度は 1 +（300 m ごと）で最大 3。**1000 m で両方が上限に達し、以後は上限のまま** |
| 出現順 | 1 試合 = 1 シードの xorshift。チャンクの選択は、入口の距離で解禁された難度以下のチャンクから重みで選ぶ。選べるものが 2 つ以上なら直前と同じものは選ばない。**シードと入口の距離だけで決まり、自機の操作に依らない** |
| 得点 | 進んだ距離（m、切り捨て）。最高記録は起動している間だけ持つ（ファイル保存なし） |
| 1 Tick の順序 | 操作の反映（自機の 1 Tick：横 → 縦）→ 今いる区間の速さで前進 → 障害物との掃引 → チャンクの回収と並べ足し |
| 再戦 | 次のシード（起動時の値から 1 ずつ進める）。終わった後の Tick と入力は状態を変えない |

## 設計上の選択

- **Core**（`Game.Core`）
  - `Runner.cs`：自機の横（`LaneState`）と縦（`VerticalState`）は独立に動く値型。どちらも直前の Tick の始めの位置（`PrevX`・`PrevY`）を持つので、状態だけからその Tick の軌跡が決まる。`RunnerBody` が横と縦の先行入力を持つ。
  - `Sweep3.cs`：1 軸ずつ重なる時刻の開区間（`Span`、分数の `Moment`）を求め、共通部分で判定する。
  - `Planner.cs`：`MotionGraph` が本物の 1 Tick で取りうる横の状態（35）と縦の状態（70）を列挙し、`Planner` が「横 × 縦」の到達集合をビット集合で Tick ごとに進める。横と縦の操作は独立なので、像は横の後続と縦の後続の積になる。障害物との判定は、横・高さの軸の重なりを状態ごとに前もって求め、Tick ごとに奥行きの軸と組み合わせる（試合の衝突と同じ `Sweep3.Axis`）。チャンクの検証（`Passable`）と自動操縦の経路（`Plan`）の両方で使う。既定の 14 チャンクの検証は .NET で約 0.3 秒。
  - `RunRules.cs`：難度曲線（`Difficulty`）と、検証済みの設定とチャンクの組（`RunRules.Build`）。検査が重いので 1 つ作って試合ごとに使い回す。
  - `ChunkTrack.cs`：チャンクの固定容量のリング。並べ方は乱数と入口の距離だけで決まる。
  - `RunnerRun.cs`：試合。`Step`・`Hash`（自機の全状態・先行入力・リング・乱数まで混ぜる）・`Clone`。
- **App**（`Game.App`）
  - `RunnerFlow`：Title / Playing / Paused / Result、時刻付きの押下、1 フレームの Tick 上限、押下の列（横と縦を 1 つずつ取り、同じ側の 2 つ目で止める）、最高記録。
  - `Autopilot`：区間（助走・チャンク）に入るたびに `Planner.Plan` で出口までの操作の列を求めて再生する。試合が変わったら計画を捨てる。
- **Unity**（`Game.Unity`）
  - `CinderLanesStage`：Stage Prefab（8 m の道の区画・両脇の灯の柱・自機・障害物 3 種の見本）。**自機の奥行きを原点（z = 0）にして描く**：Core の long の距離から「障害物の z − 自機の z」を作ってから float にするので、長く走っても位置の精度が落ちない。障害物は見本から作った固定数のプール（種類ごとに「生きているチャンクの上限 × 1 チャンクのその種類の最大数」）、道の区画は 20 個を置き直す。試合中に GameObject を作らない・壊さない。単位の立方体を当たり箱の大きさに拡大して箱の中心に置くので、見た目と当たりが一致する。ぶつかった試合は、触れた時刻の位置で止めて描く。
  - 自機が通り過ぎた障害物（奥の面が自機の中心より後ろ）は、カメラと自機の間で視界をふさがないようにする：Beam と自機と同じレーンのものはすぐ描かない。隣のレーンの壁・Hurdle は半透明（不透明度 0.12）にし、1.5 m 後ろで描かない。
  - 自機の見た目はユニティちゃん（下記）。モーションは待機・走り・ジャンプ・スライド・被弾の 5 つで、**再生位置を実時間で進めず Core の状態から毎回決める**（走りは進んだ距離 2.6 m で 1 周期、ジャンプは跳んでからの Tick、スライドは残り Tick）。ジャンプ・スライドの後は直前の姿勢から走りへ 12 Tick かけてブレンドする（Animator のクロスフェードを移り具合を指定して作る）。ぶつかった後は倒れるモーション（DAMAGED01）を結果画面の間に表示の時計で進め（撮影では台本が秒数を渡す）、寝そべったところで止める（止める位置は生成スクリプトが頭の高さから求める。起き上がりは見せない）。ぶつかった直後の 0.45 秒はカメラを揺らす（倒れてからの秒数だけで決まる減衰する揺れ）。結果のパネルは 0.8 秒遅らせて倒れる様子を見せる。撮影は同じ絵になる。クリップの根の移動・高さ・向きはポーズに焼き込み（足元基準）、位置と高さは Core だけが決める。当たり判定は Core の箱のまま。
  - `CinderLanesGame`：入力（時刻付きの意図の 1 本の列）・カメラ（自機の 5 m 後ろ・高さ 2.8 m、横は自機の 0.45 倍だけ追う）・HUD（PanelRenderer）・音（矩形波、`AudioPolicy` で消音）。
  - `CinderLanesSettings`：試合の数値の設定アセット。チャンクの表はコードに持つ。起動時に到達性の検査を含めて `RunRules` を作る。
  - 遠くのチャンクの出現は線形フォグ（50〜112 m）で隠す。見た目はプリミティブと座標から作る模様のテクスチャ（`CinderLanesArtGenerator`）、シーンと Stage Prefab は `CinderLanesSceneBuilder` で生成する。
- 物理エンジンは使わない（衝突・ジャンプは Core の整数演算。Unity の物理・コライダーは使わず、プリミティブのコライダーも外している）。

## ユニティちゃん（自機のモデルとモーション）

- 自機は「ユニティちゃん 3D モデルデータ v1.4.0」のモデル（`unitychan.fbx`）とモーション（WAIT00・RUN00_F・JUMP00・SLIDE00・DAMAGED01）を使う。© Unity Technologies Japan/UCL
- [ユニティちゃんライセンス条項](https://unity3d.jp/unity-chan/license)（現行 3.0）に従う。第 3 条 3 項のライセンス表記を、ゲームの画面の右下（HUD の `credit`）とこの README に掲示する。第 3 条 4 項により、デジタルアセットデータを再配布するときはライセンス関連ファイル一式を同梱するので、パッケージに入っていたライセンスの一式（`Assets/UnityChan/License/`）もそのまま入れている。
- リポジトリに入れたのは、パッケージから使うものだけ（モデル・主なテクスチャ 8 枚・モーション 5 つ・ライセンス一式、約 39 MB）。ボイス・元のマテリアル・サンプルのシーンとスクリプトは入れていない。ファイルと `.meta`（GUID）はパッケージのまま置き、モーションの取り込み設定（根の動きの焼き込み）だけを `CinderLanesCharacter` が変える。
- 元のマテリアルは UTS2 用で URP では描けないので、取り込んだテクスチャから URP の Simple Lit（目の線・頬は Unlit の半透明）のマテリアルを作り直している（`Assets/Game/Unity/Art/UnityChan/`）。Unity Toon Shader（com.unity.toonshader 0.13.4-preview）も試したが、この Unity では輪郭線しか描かれなかったので使っていない。

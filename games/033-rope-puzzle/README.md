# 033. ロープ物理パズル — DEWDROP SNIP（仮）

仕様書：[plan/games/033-rope-puzzle.md](../../plan/games/033-rope-puzzle.md)　実装計画：[plan/games/033-rope-puzzle-implementation.md](../../plan/games/033-rope-puzzle-implementation.md)

ロープで吊るした露玉を、マウスでなぞって切り、花の器（目標）へ届ける。全 10 問。参考作品からはメカニクスだけを採用し、名称と見た目は独自に作る。

## 環境

- Unity：6000.6.9f1（Universal 2D、C# 9.0）
- 対象プラットフォーム：Windows (StandaloneWindows64)
- 入力方式：Input System のマウス（左ボタンを押したまま動かして切る）とキーボード
- 共通パッケージ：[com.games100.int-geometry](../../packages/com.games100.int-geometry/)（`Vec2i`・`IntMath`・`Sweep`）、[com.games100.tile-motion](../../packages/com.games100.tile-motion/)（`StateHash`）
- 物理：Unity の物理エンジン（Rigidbody・Joint）は使わない。ロープ・露玉・壁・接触は全て Core の整数の計算

## 起動手順

```
dev gui 033      # エディタで開く
dev build 033    # Windows ビルド
dev run 033      # ビルドを起動
```

## 採用ルール

| 項目 | 採用ルール |
|---|---|
| 時間 | 60 Tick/秒。物理は 1 Tick に 1 回進める。浮動小数点を使わないので Mono と .NET で同じ結果になる |
| 座標 | 1 マス = 65536 単位の整数。盤は 16 × 9 マス、原点は左下、y は上向き。問題データは 1/16 マス単位で書く |
| 点 | ロープの節点と露玉は Verlet の点（今の位置と前の位置）。速さ ＝（位置 − 前の位置）× 減衰（4086/4096、0 方向へ切り捨て）。重力を足し、1 Tick の移動を上限（20480）で切り詰める |
| ロープ | 支点（動かない）→ 節点 → … → 露玉の鎖。節の自然長は全長 ÷ 節の数。距離拘束は **伸びたときだけ縮める**（たるみは許す）。補正は逆質量で配分（支点 0・節点 32・露玉 1。露玉は節点の 32 倍重い）。反復は 24 回、ロープは問題データの順、節は支点側から |
| 切断 | なぞりの線分（前のマウスの位置 → 今の位置、離したときは離した位置まで）が節の線分と交わったら（端で触れる・重なるも含む、外積で厳密に判定）、そのロープを切る。長さ 0 のなぞり（押しただけ）は切らない |
| 1 回だけ | **1 本のロープは 1 回だけ切れる**。切れたロープの断片はもう切れず、手数も増えない。同じなぞりで同じロープの節を何本横切っても 1 回で、最初に横切った節（支点側）で切る |
| 切った後 | 切った節を境に 2 つの断片に分ける。支点側は支点から垂れ、露玉側は **露玉から外れて** 落ちる（全ての節点が盤の下 2 マスより下へ出たら消え、以後は動かない）。露玉はそのロープの拘束を以後受けない。断片は当たり判定を持たない |
| 順序 | 切断は Tick と Tick の間にだけ反映し、その時点のロープの形で判定する。1 Tick は **積分 → 拘束の反復 → 露玉の移動の制限 → 壁の押し出し → 目標・トゲの接触 → 落下** の順 |
| 露玉 | 半径 0.34 マスの円。ロープの節は壁と衝突しない（通り抜ける） |
| 壁・棚 | 軸に沿った長方形。露玉が重なったら外へ押し出し、壁へ向かう速さを消し、壁に沿う速さに摩擦（3584/4096）を掛ける（跳ね返らない）。1 Tick の移動の上限が「半径 ＋ 壁の厚さの半分」より小さいことを問題の検証で保証する（すり抜けない） |
| 目標・トゲ | どちらも円。露玉の Tick 中の軌跡（始め → 終わりの直線）で厳密に判定する（`Sweep.Touches`、ちょうど接するだけでは触れない）。**目標に触れたら成功、トゲに触れたら失敗**。同じ Tick に両方へ触れたら、どちらが先でも失敗 |
| 成功 | 目標に触れた Tick にだけ成功する。ロープで吊られたままでも、触れれば成功。時間の経過や全てのロープを切ったことでは成功しない |
| 落下 | 露玉の中心が盤の外（左・右・下）へ出たら失敗 |
| 手数 | 切ったロープの本数。やり直し（R）で初期状態に戻り手数 0。成功したら問ごとの最少手数を記録する（起動中だけ） |
| 解放 | 最初は 1 問目だけ選べる。解いた問の次の問が解放される。10 問目を解くと全問の結果を出す |
| 終了後 | 成功・失敗の後の Tick と切断は状態を変えない |
| 乱数 | 使わない（同じ問・同じ操作の列なら同じ結果） |

### 問題データ

`Assets/Game/Data/Puzzles.txt` に 10 問を書く（`puzzle`・`hint`・`par`（目安の手数）・`body`・`rope 支点x 支点y 全長 節の数`・`wall x0 y0 x1 y1`・`spike x y 半径`・`goal x y 半径`・`end`）。Core の `PuzzleBook` が読み、設定に照らして検証する（10 問ちょうど・ロープ 1〜4 本・目安の手数・ロープが初めから伸びていない・露玉が初めから壁・トゲ・目標に触れていない・壁の厚さ・盤の内）。

| 問 | 名前 | ロープ | 要素 | 目安の手数 |
|---|---|---|---|---|
| 1 | はじめの一刀 | 1 | 真下に目標 | 1 |
| 2 | ふたつの糸 | 2 | 切る順で落ちる場所が変わる | 2 |
| 3 | ふりこ | 1 | 揺れている間の時機 | 1 |
| 4 | トゲの上 | 2 | 真下にトゲ | 2 |
| 5 | 棚をすべる | 1 | 棚に落として転がす | 1 |
| 6 | 吊られたまま | 2 | 吊られたまま目標に触れる | 1 |
| 7 | 三本の糸 | 3 | 順番 | 3 |
| 8 | すき間 | 2 | 柱の間のすき間に落とす | 2 |
| 9 | 高い棚 | 1 | 振り上げた先で切る | 1 |
| 10 | 仕上げ | 3 | 棚とトゲ | 3 |

各問の解答の手順は `Assets/Game/Data/Solutions.txt`（`Tick:ロープ`）にあり、テストと撮影だけが使う（ゲームの画面には出さない）。手順は、切る順序 × 時機（12 Tick 刻み、240〜720 Tick 先まで）の総当たりで解けることを確かめて選んだ。目安の手数は、その刻みの範囲で最も少ない手数（刻みの外にもっと少ない手数の解がないとは言えない）。

### 許容誤差

- ロープは反復で拘束を解くので少し伸びる。静かに吊った状態で約 1〜2%、振り子の最下点で約 4%。テストでは 8% 未満を確かめる（2 本のロープで 20000 Tick）。
- 減衰の切り捨てで小さい速さは 0 になる（振り子は数十秒で止まる）。

## 設計上の選択

- **ロープは自前の拘束**：Verlet の点と距離拘束（位置ベースの解法）を Core の整数で解く。Unity の Joint を使わないので、Core だけで「解ける」「切ったら拘束を失う」をテストでき、全 10 問を解いた最終状態のハッシュ `0xAAC0BF2B` が .NET と Mono で一致する。ハッシュは動く状態に加え、物理の設定と問の物理的な定義の指紋（`PuzzleRun.Fingerprint`。名前・案内・目安の手数は含めない）も含む。
- **精度**：最初は 1 マス = 4096 単位で作ったが、露玉への補正が丸めで 0 になる不感帯ができ、振り子が真下から外れた位置で止まった。1 マス = 65536 単位に上げた。精度を上げて `Sweep.First` の値の上限（16384）を超えたので、接触は大きさに依らず厳密な `Sweep.Touches` で判定し、目標とトゲの先後を比べない規則（同じ Tick なら失敗）にした。
- **操作と物理の分離**：Core の `PuzzleRun.Cut` はなぞりの線分を受け取り、Tick の間にだけ呼ばれる。App（`SnipFlow`）は入力の時刻までの Tick を進めてから線分を渡す（022 の時刻付き入力）ので、フレームの長さに依らず「その時刻を含む Tick の境目」で切れる。押した点・前の点（なぞりの状態）は App が持ち、Core は知らない。
- 問題選択の札のクリック（`Choose`）は、問題選択の画面で押したクリックにだけ 1 回効く（`SnipFlow` が押下の時点の画面を覚える）。UI Toolkit の `clicked` は離したときに届くので、タイトルのクリックで問題選択へ移った直後の離しや、フォーカス復帰で捨てたクリックでは札が反応しない。
- 操縦役（`Snipper`）は解答の手順の Tick に、そのロープだけを横切る短いなぞり（`CutPlan.SwipeAcross`）を返す。撮影と App テストで共有する。
- Unity（`DewdropSnipGame`）はマウスの押下・解放と移動を PassThrough のアクションで 1 つずつ拾い、画面 → 世界 → 盤の座標に直して時刻つきで渡す。なぞりの軌跡は渡した点を Tick とともに残し、最後の点から 10 Tick 以内の点だけを描く（撮影でも同じ絵になる）。カメラの大きさは画面の縦横比から決め、盤の幅が収まるまで引く。
- 描画は Stage Prefab（`Art/DewdropSnipStage.prefab`：背景・露玉・目標・切った印・ロープの Mesh・軌跡・支点 4・壁 6・トゲ 10 の置き場）を正とし、問ごとの配置は Core の問題データから並べる（`DewdropSnipStage.Layout`）。ロープは全ての節を 1 つの Mesh の四角形で描き、節が効いているか（`PuzzleRun.IsLinkActive`）は Core の拘束と同じ判定を使う。毎フレームの描画は割り当てをしない。タイトル・問題選択の背景には、起動時に 1 回だけ作った問の初期状態を描く。
- シーンは `unity run games/033-rope-puzzle -- -executeMethod Game.Unity.Editor.DewdropSnipSceneBuilder.Build` で生成する（既存の Prefab と設定アセットは上書きしない）。絵は `DewdropSnipArtGenerator` が描く。物理の値・音量・演出の長さは `DewdropSnipSettings.asset` にある。

# 020. Qix型陣取り — TIDE CLAIM

仕様書：[plan/games/020-qix.md](../../plan/games/020-qix.md)

干潟に堤を引いて海を囲い、陸に変えていく陣取り。海には渦が 1 つ漂っていて、描いている途中の堤に触れると崩される。参考作品からはメカニクスだけを採用し、名称と見た目は独自に作っている。

## 環境

- Unity：6000.6.9f1（Universal 2D、C# 9.0）
- 対象プラットフォーム：Windows (StandaloneWindows64)
- 入力方式：Input System のキーボード。HUD は PanelRenderer / UI Toolkit

## 起動手順

```
dev gui 020      # エディタで開く
dev build 020    # Windows ビルド
dev run 020      # ビルドを起動
dev capture 020  # 証跡を evidence/ に撮る
```

## 操作

| 入力 | タイトル | プレイ中 | 一時停止 | 結果 |
|---|---|---|---|---|
| 矢印キー / WASD | — | 移動（押している間） | — | — |
| Space（押している間） | — | 海へ線を引く | — | — |
| Enter | はじめる | — | つづける | もう一度 |
| Esc / P | — | 一時停止 | つづける | — |
| R | — | — | 新しい試合 | 新しい試合 |
| T | — | — | タイトルへ | タイトルへ |

向きのキーを複数押しているときは、後から押したほうに進む。一時停止・画面の切り替え・フォーカスの喪失で、押しているキーはいったん離したものとして扱う（押し直すまで動かない）。

## 採用ルール

| 項目 | 採用ルール |
|---|---|
| 盤 | 80×56 セルの格子。外周 1 セルは最初から陸 |
| セル | 海（Open）・陸（Claimed）・線（Trail）の 3 状態 |
| 縁 | 陸のうち、8 近傍に海があるセル。線を引いていない自機は縁の上だけを歩ける（陸の内部には入れない） |
| 移動 | 上下左右に 1 セルずつ。既定で 2 Tick に 1 セル（60 Tick/秒）。斜めはない |
| 線を引く | Space を押しながら縁から海へ踏み出すと線を引き始める。描いている間は Space を離すとその場で止まり、後退はしない |
| 自分の線 | 線の上へは進めない（逆走も含む） |
| 閉じる | 線が陸に着いた Tick に確定する。線を陸にし、海を 4 連結の領域に分け、敵が重なる領域を残して他の全領域を陸にする |
| 閉じた後の位置 | 着いた陸が縁でなくなった（周りの海がすべて陸になった）ときは、陸を通って最も近い縁へ移る |
| 敵 | 1 体のみ。海を漂う円で、陸に当たると反射し、一定の間隔（乱数）で向きを変える |
| ミス | 敵が線に触れる、または自機が敵の重なる海へ踏み出す。線は海に戻り、自機は線の始点へ戻る。残機 −1 |
| ミスの後 | 描画キーを一度離すまで新しい線を引けない（縁は歩ける）。押したままだと同じ場所から同じ敵へ踏み出し続け、数 Tick で残機をすべて失うため |
| 敗北 | 残機 0（既定 3） |
| 勝利 | 占有率 75% 以上。占有率 = 陸になった海のセル数 ÷ 最初の海のセル数（外周の陸と描いている途中の線は数えない）。判定は整数の比較 |
| スコア | 線を閉じて陸にしたセル数の合計（線を含む）。最高スコアは起動中だけ保持する |
| 時間 | 制限時間はない |
| 1 Tick の順序 | 自機の移動（閉じたら確定）→ 敵の移動（線に触れたらミス） |
| 終了後の操作 | 盤への操作はすべて拒否し、状態を変えない |
| 再戦 | 1 試合 1 シード。起動時の値から試合ごとに 1 ずつ進め、再戦では必ず新しいシードを使う |

### 敵の動きと接触判定

- 位置・速度・半径は 1 セルを 256 等分した整数で持つ（既定：半径 1.5 セル、速さ 40/256 セル/Tick）。浮動小数点を使わないので、Mono と .NET で同じ結果になる。
- 1 Tick の移動は 1 単位ずつの歩み（ブレゼンハム）に分ける。歩むたびに、円が重なるセルを調べ、線に重なればその位置で止まってミス、陸に重なればその軸の向きを反転して進まない。Tick の始めと終わりの位置だけを見る判定で起きる、斜めのかすり接触の見逃しがない。
- 円とセルは「円の中心とセルの最近点の距離 < 半径」で重なると判定する（接するだけなら重ならない）。
- 向きは軸に平行な向きを除く 12 方向（22.5 度刻み、cos・sin を 1024 倍した整数表）から乱数で選ぶ。
- 閉じるときに残す領域は「敵の円が重なる海のセル」を含む領域。敵は陸にも線にも重ならない状態で閉じる（線に重なればその前にミスになっている）ので、閉じた後も敵は陸に重ならない。

## 設計上の選択

| 層 | 責務 |
|---|---|
| Core | `CellGrid`（占有マスク・縁の判定）、`RegionFill`（4 連結の Flood Fill、明示的なスタック）、`Territory`（閉じたときの確定）、`Enemy`（固定小数点の円と掃引判定）、`QixGame`（試合：移動・線・ミス・勝敗）、`QixConfig`（設定）、`SeededRandom` |
| App | `QixFlow`（画面遷移・実時間から Tick への変換）、`Intent`（入力を変換した意図）、`HeldControls`（押している向きと描画キー）、`Autopilot`（撮影・テスト用の操縦役） |
| Unity | `TideClaimGame`（入力・HUD・音）、`TideClaimFieldView`（盤のテクスチャ・自機・渦の描画）、`TideClaimPalette`（セルの色）、`TideClaimSettings`（設定アセット）、シーンと素材の生成、撮影台本 |

- **入力は押している状態で、Tick ごとに読む。** キーの押下・解放と画面の操作を `Intent` の 1 本の列に並べ、押した順に処理する。Core へは Tick のたびに「向き」と「描画キー」を渡す。
- **ミス後の再開条件は Core が保証する。** App で保持入力を消すだけにすると、Core を直接操作するテストや将来の入力方式で再発するため、Core が「描画キーを離した入力」を受けるまで線の開始を拒否する。タイトルの勝利条件の文言は設定の目標値から作る。
- **占有率は整数で判定する。** `陸になったセル数 × 100 ≥ 目標% × 最初の海のセル数`。
- **Flood Fill は閉じたときだけ行う。** 80×56 の盤なら 1 回で全セルを 1 度ずつ見るだけで済む。
- **自動操縦（`Autopilot`）は「コ」の字に切り取る。** 敵から十分離れた（線が長いほど余裕を広げる）切り取り方のうち面積が最大のものを選び、なければ縁を通って敵から最も遠い縁へ向かう。既定の設定で 100 シードすべて勝利し、ミスはなかった（平均 1,829 Tick、最長 11,754 Tick）。
- **盤は 1 セル = 1 テクセルのテクスチャで描く。** 80×56 のテクスチャを Point フィルタで拡大する。盤の版番号（`GridVersion`）が変わったときだけ全体を書き直す（閉じた直後の描画は p95 1.3 ms）。縁（自機が歩けるセル）は明るい色で描き、内陸と見分けられる。
- **描画は補間しない。** 自機・渦は Tick の状態をそのまま描く（60 Tick/秒）。
- **タイトルの盤は試合を作らずに描く。** 外周の縁と海の色を直接決める。Scene ビュー用の盤の初期画像も同じ配色関数で描き出している。
- **物理エンジンは使わない。** 衝突は Core の格子と整数の円で判定する。

設定アセットは `Assets/Game/Unity/TideClaimSettings.asset`。自機の速さ、渦の半径・速さ・向きを変える間隔、残機、目標の占有率、音量を調整できる。盤の大きさは画面の配置に合わせて 80×56 に固定しており、設定の検証で他の値を拒否する。

渦の半径と目標の占有率は組み合わせても検証する。閉じるときに渦の円が重なる海は必ず残るので、渦が一度に覆いうるセル数（直径が横切る列・行の最大数 `floor(2r / 256) + 2` の正方形、海の大きさで頭打ち）を除いても目標に届かない設定は、どう遊んでも勝てないので拒否する。既定の盤・目標 75% では半径 3967（約 15.5 セル）までで、既定の半径 384（1.5 セル）は 5×5 = 25 セルを覆いうる。

シーンの再生成：

```
unity run games/020-qix -- -executeMethod Game.Unity.Editor.TideClaimSceneBuilder.Build
```

素材は `TideClaimArtGenerator` が図形から描き出した PNG。再生成は既存のファイル、そのインポート設定、Stage Prefab を上書きしない。

## テスト

| 種類 | 場所 | 件数 | 実行方法 |
|---|---|---:|---|
| Core | `Assets/Tests/Core/` | 364 | `dev test` |
| App | `Assets/Tests/App/` | 29 | `dev test` |
| EditMode（Core/App を Mono で実行） | 同上 | 393 | `dev test 020 -Unity` |
| PlayMode（実シーン18、共通証跡16） | `Assets/Tests/Unity/` | 34 | `dev test 020 -Unity -Mode PlayMode` |

- **線を閉じない限り確定しない**：途中で止めた線、描画キーを離した線、逆走・自分の線への進入を拒否した線のどれでも、陸のセル数とスコアが変わらない。
- **敵側を誤消去しない**：敵が左右どちらにいても敵の側が残る。3 領域に分かれる場合、敵が 2 領域に重なる場合、敵を小さな入り江に閉じ込めて盤の大半を取る場合も確かめた。乱数の入力で 40 試合 × 最大 4,000 Tick 進め、毎 Tick「敵は海だけに重なる」ことを検査する。
- **面積率が単調に増加**：同じ乱数の試合で、毎 Tick の陸のセル数が前の Tick 以上であることを検査する（ミスで線が消えても減らない）。
- Flood Fill は、テスト側の素朴な実装（隣と小さい番号に寄せることを変化がなくなるまで繰り返す）と乱数の盤 200 枚で、領域の分け方と面積を照合している。
- 接触判定は、線に初めて重なる位置で止まること、1 Tick の間に線の角をかすめる斜めの移動（始めと終わりの位置ではどちらも重ならない）を検出することを確かめた。
- ミスの後は、キーを押したまま数十 Tick 進めても残機が減らず、描画キーを離して押し直すと再び描けることを Core と App の両方で確かめた。
- 設定の検証は、渦の半径と目標の占有率の境界（既定の盤・目標 75% で半径 3967 は通り 3968 は拒否）を確かめ、乱数の半径と位置で「覆いうるセル数」が実際に重なるセル数以上であることを照合している。
- 勝敗は、ちょうど目標の占有率（50%）で勝ち、1% 上げると勝たない境界を確かめた。
- 試合は整数だけで進むので、乱数の入力で 3,000 Tick 進めた盤面のハッシュを .NET と Mono の両方で固定値と照合している。
- PlayMode では実シーンに仮想キーボードで入力し、歩く・線を引く・止まる・一時停止・フォーカスの喪失を確かめ、閉じた直後の盤の全セルの描画色が Core の状態と一致することを照合している。実時間で進む試合の入力テストは、渦が自機から離れた試合を選んでから行う（実行ごとのシードに依存させない）。

結果と画面証跡は [evidence/README.md](evidence/README.md) に記録している。

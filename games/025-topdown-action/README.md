# 025. 見下ろしアクション — EMBER VAULT（仮）

仕様書：[plan/games/025-topdown-action.md](../../plan/games/025-topdown-action.md)　実装計画：[plan/games/025-topdown-action-implementation.md](../../plan/games/025-topdown-action-implementation.md)

1 画面の部屋を 6 つつないだ小さなダンジョン。剣で敵を倒し、回避ロールで弾や突進をかわしながら、小鍵で扉を開け、宝箱のボス鍵でボスの間へ入り、ボスを倒して秘宝を取る。参考作品からはメカニクスだけを採用し、名称と見た目は独自に作る。

## 環境

- Unity：6000.6.9f1（Universal 2D、C# 9.0）
- 対象プラットフォーム：Windows (StandaloneWindows64)
- 入力方式：Input System のキーボード。HUD は PanelRenderer / UI Toolkit（セッション2で実装）
- 共通パッケージ：[com.games100.tile-motion](../../packages/com.games100.tile-motion/)（整数の箱・タイルとの衝突解決・残り Tick・状態ハッシュ）

## 採用ルール

| 項目 | 採用ルール |
|---|---|
| 単位 | 1 タイル = 16 px = 256 単位の整数。速さは単位/Tick、60 Tick/秒。時間の設定は Tick 数。浮動小数点を使わないので Mono と .NET で同じ結果になる |
| 部屋 | 6 部屋、各 21×11 タイルの 1 画面。部屋は地図の格子に並び、辺の出入口はその辺の隣の部屋の反対側の出入口につながる |
| タイル | 床 `.`・壁 `#`・出入口 `D`・小扉 `L`・ボス扉 `B`（この 3 つは部屋の端だけ）・宝箱 `k`（小鍵）`K`（ボス鍵）。部屋の外は壁 |
| 部屋の切り替え | 通れる出入口（`D` と開いた扉）のマスに自機の経路が重なった Tick に、隣の部屋の到着位置（出入口の並びの中央、1 マス内側）へ移る。そこから 30 Tick（`TransitionTicks`）は切り替え（スクロール）で、入力・被弾・敵の動きはない。切り替えが終わった次の Tick から進む |
| 自機 | 12×12 px。8 方向に速さ 22（斜めは各軸 181/256 倍、最低 1）。向きは 4 方向で、今の向きの成分を押していれば変えず、そうでなければ横を優先。体力 6 |
| 剣（Z） | 押し始めにだけ振る（押したままでは振り直さない）。振りは 16 Tick で、3〜10 Tick 目だけ体の前に当たり（届く距離 14 px・幅 20 px、体の中央にそろえる）。**1 回の振りで同じ敵には 1 回だけ当たる**。振っている間は速さ 6 で歩き、向きは変わらない |
| 回避ロール（X） | 押し始めに、押している方向（なければ向き）へ速さ 40 で 18 Tick 転がる。**始めた Tick から 12 Tick は無敵**。転がっている間は振れない。終わった Tick を含めて 20 Tick は次のロールができない。壁では止まる |
| 被弾 | 敵・ボスに触れると 1、弾に当たると 1 減る。動く物どうしは相対軌跡の掃引で最初に触れた時刻を求め、**1 Tick に受けるのは最初に触れた 1 つだけ**。受けると振り・ロールが止まり、当たった物から遠ざかる向き（大きいほうの軸）へ 8 Tick 押し戻され（操作は効かない）、**被弾の次の Tick から 60 Tick は無敵**（その間は一切減らない。61 Tick 目から再び受ける） |
| 敵の被弾 | 剣で 1 減る。押し戻され（ボスは押し戻されない）、次の Tick から 12 Tick は無敵。体力 0 で消える |
| 敵 3 種 | **スライム**（体力 2・速さ 8）：乱数で 4 方向か止まるを選び、20〜60 Tick 続ける。壁に当たったら選び直す。**射手**（体力 2）：動かない。自機と縦か横に並ぶ（体の帯が重なる）と、そちらへ速さ 36 の弾を撃ち、90 Tick は撃たない。**突進兵**（体力 3）：自機と縦か横に並び、間に固体がなければ 20 Tick 構えてから、その向きへ速さ 56 で壁まで突進し、壁で 50 Tick 気絶する |
| ボス | 28×28 px、体力 12。乱数を使わず「自機のほうへ歩く 120 Tick → 8 方向の弾（速さ 32）→ 止まる 50 Tick → 構え 30 Tick → 自機のほうへ速さ 64 で壁まで突進 → 気絶 70 Tick」を繰り返す |
| 弾 | 6×6 px。まっすぐ進み、壁か部屋の外に入った Tick に消える（その Tick も入るまでの区間では当たる）。自機に当たった弾だけ消え、無敵で受けなかった弾はそのまま進む |
| 小鍵・小扉 | 小鍵は個数で持ち、どの小扉にも使える。閉じた小扉（固体）へ歩いて押し当てる（歩く向きの 1 単位先が扉に重なる）と、**小鍵を 1 つ使って開く**。持っていなければ開かず、個数も変わらない。開いた扉は両側とも以後ずっと開いたまま（同じ 1 枚） |
| ボス鍵・ボス扉 | ボス鍵は宝箱から得るフラグ。ボス扉はボス鍵を持っていれば押し当てで開く（**ボス鍵は無くならない**）。**小鍵ではボス扉は開かず、ボス鍵では小扉は開かない** |
| 宝箱 | 固体。体の前（剣の当たりの範囲）に閉じた宝箱があるときに Z を押すと、振らずに開けて中身を得る。開いた宝箱は二度と中身を出さず、その前で Z を押すと剣を振る |
| 全滅の小鍵 | 西の回廊は敵を全滅させると中央に小鍵が出る。出た・取ったは保持し、入り直して敵が戻っても二度は出ない |
| ボス撃破 | ボスを倒すと **ボス撃破フラグ** が立ち、ボスの弾が消え、ボスのいた場所に秘宝が出る。部屋を出入りしても、ゲームオーバーから再開しても、ボスは戻らず秘宝は残る。倒す前に部屋を出ると、ボスは次に入ったとき満タン |
| 部屋をまたいで保持 | 小鍵の個数・ボス鍵・開いた扉・開けた宝箱・全滅の小鍵（出た・取った）・訪れた部屋・ボス撃破（`DungeonState`）、自機の体力・無敵の残り・向き |
| 部屋ごとに初めから | 敵（入るたびに出現位置・満タン）・弾。自機の振り・ロール・押し戻しは部屋を移ると捨てる。押したままの剣・ロールのキーは一度離すまで効かない |
| 敗北と再開 | 体力 0 でゲームオーバー。Enter で入口の開始位置から体力満タンで再開する。**ダンジョンの状態（鍵・扉・宝箱・ボス撃破）はそのまま**。死亡回数を数える。ファイルには保存しない |
| 勝利 | 秘宝に触れた Tick で終わり（その Tick の被弾は数えない）。結果画面に遊んだ時間・死亡回数 |
| 終了後 | ゲームオーバー・勝利の後の Tick と入力は状態を変えない |
| 1 Tick の順序 | 自機の移動 → 鍵の扉への押し当て → 剣のキー（前に閉じた宝箱があれば開け、なければ振る）→ 剣の当たり（敵は Tick の始めの位置）→ 全滅の小鍵 → 敵の移動（弾を作る）→ 弾の移動 → 小鍵・秘宝を取る（自機の経路で。秘宝ならここで勝ち）→ 被弾 → 無敵の残りを減らす → 体力 0 なら倒れる → 出入口。**致死の被弾と出入口が同じ Tick なら倒れるほうが先**（部屋は移らない） |
| 時刻と Tick | 022・023 と同じ。入力は起きた時刻を持ち、その時刻を含む Tick から効く。1 フレームで進めるのは入力と時計で合わせて 5 Tick まで。遊んだ時間は飛ばした区間も数える |
| 乱数 | 1 試合 = 1 シードの xorshift。部屋に入るたびに「試合のシード・部屋・入った回数」から系列を作る（ある部屋の乱数の使い方が他の部屋に響かない）。使うのはスライムだけ。再戦は新しいシード（起動時の値から試合ごとに 1 進める） |

### 部屋の配置

```
 [4 宝物庫：宝箱=ボス鍵] ─(小扉)─ [5 前室：突進兵 2・射手] ─(ボス扉)─ [6 ボスの間]
                                          │(小扉)
 [2 西の回廊：スライム 3・全滅で小鍵] ── [1 入口] ── [3 東の間：射手 2・スライム 2・宝箱=小鍵]
```

- 小鍵は 2 本（西の回廊の全滅・東の間の宝箱）で、どちらを先に取ってもよい。入口 → 前室の小扉に 1 本、前室 → 宝物庫の小扉にもう 1 本。
- 宝物庫のボス鍵で前室 → ボスの間のボス扉を開ける。

## 設計上の選択

| 層 | 責務 |
|---|---|
| パッケージ | `Box`・`Units`・`ISolidGrid`・`BodyMotion`・`Countdown`・`StateHash` |
| Core | `TileMap`・`Terrain`（部屋の地形と、開いた扉を重ねた衝突用の地形）、`Room`・`Rooms`・`World`（文字の地図・6 部屋・格子と出入口のつながり・扉と宝箱の通し番号）、`DungeonState`（部屋をまたぐ進行フラグ）、`Hero`・`SwordHitbox`、`Enemy`・`Projectile`、`Sweep`（相対軌跡の掃引）、`RoomRun`（今いる部屋の 1 Tick）、`Dungeon`（試合：部屋の切り替え・再開・勝敗・ハッシュ・複製）、`VaultConfig`（設定と検証） |
| App | `VaultFlow`（画面遷移・時刻付きの入力から Tick への対応・試合ごとのシード）、`Intent`・`HeldControls`、`Autopilot`（全編を進める操縦役） |
| Unity | セッション2で実装する |

- **物理エンジンには何も委譲しない。** 衝突解決は共通パッケージの整数の 1 軸ずつの解決。見下ろしなので重力はなく、横 → 縦の 2 区間で動かす。
- **扉は「両側で同じ 1 枚」の通路番号で持つ。** `World` が出入口の組に番号を振り、`DungeonState` がその番号で開閉を持つ。どちらの部屋から開けても反対側が開き、鍵は 1 回しか使われない。種類の違う出入口が向き合う地図は `World` が拒否する。
- **鍵の消費・宝箱・全滅の小鍵・ボス撃破は、二重に起きない API にする。** `TryOpen`（`Opened` / `AlreadyOpen` / `NoKey`）・`TryOpenChest`・`ShowReward`・`TryTakeReward`・`DefeatBoss` は 2 回目に状態を変えずに知らせる。
- **無敵は「受けた Tick の次から数える」残り Tick（`Countdown`）。** 受けた Tick は減らさず、Tick の終わりに 1 減らすので、境界（60 Tick 目は無敵・61 Tick 目に受ける）をそのままテストできる。ロールの無敵は「ロールの何 Tick 目か」で決め、被弾の無敵とは別に持つ。
- **1 回の振りで 1 回だけ当たるのは、振りの通し番号で保証する。** 敵の無敵が短い設定でも、同じ振りの有効 Tick の間に二度当たらない。
- **剣の当たりの箱は 1 つの関数（`SwordHitbox.For`）。** 判定・宝箱の前の判定・操縦役・描画で同じものを使う。
- **部屋の状態とダンジョンの状態を分ける。** `RoomRun` は部屋に入るたびに作り直して敵・弾・乱数を持ち、`DungeonState` は部屋をまたいで残る。開いた扉は `Terrain` が辺ごとの配列を共有して見るので、開けた Tick から衝突にも反映される。
- **操縦役は目標を状態から選ぶ。** 決め打ちの入力の列ではなく、「たどれる部屋の閉じた宝箱 → 全滅の小鍵 → 鍵のある閉じた扉 → ボス → 秘宝」の順で目標を選び、部屋の中はマスの幅優先探索で歩く。近づく弾・自機の帯での構えと突進があるときだけ、試合の複製で 9 通りの手（止まる・4 方向へ歩く・4 方向へ転がる）を 30 Tick 先読みして、ふだんの方針より被弾が少ない手を選ぶ。

| 種類 | 場所 | 件数 | 実行 |

- 題材固有：
  - 鍵消費後のみ扉が開く（`DoorKeyTests`）：鍵なしでは押し当てても固体で個数は変わらない、1 本で開いて 0 本になり反対側も開く、戻るときに鍵は要らない、2 枚目は 2 本目が要る、小鍵でボス扉は開かず（小鍵も減らない）ボス鍵で小扉は開かない、ボス鍵は無くならない、同じ宝箱は 2 回目に中身を出さない、前にない宝箱は開かない。
  - 無敵中に二重ダメージなし（`DamageTests`）：同じ Tick に 2 発の弾が当たっても 1 回、触れたままでも無敵の 60 Tick は減らず 61 Tick 目に減る（実際の試合と自機の単体の両方）、ロールの無敵は 12 Tick 目まで、1 回の振りで同じ敵に 1 回だけ（敵の無敵を 1 Tick にしても）、敵の無敵の境界、押し戻し中は操作が効かない。
  - ボス撃破フラグを維持（`BossTests`）：倒した後に部屋を出入りしてもボスは出ず秘宝は残る、撃破後のゲームオーバーから再開しても残る、秘宝で勝ち・その後の Tick は受け付けない、撃破前の複製は変わらない、倒す前に出たボスは満タンに戻る。
- 部屋跨ぎで状態一貫（`RoomStateTests`）：全滅の小鍵・宝箱・小鍵の個数が往復（2 回）で残り、敵は出現位置・満タンに戻る、体力は持ち越す、切り替えの 30 Tick は入力・被弾・敵の動きがない、切り替えの前から押していた剣は離すまで振らない、**同じ Tick の致死の被弾と出入口は倒れるほうが先**（倒れなければ移る）、再開は入口から・状態はそのまま。
- 剣と自機（`HeroTests`）：4 方向の剣の箱、届く距離ちょうど先は当たらず 1 単位内側は当たる、有効 Tick の始め・終わり、押したままでは振り直さない、斜めの速さ、向きの規則、ロールの向きと待ち時間の境界、壁で止まる。
- 地図と設定（`MapTests`・`ConfigTests`）：6 部屋のつながりと扉の種類、到着位置、不正な文字・端でない出入口・角・種類の混在・合わない隣・壁に埋まる敵の拒否、設定の範囲外（すべての int の設定に負の値を入れると拒否）。
- 再現性（`ReplayTests`）：同じシードと入力の列で同じハッシュ、シードでスライムの動きが変わる、隣の部屋の乱数は前の部屋で過ごした時間に左右されない、複製は同じように進み独立している。
- 完走（`AutopilotTests`）：操縦役で 20 シードがすべて 10 分（36000 Tick）以内に勝つ（平均 2951 Tick、死亡 0）。シード 1 の最終状態（2923 Tick・ハッシュ `0xFCD220F3`）を .NET と Mono の両方で照合する。同じ操縦役で途中でやめた試合の後でも同じ試合になる。
- 画面遷移（`VaultFlowTests`）：タイトル → 試合 → ゲームオーバー → 入口から再開、勝利 → 新しいシードで再戦、時刻付きの入力の Tick、処理落ちの上限、一時停止・フォーカス喪失でキーを持ち越さない、操縦役で全編、30・60・144・240fps と不規則な間隔で状態のハッシュが一致。

## 未実装範囲

- 仕様書の Out of scope：広い世界地図、アイテム数十種、アセットの大量制作・追加ステージ量産・製品化要素。
- 回復アイテムはない（ゲームオーバーで入口から満タンで再開する）。
- セーブはファイルに保存しない（起動中だけ）。そのため破損データ・バージョン差の扱いは対象外。

証跡画像はJPEG（`.jpg`）、品質85を標準とし、保存したJPEGのSHA-256をマニフェストに記録する。

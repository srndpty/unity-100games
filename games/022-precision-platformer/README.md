# 022. 精密プラットフォーマー — GLINT ASCENT（仮）

仕様書：[plan/games/022-precision-platformer.md](../../plan/games/022-precision-platformer.md)

1 画面の部屋を 10 個、ジャンプ・ダッシュ・壁蹴りで抜けていく精密アクション。残機はなく、死んでもその部屋の入口からすぐやり直せる。完走タイムと死亡回数が結果になる。参考作品からはメカニクスだけを採用し、名称と見た目は独自に作る。

## 環境

- Unity：6000.6.9f1（Universal 2D、C# 9.0）
- 対象プラットフォーム：Windows (StandaloneWindows64)
- 入力方式：Input System のキーボード。HUD は PanelRenderer / UI Toolkit

## 起動手順

```
dev gui 022      # エディタで開く
dev build 022    # Windows ビルド
dev run 022      # ビルドを起動
dev capture 022  # 証跡を evidence/ に撮る（画像は captures/<画像世代>/、撮影記録は runs/）
```

## 操作

| 入力 | タイトル | プレイ中 | 一時停止 | 結果 |
|---|---|---|---|---|
| ← → / A D | — | 動く（押している間）・ダッシュの向き | — | — |
| ↑ ↓ / W S | — | ダッシュの向き | — | — |
| Space / Z / C | — | 跳ぶ（押す長さで高さが変わる。壁際では壁蹴り） | — | — |
| X / Shift | — | ダッシュ | — | — |
| Enter | はじめる | — | つづける | もう一度 |
| Esc / P | — | 一時停止 | つづける | — |
| R | — | — | 1 部屋目から | 1 部屋目から |
| T | — | — | タイトルへ | タイトルへ |

左右・上下を両方押しているときは、後から押したほうを使う。一時停止・タイトル・結果・フォーカスの喪失で、押しているキーはいったん離したものとして扱う（押し直すまで効かない）。HUD のボタンでも同じ操作ができる。

## 採用ルール

| 項目 | 採用ルール |
|---|---|
| 単位 | 1 タイル = 16 px = 256 単位の整数。速度は単位/Tick。60 Tick/秒。**時間の設定は秒ではなく Tick 数**で持つ（秒から Tick への丸めの境界が生まれない）。浮動小数点を使わないので Mono と .NET で同じ結果になる |
| 部屋 | 40×22 タイルの 1 画面。カメラは固定。左右の外は壁、上の外は空、下の外へ落ちたら死亡。出口は右端 |
| タイル | 空 `.`・固体 `#`・上向きのトゲ `^`（タイルの下半分が当たり。通り抜けられる）・出口 `E`・開始位置 `S`（真下が固体） |
| 自機 | 10×14 px の箱。地形とはこの箱で判定する |
| 横移動 | 最高速 36。加速は接地中 6・空中 4、入力がないとき（と最高速を超えているとき）の減速は接地中 6・空中 2 |
| ジャンプ | 上向き 84、重力 4、落下の最高速 96。押し続けると約 3.3 タイル。上昇中に離すと上向きの速さを 24 まで切る（可変ジャンプ） |
| 入力バッファ | ジャンプキーを**押し始めた Tick と、その後 6 Tick（`JumpBufferTicks`）**の間、ジャンプできる状態を待つ。着地の 6 Tick 前までの押下は、着地後の最初の Tick に跳ぶ。発火したら消える（押したまま着地しても 2 回目は跳ばない）。キーを離した後に発火したときは可変ジャンプで低いジャンプになる |
| 接地猶予 | 足場を離れた後の**空中 1〜6 Tick 目（`CoyoteTicks`）**は地上のジャンプができる。跳ぶ・ダッシュすると猶予は消える（空中で 2 回跳べない） |
| 壁蹴り | 空中で、左右の壁との隙間が 3 px（`WallReach`）未満のときにジャンプが発火すると、壁と反対向きに横 48・上 80 で跳ぶ。その後 10 Tick は横入力を受け付けない（壁へすぐ戻れない）。接地中・接地猶予中は普通のジャンプを優先する。両側に壁があれば向いている側を蹴る |
| 壁ずり | 空中で壁に接して壁へ向けて押していて、落ちているときは落下の最高速を 32 に下げる |
| ダッシュ | 押し始めの Tick に残り回数があれば発動。向きは押している 8 方向、何も押していなければ向いている側。10 Tick の間、速さ 72（斜めは各軸 72×181/256 = 50）で真っすぐ進み、重力・横入力は効かない。終わったら各軸の速さを 36（斜めは 25）までに落とす。ダッシュ中のジャンプの押下はバッファの中で待つ |
| ダッシュ回数 | 1 回（`DashCount`）。ダッシュ中でない Tick の終わりに接地していれば最大まで回復する |
| 死亡 | Tick の中でトゲの当たりに触れる（終わりの位置ではなく移動の経路で判定。斜めに角をかすめても死亡）・部屋の下へ落ちる。死亡回数 +1。18 Tick（`DeathTicks`）の間は入力を受け付けず、その後**部屋の開始位置に新しい自機**で戻る（ダッシュ回数・速度・バッファ・猶予は初期値）。残機はなく、何度でもやり直せる |
| 押しっぱなし | 開始・死亡からの再開・次の部屋では、ジャンプ・ダッシュのキーを一度離すまで受け付けない |
| 出口 | Tick の中で出口に触れたら部屋をクリアし、次の Tick から次の部屋の開始位置で進む。10 部屋目を抜けたら勝利 |
| 接触の経路 | 1 Tick の移動は地形の解決と同じく「横に動く → 縦に動く」の 2 区間（それぞれ地形で止まった位置まで）。トゲと出口は各区間で通った範囲で判定し、先に通った区間の接触を採る。同じ区間でトゲと出口の両方に触れたら死亡が優先 |
| 1 Tick の順序 | 接地の確認 → 押し始めの検出 → 接地猶予 → ダッシュ開始 → ジャンプの解決（地上・猶予 ＞ 壁蹴り）→ 横の加減速 → 可変ジャンプ → 重力（壁ずり）→ 横移動 → 縦移動 → ダッシュの終了 → 接地の確認とダッシュの回復 → トゲと出口（移動の経路で）→ 落下 |
| 時刻と Tick | プレイを始めた（再開した）時刻を t0 として、Tick n は [t0 + (n−1)/60, t0 + n/60) の区間を表す。キーの押下・解放は**起きた時刻**を持ち、その時刻を含む Tick から効く（前の Tick を先に進めてから反映する）。フレームの区切りに依存しないので、フレームレートが違っても同じ入力なら同じ結果になる。1 フレーム（入力の反映と時計の進行を合わせて）で進めるのは 5 Tick まで。超えた区間は進めずに飛ばす（その間の時間はなかったことにする）が、その区間の入力も起きた順に反映するので、押している・離したの状態は崩れない |
| 計時 | 完走タイムは**遊んだ実時間**（一時停止・フォーカス喪失・タイトルは数えない）。ゲームの進行は処理落ちで 1 フレーム 5 Tick までに抑えるが、記録は飛ばした区間も含めて数えるので、処理落ちで短い記録にはならない。HUD・結果・最短記録はこの時間を使う。最短タイムは起動中だけ保持する |
| 終了後 | 勝利の後の Tick と入力は受け付けず、状態を変えない。2 回目のクリア・勝利は起きない |
| 乱数 | 使わない。部屋と入力の列だけで結果が決まる |

## 設計上の選択

| 層 | 責務 |
|---|---|
| Core | `Box`・`Units`（整数の箱と単位）、`StateHash`（状態のハッシュ）、`TileMap`（地形・トゲの当たり）、`BodyMotion`・`GroundProbe`・`WallProbe`（衝突解決・接地・壁）、`Countdown`（残り Tick の猶予）、`Player`（移動・ジャンプ・ダッシュ・壁蹴り）、`Room`・`Rooms`（文字の地図と 10 部屋）、`RoomRun`（1 部屋の挑戦と即時リトライ）、`Climb`（10 部屋の進行・死亡回数・経過 Tick）、`PrecisionConfig`（設定） |
| App | `PrecisionFlow`（画面遷移・時刻付きの入力から Tick への対応）、`Intent`・`HeldControls`（入力の列と Tick ごとの入力）、`RouteScript`・`RoutePilot`・`Routes`（部屋ごとの入力の列と、それで動かす操縦役） |
| Unity | `GlintAscentGame`（時刻付きの入力・カメラ・HUD・音）、`GlintAscentStage`（1 部屋の描画：Tilemap・自機）、`GlintAscentSettings`（設定アセット）、`GlintAscentArtGenerator`・`GlintAscentSceneBuilder`（素材・Stage Prefab・シーンの生成）、`GlintAscentCaptureScenario`（撮影台本） |

- **物理エンジンには何も委譲しない。** 021 の整数の衝突解決（横 → 縦の順に 1 軸ずつ、途中の列を飛ばさない）を移植した。
- **接地猶予と入力バッファは `Countdown`（残り Tick 数）で明示的に持つ。** 「何 Tick 前に起きたか」だけで決まるので、境界の Tick（猶予ちょうど・1 Tick 超え）をそのままテストできる。値型なので自機の複製で一緒に複製される。
- **トゲと出口は移動の経路で判定する。** 地形を横 → 縦の順に 1 軸ずつ解決するので、1 Tick の経路は 2 本の 1 軸の区間になる。各区間で通る範囲は、始めと終わりの箱を囲む箱にちょうど一致するので、その箱でトゲ・出口と照合する（`Motion`）。終わりの位置だけで見ると、跳び上がりながら角をかすめた接触を見逃す。
- **完走タイムはゲームの Tick 数と分けて数える。** 処理落ちで進行を 5 Tick に抑えても、遊んだ時間（`PrecisionFlow.PlayedTicks`）は時計どおりに進めるので、記録が短くならない。
- **1 フレームの Tick の上限は Flow が持ち、入力と時計で分け合う。** 入力のたびに「その時刻まで進める」ので、上限を呼び出しごとに数えると、入力の数に比例して 1 フレームの処理が増える。Unity は毎フレームの終わりに `Advance`（時計で進めないフレームは `EndFrame`）を呼んで上限を数え直す。
- **入力は時刻付きで受け取り、その時刻を含む Tick に効かせる。** フレームの始めにまとめて反映すると、30fps では押下が最大 1 フレーム遅れ、同じ操作でも跳ぶ Tick が変わる。`PrecisionFlow.Apply` は入力の時刻までの Tick を先に進めてから反映するので、届くフレームが違っても同じ Tick に効く。
- **入力の時刻は Input System のイベントの時刻（`CallbackContext.time`）を使う。** `Time.realtimeSinceStartupAsDouble` と同じ時計なので、Update でまとめて処理しても、押した瞬間の Tick に効く（今より後の時刻にはしない）。HUD のボタンはクリックを処理した時刻を使う。
- **10 部屋は Core の地図から作った Stage Prefab。** 生成スクリプトが Tilemap（岩・トゲ・出口の光）と自機を置いた Prefab を部屋ごとに作るので、プレイ前から Scene ビューで見える。既にある Prefab は上書きせず、地図と違えば生成を止める（PlayMode テストでも照合する）。シーンには 10 部屋を同じ位置に置き、今の部屋だけを表示する。
- **カメラは部屋全体と HUD の帯を収めて固定する。** 1 タイル = 1 ワールド単位、40×22 タイルの部屋の上に 1.5 タイルの帯を空け、画面の縦横比から大きさを決める。
- **ダッシュの残りは自機の色で示す。** 使い切っている間は青みがかった色にし、着地で白に戻る。HUD にも ◆◇ で出す。
- **素材はドット絵を生成する。** 1 タイル = 32 ピクセル、Point フィルタ。自機は体の箱の下端の中央を基準点にして、Tick の状態をそのまま描く（補間しない）。
- **自動操縦は先読みではなく部屋ごとの入力の列にした。** ダッシュ・壁蹴りでは数通りの先読みで抜けられない部屋がある。列は App テストの `RouteFinder`（`[Explicit]`、普段は実行しない）が重み付き A* で探したもので、設定の既定値や部屋を変えたら作り直す（Debug ビルドで約 4.5 分）。

## テスト

| 種類 | 場所 | 件数 | 実行 |
|---|---|---|---|
| Core | `Assets/Tests/Core/` | 125 | `dev test`（.NET）／`dev test 022 -Unity`（Mono） |
| App | `Assets/Tests/App/` | 37（＋ルート探索の道具 1、`[Explicit]`） | 同上 |
| PlayMode | `Assets/Tests/Unity/` | 33（実シーン 17、共通証跡公開 16） | `dev test 022 -Unity -Mode PlayMode` |

- 題材固有：着地直前の入力がバッファで発火する（`GraceTests`：着地の 0〜バッファ+2 Tick 前の押下を、押し続け・1 Tick だけの両方で、バッファ 0・1・6・30 について確認）、猶予時間外のジャンプ不可（`GraceTests`：空中 1〜猶予+2 Tick 目を猶予 0・1・6・30 について確認。跳んだ後・ダッシュ後に猶予が消える）、死亡後にダッシュ回数が戻る（`RoomRunTests`：回数 1〜3 で使い切ってから死亡）。
- フレームレート：1・2 部屋目のルートを時刻付きのキー操作に直し、30・60・144・240fps と不規則なフレーム間隔で届けて、途中と最後の状態のハッシュが全て一致することを確認（`PrecisionFlowTests.FrameRate_DoesNotChangeTheResult`）。入力の時刻を使わずフレームで反映するように変えると失敗することも確認した。
- 実シーン：キーで動く・跳ぶ・ダッシュする（使い切りの色と着地での回復）、入力の時刻がゲームの時計と同じ、死亡の姿と死亡回数の HUD・入口での再開、10 部屋の Stage の切り替えと結果画面、タイトルへ戻った表示が起動直後と一致、一時停止・HUD のボタン・フォーカスの喪失、設定アセットの値で `Routes` が通ること。
- 完走：`Routes` で 10 部屋を死亡なしで連続完走（2882 Tick）し、最終状態のハッシュ `0x4FC97CE8` を .NET と Mono の両方で照合する。ハッシュは位置・速度だけでなく、猶予・バッファ・壁蹴りの固定・ダッシュの残り Tick と直前のキーの押下まで含むので、一致すれば以後の動きも一致する。
- 処理落ち：1 フレームに入力がいくつたまっても、入力の反映と時計の進行で合わせて 5 Tick を超えない（`PrecisionFlowTests.Hitch_*`）。

証跡と検証の記録は [evidence/README.md](evidence/README.md)、振り返りは [retrospective.md](retrospective.md)。

## 未実装範囲

- 仕様書の Out of scope：全章マップ、特殊ギミック多数（トゲ以外のギミックはない）、アセットの大量制作・追加ステージ量産・製品化要素。
- ジャンプでダッシュを打ち消す動き、壁つかまり・よじ登り、ダッシュの回復アイテムは入れない。
- 開始・再開の最初の Tick より前に押したジャンプ・ダッシュは「押したままのキー」として扱い、押し直すまで効かない（Enter から 1/60 秒以内に押した場合だけ起きる）。
- 部屋の配置は探索で抜けられることと、人間の試遊で通しプレイできることを確かめた（2026-11-22 に完了承認）。6 部屋目の最初の跳躍は、成功する操作の幅が他より小さい。

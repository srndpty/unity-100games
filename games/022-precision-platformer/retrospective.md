# 022 振り返り

## 新たに学んだ点

接地猶予と入力バッファを残り Tick 数（`Countdown`）で持ち、設定も秒ではなく Tick 数にしたので、「猶予ちょうど」「1 Tick 超え」の境界をそのままテストでき、丸めの議論が要らなかった。入力に Input System のイベント時刻を付け、その時刻を含む Tick に効かせると、30〜240fps と不規則な間隔で状態のハッシュが一致した。

ダッシュと壁蹴りのある部屋では先読みの自動操縦が使えないので、重み付き A* で入力の列を探す道具をテストの `[Explicit]` に置き、見つけた列を撮影・テストで再生した。

## 想定との差

入力ごとに「その時刻まで進める」ため、処理落ちの上限を呼び出しごとに数えると、入力の数に比例して 1 フレームの Tick が増えることをレビューで指摘された。状態のハッシュも位置と速度だけで、バッファなどの内部状態を含まず、フレームレート比較の証拠として弱かった。整数の斜め成分は最小速度で 0 になっていた。

## 次回の改善点

時刻付きの入力を扱うときは、1 フレームの処理量の上限を最初からフレーム単位で持つ。再現性の比較に使うハッシュは、以後の動きを決める状態（残り Tick・直前の押下）を全て含めて作る。

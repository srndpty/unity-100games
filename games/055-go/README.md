## 採用ルール

### 盤と着手

| 項目 | 採用ルール |
|---|---|
| 盤 | 9 路（81 点）。座標は列 A〜J（I を除く、左から）、行 1〜9（下から） |
| 手番 | 黒が先手。置き石なし |
| 着手 | 空点に置く。置いた後、呼吸点が 0 になった相手の連を全て取り、その後で自分の連の呼吸点を見る |
| 自殺手 | 相手の石を取れず、自分の連の呼吸点が 0 になる手は禁止（理由付きで拒否し、盤・手番・ハッシュ・履歴は変わらない） |
| コウ | 着手後の盤面（石の配置）が、対局中に現れたいずれかの盤面と同じになる手は禁止（positional superko）。そのうち「直前に相手が打った 1 子を取る」ものを単純コウ（`Ko`）、それ以外を同型反復（`Superko`）として理由を分ける。打って返し（2 子以上を取り返す）は合法 |
| 同型の判定 | 64 ビット Zobrist ハッシュ（固定シードの表）の履歴で候補を引き、一致したら盤面そのものを比べて確定する（衝突で誤って拒否しない） |
| パス | いつでも可。パスは盤面を変えないので同型反復の対象外 |
| 終局 | 両者が連続してパス／どちらかが投了／手数の上限（既定 300 手、パスを含む）に達した。2 回目のパスと上限が重なったら「連続パス」 |
| 投了 | 手番でなくてもできる。終局後はできない |

### 計点（中国式の面積・Tromp-Taylor 型）

| 項目 | 採用ルール |
|---|---|
| 面積 | 死石を取り除いた盤で、各色の**石の数＋その色の石だけに接する空点の領域**。両色に接する空点（ダメ・セキの共有の呼吸点）はどちらにも数えない |
| コミ | 白に 7 目（整数なので引き分けがある）。差 = 黒の面積 − 白の面積 − 7。正なら黒、負なら白の勝ち、0 は引き分け |
| 死石 | 終局（連続パス・手数の上限）の後、今の盤からプレイアウトを決まった回数（既定 600）回し、連の石が相手の持ち物になった割合が 50 % を超えた連を死石と推定して印を付ける。プレイヤーは連をクリック（または決定）して生死を切り替え、確定すると計点する。乱数は（試合シード × 手数 × 推定）の系列 |
| 投了 | 投了の対局は計点しない（結果は投了で決まる） |
| アゲハマ | 表示するが、面積計点なので得点には足さない |

### CPU（MCTS）

| 項目 | 採用ルール |
|---|---|
| 探索 | UCT ＋ RAVE。手番ごとに木を作り直す。選択の値 = (1 − β) × 勝率 + β × AMAF の勝率 + 0.1 × √(親の訪問) ÷ (1 + 子の訪問)、β = √(k ÷ (3n + k))、k = 1000。全て整数で計算する（Mono と .NET で同じ手） |
| 木の手 | 対局の履歴＋木の経路で同型反復まで判定した合法手から、自分の眼（四方が自分の石で、斜めの相手の石が中央なら 1 つ以下・辺と隅は 0）を埋める手を除いたもの。木の中ではパスも候補。根のパスは「相手が直前にパスした」か「ほかに手がない」ときだけ（CPU から先にはパスしない） |
| プレイアウト | 直前の手がアタリを作ったら取る・逃げる。それ以外は眼埋めを除く置ける点から一様に選ぶ（単純コウだけ判定）。2 連続パスか 243 手で打ち切り、盤をそのまま面積で数える。勝ち 2・引き分け 1・負け 0 |
| 強さ | プレイアウトの総数。弱い 500・普通 2,000・強い 8,000（設定アセット） |
| 手の決定 | 訪問回数の最大（同数は点の番号の小さい方、パスは最後）。相手がパスした後、パスが全勝（数えて勝っている）ならパスで終える |
| 投了 | 30 手目以降に、決めた手の勝率が 10 % 未満なら投了する |
| 時間 | 1 Tick に 20 回は必ず回し、Unity はフレームの残り時間でも回す（`GoFlow.Think`）。手は総数だけで決まり、分け方（機械の速さ）は考える時間だけを変える。考える間は最小 30 Tick。撮影とテストは Tick の分だけで進む |
| 乱数 | `RandomSeries`（試合シード × 手数 × 用途：探索 1・死石の推定 2・操縦役 3） |

## 設計上の選択

| 層 | 責務 |
|---|---|
| Core | `Points`（交点の番号と表記・隣の表）、`PointSet`（81 点の 128 ビット集合）、`Board`（色・連の番号・連ごとの石と呼吸点の集合を差分で更新、Zobrist ハッシュ）、`Zobrist`、`GoGame`（手番・パス・投了・終局・同型反復の履歴・アゲハマ・状態ハッシュ）、`AreaScore`、`GoConfig`、`BoardText`、`Playout`、`Mcts`、`Ownership`（死石の推定）、`MctsConfig` |
| App | `GoFlow`（タイトル・遊び方・対局・一時停止・死石の確定・結果、意図の列、画面の版、フォーカス喪失、再戦のシード）、`CpuPlayer`、`BoardCursor`、`Pilot`（操縦役：小さい MCTS の手を矢印キーと決定に変える）、`FlowSettings` |

- 連の石と呼吸点は 128 ビットの集合で持ち、着手のたびに「つないだ連の和」「取った跡を隣の連の呼吸点に足す」で差分更新する。テストで、毎手の全ての連を塗りつぶしの数え直しと照合する。
- 盤の書き換え（`Board.Play`）は Core の内部だけ。画面とテストは `GoGame` の `TryPlay`／`TryPass`／`TryResign` を通す。
- 状態ハッシュは tile-motion の `StateHash`。盤・手番・パス・終局・アゲハマに加え、同型反復の履歴（各手の後の盤面ハッシュ）も混ぜる。
- 乱数は int-geometry の `SeededRandom`・`RandomSeries`、探索の √ は `IntMath.Sqrt`。
- 探索の木は手番ごとに作り直す。木の合法手は対局の `GoGame.Repeats`（履歴＋木の経路）で判定し、テストで「展開した全ての経路を実際の対局で打てる」「展開する手 = 対局が受け付ける手 − 眼埋め（全局面）」を確かめる。
- 純粋なランダムのプレイアウトだけでは、1,000 回では 4 子のアタリを取る手（プレイアウトの勝率 70 %）とほかの手（60 %）を見分けられなかった（子 1 つあたり 13 回程度）。アタリへの応手のプレイアウト方針と RAVE を足して見分けられるようにした。

### 計測（プレイアウトの速さ）

| 環境 | 1 秒あたり | 20 回あたり p50 / p95 |
|---|---|---|
| Unity エディタの Mono（EditMode テスト、i9-13900KF） | 4,796 回 | 4.10 ms / 4.55 ms |
| .NET 9（dotnet test、同じ機械） | 約 10,000 回 | — |

空の盤からの探索（最も手数の長いプレイアウト）で測った（`SpeedTests`）。強い（8,000 回）でもエディタで約 1.7 秒ぶんの計算。

## テスト

| 種類 | 場所 | 件数 |
|---|---|---|
| Core（.NET / Mono） | `Assets/Tests/Core/` | 109 |
| App（.NET / Mono） | `Assets/Tests/App/` | 19 |

- 題材固有：自殺手（1 子・複数子・取れば合法・白）`SuicideTests`、単純コウ・打って返し・三コウの同型反復・ハッシュ衝突 `KoTests`、取り石後の呼吸点（40 シードの乱択対局の全局面で参照実装と照合、アゲハマの累計、Zobrist の差分）`LibertyTests`。
- 乱択の 1 局（シード 2026）の最終ハッシュ `0x09A00C4C` と、操縦役 対 CPU の 1 局（シード 2026）の最終ハッシュ `0x15B11646` を .NET と Mono で照合する。
- MCTS：分け方に依らず同じ木（1・7・599 回ずつ）、展開した経路の合法性（三コウの局面を含む）、アタリの 4 子を取る・逃げる（3 シード）、眼だけならパス、相手のパスの後に勝っていればパス、根から先にパスしない、少ない回数でもランダム打ちに 6 局中 5 勝、300 回が 30 回に 6 局中 5 勝。
- 死石の推定：地の中の 1 子を死、壁を生きと推定し、計点に反映する。
- App：画面の流れ、演出中・CPU の手番の入力を捨てる、古い版のクリック、自殺手の理由、一時停止とフォーカス喪失で探索が止まる、連続パス → 死石の確定 → 結果、投了（プレイヤー・CPU）、再戦のシード、CPU の手が探索の分け方に依らない。

# 055. 囲碁 — 石庭（SEKITEI）

仕様書：[plan/games/055-go.md](../../plan/games/055-go.md)／実装計画：[plan/games/055-go-implementation.md](../../plan/games/055-go-implementation.md)

状態：完了（2026-11-28 人間の動作承認）。[検証記録](evidence/README.md)、[振り返り](retrospective.md)。

9 路盤で CPU と打つ囲碁。CPU は回数で止める小規模な MCTS（UCT 型＋RAVE）。参考作品からはメカニクスだけを採用し、盤・石・音は実行時やエディタのスクリプトで作っている。

## 環境

- Unity：6000.6.9f1（Universal 2D、C# 9.0）
- 対象プラットフォーム：Windows (StandaloneWindows64)
- 入力方式：Input System のマウスとキーボード。HUD は PanelRenderer / UI Toolkit。日本語は Windows の Yu Gothic で表示する

## 操作

シーンは `Assets/Scenes/Sekitei.unity`。

| 入力 | タイトル・一時停止・結果 | 対局中 | 死石の確定 |
|---|---|---|---|
| 左クリック | 項目を選ぶ | 交点に打つ（打てない点は理由を右の板に出す）。「パス」「一時停止」のボタン | 連の生死を切り替える。「確定」のボタン |
| マウスを交点に重ねる | — | 打てる点なら置く前の影を出す | — |
| ↑↓ / WS | 項目を選ぶ | カーソルを動かす（キーを使うまで出さない） | カーソルを動かす |
| ←→ / AD | CPU の強さ・あなたの石を切り替える | カーソルを動かす | カーソルを動かす |
| Enter / Space | 決定 | カーソルの点に打つ | カーソルの連を切り替える |
| P | — | パス | — |
| Esc | 一時停止から戻る | 一時停止（再開・投了・タイトルへ） | 確定して計点する |

- 石を置いた演出の間（12 Tick）と CPU の手番の着手・パスは捨てる（先行入力しない）。カーソルは動かせる。
- フォーカスを失うと一時停止し、戻っても手で再開する。ウィンドウを選び直したクリックは捨てる。
- 入力で画面が変わったら、同じフレームにたまった残りの入力（キーも）を捨てる（タイトルの Enter と同時の Space が初手にならない）。同じ画面の中のカーソル移動と決定はまとめて効く。
- 終局後の死石の推定を回し終えるまで（「死石を推定中…」）は、死石の切り替えも確定も受け付けない。

## 採用ルール

### 盤と着手

| 項目 | 採用ルール |
|---|---|
| 盤 | 9 路（81 点）。座標は列 A〜J（I を除く、左から）、行 1〜9（下から） |
| 手番 | 黒が先手。置き石なし |
| 着手 | 空点に置く。置いた後、呼吸点が 0 になった相手の連を全て取り、その後で自分の連の呼吸点を見る |
| 自殺手 | 相手の石を取れず、自分の連の呼吸点が 0 になる手は禁止（理由付きで拒否し、盤・手番・ハッシュ・履歴は変わらない） |
| コウ | 着手後の盤面（石の配置）が、対局中に現れたいずれかの盤面と同じになる手は禁止（positional superko）。そのうち「直前に相手が打った 1 子を取る」ものを単純コウ（`Ko`）、それ以外を同型反復（`Superko`）として理由を分ける。打って返し（2 子以上を取り返す）は合法 |
| 同型の判定 | 64 ビット Zobrist ハッシュ（固定シードの表）の履歴で候補を引き、一致したら盤面そのものを比べて確定する（衝突で誤って拒否しない） |
| パス | いつでも可。パスは盤面を変えないので同型反復の対象外 |
| 終局 | 両者が連続してパス／どちらかが投了／手数の上限（既定 300 手、パスを含む）に達した。2 回目のパスと上限が重なったら「連続パス」 |
| 投了 | 手番でなくてもできる。終局後はできない |

### 計点（中国式の面積・Tromp-Taylor 型）

| 項目 | 採用ルール |
|---|---|
| 面積 | 死石を取り除いた盤で、各色の**石の数＋その色の石だけに接する空点の領域**。両色に接する空点（ダメ・セキの共有の呼吸点）はどちらにも数えない |
| コミ | 白に 7 目（整数なので引き分けがある）。差 = 黒の面積 − 白の面積 − 7。正なら黒、負なら白の勝ち、0 は引き分け |
| 死石 | 終局（連続パス・手数の上限）の後、今の盤からプレイアウトを決まった回数（既定 600）回し、連の石が相手の持ち物になった割合が 50 % を超えた連を死石と推定して印を付ける。推定は CPU の探索と同じくフレームの予算で少しずつ回す（回し方に依らず同じ推定）。プレイヤーは連をクリック（または決定）して生死を切り替え、確定すると計点する。乱数は（試合シード × 終局の手数 × 推定）の系列 |
| 投了 | 投了の対局は計点しない（結果は投了で決まる） |
| アゲハマ | 表示するが、面積計点なので得点には足さない |

### CPU（MCTS）

| 項目 | 採用ルール |
|---|---|
| 探索 | UCT 型 ＋ RAVE。手番ごとに木を作り直す。選択の値 = (1 − β) × 勝率 + β × AMAF の勝率 + 0.1 × √(親の訪問) ÷ (1 + 子の訪問)、β = √(k ÷ (3n + k))、k = 1000。探索項は標準の UCT（C√(ln N ÷ n)）ではなく、事前確率のない PUCT 型。全て整数で計算する（Mono と .NET で同じ手） |
| 木の手 | 対局の履歴＋木の経路で同型反復まで判定した合法手から、自分の眼（四方が自分の石で、斜めの相手の石が中央なら 1 つ以下・辺と隅は 0）を埋める手を除いたもの。ただし眼を埋めると別々の連がつながる手は残す。木の中ではパスも候補。根のパスは「相手が直前にパスした」か「ほかに手がない」ときだけ（CPU から先にはパスしない） |
| 終局の節点 | 2 連続パスか、対局の手数の上限（パスを含む）に届いた節点は展開もプレイアウトもせず、そのまま面積で数える。プレイアウトも上限までの残りの手数で打ち切る（対局で起きない先の局面で評価しない） |
| プレイアウト | 直前の手がアタリを作ったら取る・逃げる。それ以外は眼埋めを除く置ける点から一様に選ぶ（単純コウだけ判定）。2 連続パスか 243 手（と上限までの残り）で打ち切り、盤をそのまま面積で数える（死石の推定なし）。勝ち 2・引き分け 1・負け 0 |
| 強さ | プレイアウトの総数。弱い 500・普通 2,000・強い 8,000（設定アセット） |
| 手の決定 | 訪問回数の最大（同数は点の番号の小さい方、パスは最後）。相手がパスした後、パスが全勝ならパスで終える。根ですぐ終局する手（相手のパスの後のパス、手数の上限まで残り 1 手ならどの手も）は、終局後と同じ系列の死石の推定（各 600 回）で死石を除いて数える。推定は探索の回数の中で木より先に回す |
| 投了 | 30 手目以降に、決めた手の勝率が 10 % 未満なら投了する |
| 時間 | 対局では、探索（と死石の推定）を 1 フレームの予算（入力と Tick を含めて 8 ms）の残りだけで回す（`GoFlow.Think`）。Tick では回さないので、処理落ちで Tick がたまっても探索は増えない。撮影とテストは 1 Tick に 20 回ずつ回す（`GoFlow.SearchInTicks`）。手は総数だけで決まり、回し方（機械の速さ）は考える時間だけを変える。考える間は最小 30 Tick |
| 乱数 | `RandomSeries`（試合シード × 手数 × 用途：探索 1・死石の推定 2・操縦役 3） |

## 設計上の選択

| 層 | 責務 |
|---|---|
| Core | `Points`（交点の番号と表記・隣の表）、`PointSet`（81 点の 128 ビット集合）、`Board`（色・連の番号・連ごとの石と呼吸点の集合を差分で更新、Zobrist ハッシュ）、`Zobrist`、`GoGame`（手番・パス・投了・終局・同型反復の履歴・アゲハマ・状態ハッシュ）、`AreaScore`、`GoConfig`、`BoardText`、`Playout`、`Mcts`、`Ownership`・`OwnershipSearch`（死石の推定、少しずつ回せる）、`MctsConfig` |
| App | `GoFlow`（タイトル・遊び方・対局・一時停止・死石の確定・結果、意図の列、画面の版、フォーカス喪失、再戦のシード）、`CpuPlayer`、`BoardCursor`、`Pilot`（操縦役：小さい MCTS の手を矢印キーと決定に変える）、`FlowSettings` |
| Unity | `SekiteiGame`（入力を意図に、フレームの予算で CPU の探索と死石の推定、描画の反映）、`SekiteiStage`（Prefab：盤・81 の石・81 の地の印・最後の手・カーソル・置く前の影）、`BoardProjection`（交点と世界の座標、クリックの交点）、`SekiteiHud`（UI Toolkit。コードで組む）、`SekiteiAudio`（効果音を実行時に作る）、`SekiteiSettings`（設定アセット）、`SekiteiCaptureScenario`、Editor の `SekiteiArtGenerator`・`SekiteiSceneBuilder`・`SekiteiBuildCheck` |

- 連の石と呼吸点は 128 ビットの集合で持ち、着手のたびに「つないだ連の和」「取った跡を隣の連の呼吸点に足す」で差分更新する。テストで、毎手の全ての連を塗りつぶしの数え直しと照合する。
- 盤の書き換え（`Board.Play`）は Core の内部だけ。画面とテストは `GoGame` の `TryPlay`／`TryPass`／`TryResign` を通す。
- 状態ハッシュは tile-motion の `StateHash`。コミ・手数の上限・盤・手番・パス・終局・アゲハマに加え、同型反復の履歴（各手の後の盤面ハッシュ）と手の列も混ぜる。
- 乱数は int-geometry の `SeededRandom`・`RandomSeries`、探索の √ は `IntMath.Sqrt`。
- 探索の木は手番ごとに作り直す。木の合法手は対局の `GoGame.Repeats`（履歴＋木の経路）で判定し、テストで「展開した全ての経路を実際の対局で打てる」「展開する手 = 対局が受け付ける手 − 眼埋め（全局面）」を確かめる。
- 死石の推定はプレイアウトの統計で、厳密な死活ではない。白の壁の右の地が 3 列で、その中に黒の 2 子と二眼の黒があると、4 シード中 3 シードで白の壁（生き）を死と推定した（地が 4 列なら全シードで正しい）。印はプレイヤーが直せる。
- 純粋なランダムのプレイアウトだけでは、1,000 回では 4 子のアタリを取る手（プレイアウトの勝率 70 %）とほかの手（60 %）を見分けられなかった（子 1 つあたり 13 回程度）。アタリへの応手のプレイアウト方針と RAVE を足して見分けられるようにした。

### 計測（プレイアウトの速さ）

| 環境 | 1 秒あたり | 20 回あたり p50 / p95 |
|---|---|---|
| Unity エディタの Mono（EditMode テスト、i9-13900KF） | 4,796 回 | 4.10 ms / 4.55 ms |
| .NET 9（dotnet test、同じ機械） | 約 10,000 回 | — |

空の盤からの探索（最も手数の長いプレイアウト）で測った（`SpeedTests`）。強い（8,000 回）でもエディタで約 1.7 秒ぶんの計算。対局でフレームの予算（8 ms）だけで回したときの待ち時間とフレームの時間は [evidence/README.md](evidence/README.md) に記録した。

# 035. ピンボール — COMET COIL（仮）

仕様書：[plan/games/035-pinball.md](../../plan/games/035-pinball.md)／実装計画：[plan/games/035-pinball-implementation.md](../../plan/games/035-pinball-implementation.md)

参考作品の名称・素材・演出は使わないオリジナル作品。縦長の台 1 つに、フリッパー 2・バンパー 3・ドロップターゲット 3・プランジャーを置き、3 球を失うまで得点を競う。

## 環境

- Unity：6000.6.9f1
- 対象プラットフォーム：Windows (StandaloneWindows64)
- 入力方式：キーボード（Input System）

## 起動手順

```
dev gui 035      # エディタで開く

dev capture 035  # 証跡を evidence/ に撮る（画像は captures/<画像世代>/、撮影記録は runs/）
```

## 採用ルール

| 項目 | 採用ルール |
|---|---|
| 時間 | 60 Tick/秒。1 Tick を 8 区間（480 回/秒）に分けて物理を進める。入力はイベント時刻を含む Tick の境目に反映し、押したキーは次の Tick の始めから効く |
| 座標 | 整数。1 マス = 1024 単位、台は横 24 × 縦 44 マス（原点は左下、y は上向き、重力は −y）。速度は 1 区間あたり 1/256 単位で、位置は端数（1/256 単位）も持つ |
| 衝突物 | 全てカプセル（線分＋半径、長さ 0 なら円）：壁・一方通行の扉・バンパー・ドロップターゲット。フリッパーは回るカプセル。球どうしは当たらない（すり抜ける） |
| 1 区間の順序 | フリッパーを回す → 重なった球をフリッパーの外へ押し出し、面の速さ（ω × r）を加えて反射 → 重力 → 球を経路で動かす |
| 連続衝突検出 | 1 区間の経路を、長い軸に沿って 1 単位ずつの点の列とみなす。最初に相手の内側（中心の距離 &lt; 半径の和、ちょうど等しいのは外）に入った点の手前で反射し、区間の残りを反射後の速度で続ける。隣り合う点は √2 単位以内なので、どの相手もすり抜けない。斜めのかすりも拾う。点は保守的前進（隙間の半分ずつ）で飛ばし、全ての点を調べた結果と一致する |
| 区間の残り時間 | 区間全体に対する残り時間（1/65536 区間単位）を持ち、接触のたびに「その経路で進んだ点の数 ÷ 経路の点の数」の割合だけ減らす（切り上げ）。接触の回数に上限は置かず、移動を途中で捨てない。進めなかった接触（手前の点が始点）は、当たった相手を「挟んでいる相手」に加えて速度をそのどれにも近づかない向きへ射影する（なければ止める）。同じ相手に進めずにもう一度当たったら、挟まって動けないとしてその区間を終える。進んだ接触は残り時間を 1 以上減らし、進めない接触は相手ごとに 1 回なので、必ず終わる |
| 当たる相手 | 球が近づいていない相手（始点の法線と速度の内積が 0 以上）は除く（凸な相手に近づかない直線は内側に入らない）。接して滑る球は点の丸めで 1 単位まで食い込みうる（次の区間で押し出す） |
| 反射 | 相対速度の法線成分を反発係数で返し、接線成分はそのまま（摩擦なし）。反射の後は丸めがあっても面に近づかない。速さは上限で頭打ち |
| フリッパー | 押している間は上の角度へ加速（1 区間 150、上限 600、角度は 1 周 65536）し、端で止まって保つ。離すと戻る（加速 80、上限 400）。押した Tick の最初の区間から動く |
| すり抜けない条件 | 1 区間に先端が動く距離 &lt; 球の半径 + フリッパーの半径（角速度の上限 × 長さ × 2π/65536 で判定）、1 区間の球の移動 ≤ 球の半径。台の読み込みで検証し、破る設定は拒否する。フリッパーの回る範囲に静止した衝突物を置かず、左右のフリッパーどうしも回る範囲で重ならない（フリッパーどうしは当たらない） |
| バンパー 3 | 触れたら反射に加え外向きに 24000 の速さで弾く。1 回の接触で 100 点を 1 回 |
| ドロップターゲット 3 | 起きている間だけ当たり、触れると倒れて 500 点。3 枚倒すと 2000 点を足して全部起き直す |
| マルチボール | 3 枚倒したとき台の上の球が 1 個（レーンに球がない）なら、2 個目をレーンに出して自動で打ち出す（強さは試合のシードで決める）。台の上は最大 2 個で、マルチボール中は増えない |
| プランジャー | レーンに球があるとき、Space を押している Tick 数で引き（60 Tick で引ききり）、離すと引きに比例した速さ（20000〜46000）で上へ打ち出す。引き 0 で離しても打たない。弱いと落ちてきてレーンに戻る |
| 一方通行の扉 | レーンの出口。上へ抜ける球は通し、台から下りてくる球は止めて台へ転がす。始めから重なっている球は止めない |
| 球の喪失 | 球の中心がドレイン線（y = 0.5 マス）より下、または台の外（2 マスの余白）へ出た区間に 1 回だけ失う。台の上に球が残れば続ける。最後の 1 個を失ったら 1 球が終わり、次の球をレーンへ出す。同じ Tick に 2 個失っても 1 球だけ進む |
| 終了 | 3 球目を失ったら結果画面（得点・起動中の最高記録）。終了後の入力は状態を変えない。再戦は新しいシード（試合ごとにシードを進める） |
| 乱数 | マルチボールの 2 個目の打ち出しの強さだけ（試合のシードから分けた系列、xorshift） |

台は [Assets/Game/Data/Table.txt](Assets/Game/Data/Table.txt) に置き、Core の `Table.Parse` が検証する（バンパー・ターゲットの数、台の内、線分は 16 マス以下、フリッパーの回る範囲、左右のフリッパーの重なり、レーンの幅と置き場、ドレイン、すり抜けない条件）。

## 設計上の選択

- **物理を Core で持つ。** 中心課題の「高速球の連続衝突検出」を自前で書いてテストするため、Unity の物理は使わない。位置・速度・角度は全て整数で、.NET と Mono（Unity）で同じ結果になる（操縦役の試合の最終ハッシュを固定値で照合）。
- **経路の点の列で衝突を定義する。** 接触の時刻を 2 次式で解くと、long に収まる範囲（int-geometry の `Sweep.FirstLimit`）が台の広さに足りない。経路を 1 単位ずつの点の列と定めると判定が厳密な整数の比較だけになり、すり抜けないことが点の間隔から言える。
- **区間の残り時間を使って動き続ける。** 残り時間は区間全体に対する割合で持ち、接触のたびに使った割合だけ減らす（PR レビューで、短くなった経路の割合を丸 1 区間の速度に掛けて進みすぎていたのを直した）。接触の回数に上限を置かない。最初は接触した区間の残りを捨てていたが、斜面を滑る球が止まり続けた。反射後の速度で残りを進め、位置の端数も保つ（端数を捨てると遅い滑りが積み上がらず、軸の上で球が釣り合って止まった）。
- **フリッパーは区間の中では止まっているとみなす。** 動きは区間の始めの押し出しで扱う（先端の移動を半径の和より小さく保つので、押し出す向きを誤らない）。近づいているかも止まった姿勢で判定する。
- **Unity**：`CometCoilStage` は静止した部品（壁・扉・バンパー・ターゲット・フリッパーの軸）を台のデータから置いた Stage Prefab で、試合中は球・フリッパー・プランジャー・倒れたターゲット・光るバンパーだけを更新する（割り当てなし）。Prefab の照合は置くときと同じ関数（`Layout`・`Segment`・`CircleScale`）の値で行う。`CometCoilGame` はキーの押下・解放を時刻つきで 1 本の列に入れる。1 つの操作に束ねた複数のキーは組の中の番号つきの意図にし、どれが押されているかは Flow がキーごとに持つ（一時停止・フォーカス喪失で全て離したとみなし、押したままのキーは押し直すまで効かない）。素材は `CometCoilArtGenerator` が 16 px/マスで描き、フリッパー・バンパー・球は台のデータの大きさで描く。
- **App**：`PinballFlow`（画面遷移・時刻から Tick への変換・1 フレームの Tick 上限 5・フォーカス喪失で一時停止しキーを離す、押しているキーは操作ごとにキーのビットで持つ）、`Autopilot`（試合を複製して「今押す」を 24 Tick 先読みし、打ち上がるなら押す。近づくたびに 12% で見送り、試合が終わるようにする）。
